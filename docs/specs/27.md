# 실황 수업 '나가기' 시 학습장 입력 모달 띄우기

## 배경과 목적
- 실황 수업 화면은 두 개입니다.
  - **HotlineClassScreen**: `app/hotline-class.tsx` (선생님 수업)
  - **TopicLiveClassScreen**: `app/topic-live-class.tsx` (주제 실황 수업)
- 지금 두 화면은 나갈 때(언마운트) **useSolveFinished**(`src/host/useSolveFinished.ts`)로 `solve_finished`만 보냅니다. 학습장 시트(`study_note`)를 띄울지는 에이전트가 정합니다.
  - mockAgent(`src/agent/mockAgent.ts:90`)는 푼 수(solvedCount)가 0이거나 이미 학습장을 남긴 task면 시트를 띄우지 않습니다.
  - 실서버의 동작은 확인되지 않았습니다.
- 개념만 조회하고 나가면 taskId가 없습니다. 그래서 `flushActivity`가 조회 기록을 버리고, 학습장도 뜨지 않습니다.
- 목적: 수업 중 학습 행동을 했다면, 나갈 때 앱이 학습장 시트를 직접 띄웁니다. 학습장이 이미 있으면 수정(update) 모드로 띄웁니다. 저장한 학습장은 Study Log 목록에 보이게 합니다.
  - 학습 행동은 세 가지입니다: 답안 올리기(선생님의 답안 올리기 메시지 `snapshot` 포함), 개념 조회, 퀴즈 답안 제출.
- 폰 문제 목록 화면은 이미 같은 규칙으로 동작합니다. `src/phone/studyNoteOnLeave.ts`의 `openStudyNoteOnLeave`가 나갈 때 task를 확보하고 `showLocalSheet('study_note')`를 부릅니다. 실황 수업도 이 방식을 따릅니다.

## 범위
### 하는 것
- HotlineClassScreen과 TopicLiveClassScreen에서 '이번 방문의 학습 행동'을 추적합니다. 학습 행동은 다음 세 가지입니다.
  1. 답안 올리기: `onSave` 호출. 직접 저장과 선생님 `snapshot` 메시지로 패널이 `saveWorkout`을 부르는 경우가 모두 포함됩니다.
  2. 개념 조회: **CanvasStudySheet**(`src/kit/canvas/CanvasStudySheet.tsx`)의 개념 탭에서 새 개념을 고름. 이때 `canvasActivityStore`에 `concepts`가 쌓입니다.
  3. 퀴즈 답안 제출: **QuizResponseModal**(`src/kit/live-class/QuizResponseModal.tsx`)의 `onSubmitted`.
- 화면이 사라질 때(언마운트) 위 행동이 하나라도 있었으면 다음을 한 번씩 합니다.
  - task 확보
  - 활동 기록 저장
  - 학습장 시트 열기
- 학습장이 이미 있으면 기존 **StudyNoteForm**(`src/kit/study-note/StudyNoteForm.tsx`)의 fetchNote/persistNote 흐름을 그대로 씁니다. 시트에는 기존 내용이 채워지고 버튼은 '수정'입니다. 저장하면 update가 호출됩니다.
- 저장하면 `bumpStudyData()`(이미 StudyNoteWidget이 함)로 **StudyLogPanel**(`src/agent/StudyLogPanel.tsx`)의 **StudyNoteReviewList**(`src/kit/study-log/StudyNoteReviewList.tsx`)가 목록을 다시 받습니다. 받은 목록에 hotline/topic-live 학습장 카드가 보이는지 테스트로 보장합니다.

### 하지 않는 것
- 개인 풀이 캔버스(**NotebookScreen** `app/notebook.tsx`, kind 'self')의 동작은 바꾸지 않습니다.
- 폰 문제 목록 화면(`src/phone/*`)의 동작은 바꾸지 않습니다.
- 서버 API(api-v3 `/api/study-notes`, graphql)는 바꾸지 않습니다.
- 에이전트 서버의 `solve_finished` 처리 규칙은 바꾸지 않습니다.
- 수업 중 화면 안에서 학습장을 띄우는 기능(나가기 전)은 넣지 않습니다.
- 퀴즈를 받기만 하고 답하지 않은 경우, 시트를 띄우는 조건으로 치지 않습니다. 받은 퀴즈의 활동 기록은 지금처럼 남깁니다.

## 변경할 동작
1. 나갈 때 학습장을 여는 로직을 순수 함수로 둡니다. 이름은 예시로 `openLiveStudyNoteOnLeave`입니다.
   - 시그니처: `(a: { taskId?: number; spec: TaskSpec; acted: boolean; activity: Activities; title: string }, deps: { ensureTaskId; store; showSheet }) => Promise<void>`
   - 위치: `src/host/` 아래(예: `src/host/liveStudyNoteOnLeave.ts`) 또는 `useSolveFinished.ts` 안.
   - `acted`가 false면 아무것도 하지 않습니다. 시트를 띄우지 않고, task도 만들지 않습니다.
   - `acted`가 true면 순서대로 합니다.
     - `taskId = a.taskId ?? await deps.ensureTaskId(undefined, a.spec)`
     - taskId가 없으면(생성 실패) 시트를 띄우지 않고 끝냅니다. ensureTaskId가 이미 `client_error`를 보고합니다.
     - taskId가 있으면 `appendActivity(store, taskId, activity)`를 부릅니다. 이어서 `showSheet('study_note', { taskId, mode: 'live', title })`를 부릅니다.
   - deps 기본값: `ensureTaskId`(`src/adapters/ensureTask.ts`), `storage`(`src/storage`), `getAgentSession().showLocalSheet`.
2. **useSolveFinished** 변경
   - 실황 수업(kind `'hotline'` | `'topic_live'`)용 인자를 받습니다.
     - `liveSpec: TaskSpec`: `hotlineSpec(tutorId)` / `topicLiveSpec(topicId)`, `src/host/widgets.tsx`
     - `title: string`
   - 반환값에 학습 행동 표시 함수를 둡니다(예: `markActed()`). `countSolved()`는 행동으로 칩니다.
   - 언마운트 cleanup에서 kind가 실황이고 이 화면이 owner일 때는 다음과 같이 합니다.
     - 기존 `flushActivity`(taskId 없으면 기록을 버림) 대신, 1번 함수에 그 시점의 `canvasActivityStore.getState()`를 넘깁니다.
     - 그다음 store를 reset합니다.
     - 개념 조회가 있었는지(activity.concepts 비어 있지 않음)는 cleanup에서 activity로 판단해 acted에 OR합니다.
   - 실황 kind는 `solve_finished`를 보내지 않습니다. 에이전트가 같은 시트를 또 띄우지 않게 하려는 것으로, 폰 설계 `docs/superpowers/specs/2026-11-15-phone-concept-answer-sheet-design.md`와 같습니다.
   - `bumpStudyData()`는 그대로 부릅니다.
   - kind `'self'`의 동작(solve_finished 전송, flushActivity)은 그대로 둡니다.
3. 두 화면 변경 (`app/hotline-class.tsx`, `app/topic-live-class.tsx`)
   - `useSolveFinished`에 spec과 title을 넘깁니다. title은 hotline이 `'선생님 실황 수업'`, topic-live가 `'주제 실황 수업'`입니다.
   - `onSave`의 `countSolved()`는 그대로 둡니다. 선생님 `snapshot` 메시지도 패널 `sendBoardAction SAVE` → `saveWorkout` → `onSave` 경로로 행동이 기록됩니다.
   - QuizResponseModal의 `onSubmitted`에서 행동을 표시합니다.
   - 최신 taskId는 지금처럼 `latest.current`로 cleanup에 전달합니다. `findLiveClassTaskId`나 `resolveTaskId`/`onSave`로 채워진 값입니다.
4. 학습장 시트는 기존 **SheetHost**(`src/host/SheetHost.tsx`)와 StudyNoteWidget(`src/host/widgets.tsx`의 `sheetWidgets.study_note`)이 띄웁니다.
   - 기존 학습장이 있으면 StudyNoteForm이 내용을 채우고 '수정'으로 저장(update)합니다. 이 부분은 코드를 바꾸지 않습니다.
5. Study Log
   - StudyNoteReviewList의 `CARD_TYPES`에는 이미 `'hotline'`·`'topic-live'`가 있습니다. `cardTitle`은 `describeTask`로 '선생님 실황 수업' / '주제 실황 수업'을 냅니다.
   - 저장 후 refreshKey가 바뀌면 다시 조회합니다.
   - 코드 변경이 필요 없으면 테스트만 추가합니다.

## API 계약
없음. 다른 프로젝트와 새로 주고받는 것이 없습니다. 기존 `study_note` 시트 props `{ taskId: number; mode: 'live'; title: string }`와 기존 api-v3 `/api/study-notes` 호출을 그대로 씁니다.

## 수용 기준
- 공통 전제: 1번 함수의 단위 테스트에는 deps를 mock으로 주입합니다.
- acted=false면 1번 함수는 ensureTaskId·appendActivity·showSheet를 하나도 부르지 않습니다.
- acted=true이고 taskId=7이면 ensureTaskId를 부르지 않습니다. `showSheet('study_note', { taskId: 7, mode: 'live', title: '선생님 실황 수업' })`를 정확히 1회 부릅니다. store에 taskId 7의 활동 기록이 append됩니다.
- acted=true, taskId 없음, ensureTaskId가 9를 돌려주는 경우:
  - ensureTaskId가 spec `{ taskType: 'topic-live', task: { topicId } }`로 1회 불립니다.
  - `showSheet('study_note', { taskId: 9, mode: 'live', title: '주제 실황 수업' })`가 불립니다.
- acted=true인데 ensureTaskId가 undefined를 돌려주면 showSheet를 부르지 않습니다.
- useSolveFinished(kind 'hotline' 또는 'topic_live') 테스트:
  - countSolved()를 부르고 언마운트하면 학습장 시트(showLocalSheet 'study_note')가 1회 열립니다.
  - 이때 `solve_finished`는 emit되지 않습니다.
- useSolveFinished(실황) 테스트:
  - 행동 없이 canvasActivityStore에 `concepts`만 dispatch하고 언마운트합니다. taskId가 없으면 ensureTaskId가 불리고, 그 결과 taskId로 시트가 열립니다.
  - 개념 조회는 행동으로 칩니다.
- useSolveFinished(실황) 테스트:
  - 아무 행동 없이 언마운트하면 시트가 열리지 않습니다. 진입 시 찾은 기존 taskId가 있어도 같습니다.
  - 이때 ensureTaskId도 불리지 않습니다.
- useSolveFinished(실황) 테스트: 퀴즈 답안 제출 표시 함수(markActed 등)를 부르고 언마운트하면 시트가 열립니다.
- useSolveFinished(실황) 테스트: 퀴즈를 받기만 하고(canvasActivityStore `quiz` dispatch) 다른 행동 없이 언마운트하면 시트가 열리지 않습니다.
- useSolveFinished(kind 'self') 기존 테스트(`__tests__/solveFinished.test.tsx`)는 수정 없이 통과합니다. 기존 동작은 solve_finished 전송, taskId 없으면 기록을 버리는 것입니다.
- `app/hotline-class.tsx`와 `app/topic-live-class.tsx`에서 확인할 것:
  - QuizResponseModal의 onSubmitted가 행동 표시 함수를 부릅니다.
  - useSolveFinished에 각각 hotlineSpec(tutorId)/topicLiveSpec(topicId)와 title이 넘어갑니다.
- 서버에 학습장이 있는 taskId로 study_note 시트가 열리면 StudyNoteForm이 기존 내용을 보여 줍니다. 저장 버튼 문구는 '수정'이고, 저장하면 fetchers.update가 불립니다(register 아님).
- listNotes가 taskType 'hotline'과 'topic-live' 항목을 돌려주면 StudyNoteReviewList에 각각 '선생님 실황 수업'·'주제 실황 수업' 제목의 카드가 보입니다.
- StudyNoteReviewList의 refreshKey가 바뀌면 listNotes를 다시 부릅니다.
- `npx tsc --noEmit`과 전체 jest 테스트가 통과합니다.

## 가정
- 모달은 '나가기' 버튼뿐 아니라 뒤로가기·제스처를 포함한 모든 종료 경로(언마운트)에서 띄웁니다. 기존 useSolveFinished 설계와 같습니다.
- 진입 때 이전 방문의 task를 찾았더라도, 이번 방문에 학습 행동이 없었으면 모달을 띄우지 않습니다.
- 개념만 조회한 경우 task는 조회 순간이 아니라 나갈 때 ensureTaskId로 만듭니다(폰 방식과 같음).
- 실황 수업에서는 앱이 시트를 직접 띄우므로 solve_finished를 보내지 않습니다.
- 시트 title은 '선생님 실황 수업' / '주제 실황 수업' 고정값입니다. topicHints는 넣지 않습니다.
- Study Log 목록에는 서버 `GET /api/study-notes?from=`가 이번 주 저장·수정한 학습장을 돌려준다고 봅니다. 앱은 받은 목록을 보여 주기만 합니다.
