# 실황 수업 도중 '나가기' 확인 모달

## 배경과 목적
지금은 실황 수업 캔버스 화면에서 하단 툴바(**FloatingToolbar**: `src/kit/canvas/FloatingToolbar.tsx`)의 '나가기'를 누르면 확인 없이 바로 화면을 나갑니다. 나가기는 `goBack` = `router.canGoBack() ? router.back() : router.replace('/')`이 처리합니다. 수업 도중 실수로 눌러 수업에서 빠지는 일을 막으려고, 수업이 진행 중일 때는 확인 모달을 먼저 보이고 '예'를 눌렀을 때만 나가게 합니다.

대상 화면(용어집 기준):
- **TopicLiveClassScreen**: `app/topic-live-class.tsx` (`/topic-live-class`, 주제 실황 수업)
- **HotlineClassScreen**: `app/hotline-class.tsx` (`/hotline-class`, 선생님 실황 수업)

## 범위
### 하는 것
- 두 화면의 툴바 '나가기' 액션(`canvasAction('exit', '나가기', 'chevron-back', ...)`)이 `liveState === 'live'`일 때 바로 나가지 않고 확인 모달을 엽니다.
- 확인 모달은 공용 **Dialog**(`src/ui/Dialog.tsx`)로 만듭니다.
- '예'를 누르면 모달을 닫고 기존 `goBack`을 부릅니다. '아니오'를 누르거나 scrim을 누르거나 Android 뒤로 가기(onDismiss)를 하면 모달만 닫고 화면에 남습니다.

### 하지 않는 것
- **NotebookScreen**(`app/notebook.tsx`)의 나가기는 바꾸지 않습니다. 실황 수업이 아니기 때문입니다.
- 수업 전 대기 화면 **LiveClassWaiting**(`src/kit/live-class/LiveClassWaiting.tsx`)의 '나가기' 버튼은 바꾸지 않습니다. 지금처럼 바로 나갑니다.
- `liveState`가 'checking' 또는 'waiting'일 때 툴바의 '나가기'는 지금처럼 바로 나갑니다.
- 하드웨어 뒤로 가기, iOS 스와이프 제스처, 내비게이션 beforeRemove 같은 다른 종료 경로는 가로채지 않습니다.
- '주제 실황 강의가 준비되지 않았습니다' 토스트 뒤에 자동으로 나가는 동작(notReady)은 바꾸지 않습니다.
- 나간 뒤 **useSolveFinished**(`src/host/useSolveFinished.ts`)가 언마운트 때 학습장 시트를 여는 동작은 바꾸지 않습니다. '예'로 나가면 지금 나가기와 똑같이 언마운트 경로를 탑니다.
- 툴바 버튼 구성, 순서, 아이콘은 바꾸지 않습니다.

## 변경할 동작
1. 두 화면에 `exitConfirmVisible` 상태(boolean, 처음 값 false)를 둡니다.
2. 툴바 exit 액션의 onPress를 다음처럼 바꿉니다.
   - `liveState === 'live'`이면 `setExitConfirmVisible(true)`만 합니다. 이때 `router.back`과 `router.replace`는 부르지 않습니다.
   - 그 밖의 상태이면 지금처럼 바로 `goBack()`을 부릅니다.
3. 화면 JSX에 다음 Dialog를 렌더합니다.
   - `visible={exitConfirmVisible}`
   - `title="수업 진행 중입니다. 나가시겠습니까?"`
   - `onDismiss={() => setExitConfirmVisible(false)}`
   - `confirm={{ title: '예', onPress: () => { setExitConfirmVisible(false); goBack(); } }}`
   - `cancel={{ title: '아니오' }}`
   - cancel에 onPress를 주지 않으므로 '아니오'는 onDismiss로 닫힙니다.
4. 두 화면에 같은 코드를 중복해서 두어도 되고, 작은 공용 훅이나 컴포넌트로 뽑아도 됩니다. 새 공용 파일을 만들면 `docs/COMPONENTS.md`에 항목을 추가합니다.
5. 퀴즈 모달(**QuizResponseModal**)과 대기 화면 등 다른 오버레이의 동작은 바꾸지 않습니다.

## API 계약
없음

## 수용 기준
1. TopicLiveClassScreen에서 `liveState`가 'live'가 된 뒤 툴바의 exit 액션(`screenActions`에서 id가 'exit'인 항목)의 onPress를 부르면, '수업 진행 중입니다. 나가시겠습니까?' 문구가 화면에 보이고 `router.back`과 `router.replace`는 불리지 않는다.
   - 'live'가 되는 조건: last message가 위치 guide인 경우.
2. 1의 상태에서 '예' 버튼을 누르면 `router.canGoBack()`이 true일 때 `router.back()`이 불리고, false일 때 `router.replace('/')`가 불린다. 두 경우 모두 확인 문구가 사라진다.
3. 1의 상태에서 '아니오' 버튼을 누르면 확인 문구가 사라지고 `router.back`과 `router.replace`는 불리지 않는다.
4. HotlineClassScreen에서도 1~3이 똑같이 성립한다.
   - 'live'가 되는 조건: lastOnlineClassMessage가 위치 guide인 경우.
5. 두 화면 모두 대기 상태(`testID="live-class-waiting"`가 보이는 상태)에서 대기 화면의 '나가기'(accessibilityLabel '나가기')를 누르면, 확인 문구 없이 바로 `router.back()`이 불린다. 뒤로 갈 수 없으면 `router.replace('/')`가 불린다. 기존 `__tests__/liveClassWaiting.test.tsx`의 '나가기' 테스트가 그대로 통과한다.
6. 두 화면 모두 `liveState`가 'waiting' 또는 'checking'일 때 툴바 exit 액션의 onPress를 부르면, 확인 문구 없이 바로 `goBack` 동작(`router.back()` 또는 `router.replace('/')`)이 일어난다.
7. 화면에 처음 들어왔을 때는 확인 문구가 보이지 않는다.
8. NotebookScreen(`app/notebook.tsx`)의 툴바 나가기는 확인 없이 바로 나간다. 코드 변경이 없어야 한다.
9. 위 동작을 검증하는 jest 테스트가 추가되고, `npx jest`와 타입 검사(`npx tsc --noEmit`)가 통과한다.

## 가정
- '실황 수업'은 주제 실황 수업(TopicLiveClassScreen)과 선생님 실황 수업(HotlineClassScreen) 둘 다를 뜻한다고 보았습니다.
- '수업 도중'은 화면의 `liveState === 'live'`인 상태로 보았습니다. 수업 전 대기('waiting')와 확인 중('checking')일 때는 확인 없이 나갑니다.
- 모달은 공용 Dialog를 쓰고, 문구는 제목 하나 '수업 진행 중입니다. 나가시겠습니까?'로 둡니다. 요구사항의 닫는 따옴표 오타는 물음표로 고쳐 읽었습니다.
- 버튼 라벨은 '예'(confirm, primary)와 '아니오'(cancel)로 둡니다.
- 확인 대상은 '나가기' 버튼 클릭뿐입니다. 하드웨어 뒤로 가기와 제스처는 가로채지 않습니다.
