# 핫라인 수업: 스크립트 없는 유닛(scriptId 0)으로의 전환과 재진입 로딩 수정

## 배경과 목적
선생님 웹 `hotline-portrait-live`(tutor-web `src/app/hotline-portrait-live/PageClient.tsx`)의 목록보기에서 유닛을 바꾸면 `sendUnitSwitchGuide`가 guide를 보냅니다. 형태는 `{ tutorId, scriptId: target.id, studyIdx: 0, rawCutIdx: 0, action: 'refresh', step: 'refresh', sourceType, sourceId, releaseScriptUrl? }`입니다. 스크립트 없는 유닛은 `onlineClassOfTutor`의 `scripts`가 비어 있으므로 tutor-web이 `id: 0`인 항목을 만듭니다. 그래서 이 유닛의 guide는 **`scriptId: 0`** 과 sourceType/sourceId를 함께 보냅니다. On Air guide도 `scriptId: currentScript.id ?? 0`이라 같은 값입니다.

학생 앱 화면 **HotlineClassScreen**(`app/hotline-class.tsx`)은 이 guide를 캔버스 패널 **HotlineClassCanvas**(`src/kit/canvas/note-canvas/hotline-class-canvas.tsx`)의 `onReceiveGuide`로 넘깁니다. 그런데 패널은 다음 두 경우에만 유닛을 바꿉니다.
- `guide.scriptId == null`일 때 sourceType/sourceId로 바꿉니다.
- `Number(guide.scriptId) > 0`일 때 id로 바꿉니다.

`scriptId: 0`은 어느 쪽에도 해당하지 않습니다. 그래서 guide가 `handleLiveClassMessage`로 그냥 넘어가고 문제가 바뀌지 않습니다(증상 1: 전파가 안 됨).

캔버스에서 나갔다가 다시 들어오면 패널이 새로 마운트됩니다. 이때 `currentScript`와 `currentScriptId`는 비어 있습니다. 마지막 수업 메시지(`lastOnlineClassMessage`)가 바로 이 `scriptId: 0` refresh guide이면, 같은 이유로 `currentScript`가 정해지지 않습니다. 그러면 `releaseScriptUrl`과 `studySequences`가 비어 있고, `ActivityIndicator`가 계속 돕니다(증상 2: 끝없는 로딩).

주제 실황 패널 **TopicLiveCanvas**는 #74에서 **LiveScriptId**(`src/kit/canvas/note-canvas/live-script-id.ts`)의 `hasScriptId`와 `normalizeGuideScriptId`로 이 문제를 이미 고쳤습니다. 이번 작업은 같은 판정을 HotlineClassCanvas에 적용합니다.

## 범위
### 하는 것
- `hotline-class-canvas.tsx`의 `onReceiveGuide`(CLASS_ON_AIR 분기 포함)와 `refreshMenuscript`의 scriptId 판정을 `hasScriptId`로 바꿉니다. 그러면 0과 null은 '스크립트 id 없음', 음수는 '스크립트 id 있음'으로 다룹니다.
- 스크립트 id가 없는 guide는 sourceType/sourceId로 유닛을 바꾸고, 그 유닛을 기본 보드(`releaseScriptUrl = 'default'`)로 엽니다. `live-scripts`에 그 유닛의 releaseScriptUrl이 있으면 그 주소로 엽니다.
- 재진입 시 마지막 메시지가 스크립트 없는 유닛의 guide여도 캔버스가 뜨게 합니다.
- 위 동작을 검증하는 jest 테스트를 추가하고, 문구가 바뀌어 깨지는 기존 소스 검사형 테스트를 같은 의도로 고칩니다.

### 하지 않는 것
- tutor-web이나 graphql-server는 바꾸지 않습니다. guide 형식도 그대로입니다.
- **TopicLiveCanvas**(`topic-live-canvas.tsx`)와 `app/topic-live-class.tsx`는 바꾸지 않습니다.
- `cacheLiveReleaseScriptUrl`(**CanvasLegacy** `src/kit/canvas/note-canvas/legacy.ts`)은 바꾸지 않습니다.
- `scriptMaker`, `makeTemporaryScript`, 재생 로직(`runPlay`, `playToPointInternal`, `fastforward`)은 바꾸지 않습니다.
- `ONLINE_CLASS_OF_TUTOR` 쿼리(**QueryTopic** `src/api/graphql/queries/topic.ts`)와 `app/hotline-class.tsx`의 `live-scripts` 구성은 바꾸지 않습니다. 단, 아래 '변경할 동작' 5번에서 확인이 필요하다고 한 부분은 예외입니다.
- qoolla-package 의존 버전은 바꾸지 않습니다.

## 변경할 동작
대상 파일: **HotlineClassCanvas** `src/kit/canvas/note-canvas/hotline-class-canvas.tsx`

1. **LiveScriptId** `./live-script-id`에서 `hasScriptId`와 `normalizeGuideScriptId`를 import합니다.
2. `onReceiveGuide`에서 imageQuiz 처리와 `hideModal()`, snapshot 처리를 지나고, CLASS_ON_AIR 분기에 들어가기 전에 guide를 정규화합니다.
   - 코드: `guide = normalizeGuideScriptId(guide, JSON.parse(storage.getString('live-scripts') || '[]'));`
   - 핫라인의 `live-scripts`에서 스크립트 없는 유닛 항목에는 id가 없습니다. 그래서 지금은 대개 guide가 그대로 남습니다. 서버가 나중에 음수 defaultScript id를 내려주면 그 id로 바뀝니다.
3. CLASS_ON_AIR 분기를 바꿉니다.
   - `onAirScriptId > 0` 판정 두 곳을 `hasScriptId(onAirScriptId)`로 바꿉니다.
   - `scriptId: 0`인 On Air guide는 sourceType/sourceId 비교로 전환 여부를 정합니다. 바뀌었으면 기존 else 경로를 따릅니다: `setCurrentScript({sourceType, sourceId})`, `setCurrentScriptId(0)`, `setReleaseScriptUrl(undefined)`, syncPoint 저장.
4. 일반 전환 분기를 바꿉니다.
   - `if (guide.scriptId == null)`을 `if (!hasScriptId(guide.scriptId) && guide.sourceType)`로 바꿉니다. 안의 동작은 지금과 같습니다. 즉 currentScript와 source가 다르면 다음을 하고 return합니다: syncPoint 저장, `setLastGuide({studyIdx:0, step:'refresh'})`, `setTargetGuide`, `setCurrentScript({sourceType, sourceId})`, `setReleaseScriptUrl(undefined)`, `setCurrentScriptId(0)`.
   - `else if (Number(guide.scriptId) > 0)`을 `else if (hasScriptId(guide.scriptId))`로 바꿉니다. 안의 동작은 지금과 같습니다.
   - 159행 근처의 `cacheLiveReleaseScriptUrl(guide) && currentScriptId == Number(guide.scriptId)` 분기는 그대로 둡니다. 이 분기는 scriptId가 0이면 false입니다.
5. `refreshMenuscript`를 바꿉니다.
   - `Number(targetScriptId) > 0`을 `hasScriptId(targetScriptId)`로 바꿉니다. 이 분기는 지금처럼 항목을 고르고 `setReleaseScriptUrl(tScript[0].releaseScriptUrl || 'default')`를 호출합니다.
   - `if (!targetScript) return;` 가드는 유지합니다.
   - id로 찾지 못하면 source로 찾습니다. 조건은 `src.sourceType == targetScript.sourceType && String(src.sourceId) == String(targetScript.sourceId)`입니다.
     - `targetScript.id`가 있으면(`hasScriptId`) id도 같아야 합니다.
     - id가 없으면 source만 맞으면 됩니다. 스크립트 없는 항목, 즉 id가 없거나 0인 항목을 먼저 고릅니다.
   - 찾은 항목이 있으면 `setReleaseScriptUrl(found.releaseScriptUrl || 'default')`를 호출합니다.
   - 그래서 guide에서 만든 `{sourceType, sourceId}`(id 없음)도 반드시 열립니다. 지금 코드는 `src.id == targetScript.id`(undefined == undefined)에 우연히 기대고 있는데, 이 의존을 없앱니다.
6. 재진입 경로를 확인합니다. 순서는 이렇습니다: `app/hotline-class.tsx`가 `live-scripts`를 채움 → `callGetLastMessage` → `toPositionGuide` → `onReceiveGuide`. 마지막 메시지가 `{action:'refresh', scriptId:0, sourceType, sourceId}`일 때 다음이 이어져야 합니다: 4번 분기로 currentScript 지정 → `refreshMenuscript` → `releaseScriptUrl='default'` → `initDefaultClassBoard` → `studySequences`가 채워짐 → `ActivityIndicator`가 WebView로 바뀜 → `changeUnit(currentScript)` 호출. 이 흐름을 막는 조건이 더 있으면 같은 원칙('0은 id 없음')으로 고칩니다.
7. 기존 jest 테스트 중 hotline 소스 문자열을 검사하는 것이 있습니다(`__tests__/classOnAirCanvas.test.ts`, `__tests__/positionGuideCanvas.test.ts`, `__tests__/imageQuizGuide.test.ts`, `__tests__/liveScriptsCache.test.ts`, `__tests__/hotlineRefreshMenuscript.test.ts` 등). 문구가 바뀌어 깨지면 같은 의도를 검증하도록 함께 고칩니다.

## API 계약
없음. 외부와 주고받는 형식은 바뀌지 않습니다. 참고로 앱이 받는 기존 guide 형식은 다음과 같습니다.
- 유닛 전환: `{ tutorId, scriptId: number(스크립트 없는 유닛은 0), studyIdx: 0, rawCutIdx: 0, action: 'refresh', step: 'refresh', sourceType: string, sourceId: number, releaseScriptUrl?: string }`
- On Air: `{ action: CLASS_ON_AIR, tutorId, scriptId: number(없으면 0), studyIdx: 0, rawCutIdx, step: 'main', mode: 'main', sourceType, sourceId, releaseScriptUrl? }`
- 판정 규칙: scriptId가 0이 아닌 유한수(음수 포함)이면 id로 찾습니다. null, undefined, 0이면 sourceType/sourceId로 찾습니다.

## 수용 기준
- `live-scripts`가 `[{id:12, sourceType:'UNIT', sourceId:1, releaseScriptUrl:'u12'}, {sourceType:'UNIT', sourceId:2}]`이고 HotlineClassCanvas가 id 12 유닛을 연 상태라고 합시다. 여기서 `onReceiveGuide({action:'refresh', step:'refresh', studyIdx:0, scriptId:0, sourceType:'UNIT', sourceId:2})`를 호출하면 다음이 모두 성립합니다.
  - `makeTemporaryScript`가 `('UNIT', 2)`로 호출됩니다.
  - `changeUnit`이 `sourceType 'UNIT'`, `sourceId 2`인 객체로 호출됩니다.
  - storage `syncPoint`에 그 guide가 저장되었다가 재생 후 지워집니다.
  - 이 검증은 `__tests__/classOnAirEntryReplay.test.tsx`처럼 panel을 렌더하는 jest 테스트로 합니다.
- 새로 마운트한 HotlineClassCanvas(currentScript 없음)에 위 `scriptId:0` guide 하나만 넘겨도 `makeTemporaryScript('UNIT', 2)`가 호출됩니다. 또 `studySequences`가 채워져 WebView가 렌더되고, `ActivityIndicator`는 더 이상 렌더되지 않습니다(재진입 로딩 회귀 테스트).
- `scriptId` 키가 아예 없는 guide(null)도 위와 같이 전환됩니다.
- currentScript가 이미 `{sourceType:'UNIT', sourceId:2}`이면 같은 source의 `scriptId:0` guide로는 다시 전환하지 않습니다. 즉 `makeTemporaryScript`를 추가로 호출하지 않습니다.
- 스크립트 없는 유닛 A(sourceId 2)에서 스크립트 없는 유닛 B(sourceId 3, `live-scripts`에 있음)로 `scriptId:0` guide를 보내면 `makeTemporaryScript('UNIT', 3)`가 호출됩니다.
- `scriptId:0` guide에서 스크립트 있는 유닛으로 돌아가는 `scriptId:12` guide를 보내면 `scriptMaker`가 'u12'로 호출됩니다.
- `scriptId:-9092`처럼 음수 id인 guide가 오고 `live-scripts`에 `{id:-9092, sourceType, sourceId, releaseScriptUrl:'d'}`가 있으면, 패널은 id로 전환하고 `scriptMaker('d')`를 호출합니다.
- CLASS_ON_AIR guide의 `scriptId`가 0이고 source가 현재와 다르면 그 source의 유닛으로 전환합니다(`makeTemporaryScript` 호출). source가 같고 studySequences가 있으면 cuts[0]부터 다시 재생합니다(기존 동작).
- 스크립트 있는 유닛의 전환, 동기화, On Air, imageQuiz/quiz 처리는 전과 같습니다. 기존 jest 테스트가 모두 통과합니다.
- `hotline-class-canvas.tsx`에 `Number(guide.scriptId) > 0`, `onAirScriptId > 0`, `Number(targetScriptId) > 0` 판정이 남아 있지 않습니다.
- `npm test`(jest)가 모두 통과하고, `npx tsc --noEmit`에서 새 오류가 생기지 않습니다.
- 실기기나 시뮬레이터에서 선생님이 mentor `hotline-portrait-live` 목록보기로 스크립트 없는 유닛을 고르면, 학생 캔버스 배경이 그 유닛으로 바뀝니다. 캔버스에서 나갔다가 다시 들어오면 로딩 표시가 사라지고 그 유닛 캔버스가 보입니다.

## 가정
- tutor-web은 스크립트 없는 유닛의 전환 guide에 `scriptId: 0`을 보냅니다(`sendUnitSwitchGuide`의 `scriptId: target.id`, `fetchOnlineClassScripts`의 `id: 0`). 앱만 고쳐 이 값을 처리합니다.
- `onlineClassOfTutor`는 아직 스크립트 없는 유닛에 defaultScript를 내려주지 않습니다. 그래서 핫라인은 지금처럼 `makeTemporaryScript`(`releaseScriptUrl 'default'`)로 기본 보드를 만듭니다.
- 서버가 나중에 음수 defaultScript id를 내려줄 때를 대비해, `normalizeGuideScriptId`와 `hasScriptId`로 음수 id도 처리합니다.
- 패널은 화면이 포커스를 잃으면 언마운트되고 다시 들어오면 새로 마운트됩니다(`app/hotline-class.tsx`의 `isFocused ? Panel : Go3MathLoader`). 그래서 재진입 로딩의 원인은 마지막 메시지 guide의 scriptId 0 처리 하나라고 판단했습니다.
- 마지막 메시지의 유닛이 `live-scripts`에 없으면(수업 목록에서 빠진 유닛) 로딩이 남을 수 있습니다. 이 경우는 이번 범위에서 다루지 않습니다.
