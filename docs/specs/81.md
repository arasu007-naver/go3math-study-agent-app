# script cut position mismatch — make the hotline live canvas background scale match the mentor canvas

## Background and purpose
On the mentor web's `https://mentor.qoolla.com/hotline-portrait-live` canvas, script cuts (the mentor's strokes and objects) sit in the right place on the problem image. On the student tablet's hotline live class canvas (**HotlineClassCanvas**: `src/kit/canvas/note-canvas/hotline-class-canvas.tsx`, HTML template `src/kit/canvas/templates/live-class-canvas-template.ts`), the same cuts drift away from the problem image.

### Cause (from reading the code)
- Mentor canvas (tutor-web `src/components/canvas/PortraitScriptDynamicSizeCanvas.jsx` `changeBackgroundImage`): the coordinate space is 1280×1920. The background image is placed at top=left=10 with `scale = 810 / oImg.width`, and if `oImg.height * scale > 1900` then `scale = 1440 / oImg.height`. In other words, the problem image is always normalized to **810px wide (or 1440px tall for very tall images)**, whatever its actual pixel size. The mentor draws script cuts (ADD objects and so on) at 1280×1920 coordinates on top of that normalized background.
- Tablet canvas (`live-class-canvas-template.ts`): script cuts are multiplied by `classScale` (= `scriptPlayScale`) on left, top, scaleX and scaleY, so they correctly follow the mentor coordinates. The background image is different. The `BACKGROUND` cut (`changeBackgroundImage`) and `INIT_BACKGROUND` (`changeFeedbackBackgroundImage`) both use a fixed `instanceScale = 810/1280*classScale`, which assumes the source image is 1280px wide. They never look at the image's real width or height.
- So whenever the problem image is not exactly 1280px wide, the background is drawn bigger or smaller on the tablet than on the mentor canvas (by a factor of 1280/image width). Script cuts land in the same coordinates as on the mentor canvas, so relative to the background they drift progressively right and down, or left and up, the farther they are from the top-left corner (10,10). Tall images (normalized height over 1900) also skip the mentor's 1440 height cap, so the mismatch is larger for them.

Purpose: make the background image scale and position on the tablet hotline live canvas follow exactly the mentor canvas's rule (×classScale), so script cuts land in the same place relative to the problem image as on the mentor canvas.

## Scope
### In scope
- Change the background scale calculation in `changeBackgroundImage` (`BACKGROUND` action) and `changeFeedbackBackgroundImage` (`INIT_BACKGROUND` action) inside the HTML that `live-class-canvas-template.ts` generates. Use the mentor rule (810/image width, with the 1440/image height cap when the height would exceed 1900), multiplied by classScale.
- Keep this calculation in one function in TS source, as a string-embedded JS function (Hermes release builds do not provide `Function.toString`). Example: a new `LIVE_BG_SCALE_JS` export in `src/kit/canvas/templates/notebook-background-scale.ts`, or a new file next to it. The function signature is `liveBackgroundScale(imgWidth, imgHeight)`, and it returns the mentor-basis scale before classScale is applied.
- Unit tests for the change.

### Out of scope
- No changes to how script cuts (ADD/MODIFY/FOLLOW/PROLOGUE/EPILOGUE/SYNCH, etc.) are scaled. They already follow mentor coordinates via classScale.
- No changes to `canvasScreenSize`, `canvasContextSize` or `scriptPlayScale` in `src/kit/canvas/canvasSize.ts`.
- No changes to the `NOTEBOOK` action (`changeNotebookBackgroundImage`, `notebookBackgroundScale`). It is a separate path for the student's own notebook background.
- No changes to the topic live canvas (**TopicLiveCanvas**, `topic-canvas-template.ts`), the whiteboard template or `canvas-template-base.ts`.
- No changes to tutor-web (the mentor page) or any other project.

## Behavior to change
1. In the `live-class-canvas-template.ts` template, when the background image loads in `changeBackgroundImage(imageUrl)`:
   - `base = liveBackgroundScale(oImg.width, oImg.height)`. In that function, `scale = 810 / imgWidth`, and if `imgHeight * scale > 1900` then `scale = 1440 / imgHeight`. If imgWidth is 0 or invalid, it returns the old default `810/1280`.
   - Call `setBackgroundImage` with `scaleX = scaleY = base * classScale` and `top = left = 10 * classScale` (offset unchanged).
2. `changeFeedbackBackgroundImage(imageUrl)` (`INIT_BACKGROUND`) follows the same rule. The scale must be computed inside the image load callback, from the real image size.
3. The rest of the existing behavior stays the same: `resetEpoch` increment, `canvas.clear()`, `lastSupplementaryYPos = 0`, the postMessage messages (CLEANCUTS / BACKGROUND), and `crossOrigin: 'anonymous'`. The `instanceScale` field in the CLEANCUTS message reports the new final scale value (`base*classScale`).
4. Result: a background image 1280px wide comes out the same as before (810/1280). Images of other widths now take the same relative size as on the mentor canvas.

## API contract
None.

## Acceptance criteria
- `liveBackgroundScale(1280, 1000)` returns 810/1280 (≈0.6328).
- `liveBackgroundScale(810, 1000)` returns 1.
- `liveBackgroundScale(1620, 1000)` returns 0.5.
- `liveBackgroundScale(810, 2000)` returns 1440/2000 = 0.72 (because 2000×1 > 1900).
- `liveBackgroundScale(0, 1000)` and `liveBackgroundScale(undefined, undefined)` return 810/1280 and do not throw.
- The `liveBackgroundScale` function in the HTML string returned by `live-class-canvas-template.ts` can be extracted and evaluated (for example with `new Function`) as JS that gives the same results as above.
- In the template HTML returned by `live-class-canvas-template.ts`, neither `changeBackgroundImage` nor `changeFeedbackBackgroundImage` contains the fixed expression `810/1280*classScale`. Both pass `liveBackgroundScale(oImg.width, oImg.height)*classScale` (or an equivalent expression) as the scaleX/scaleY of `setBackgroundImage`.
- In the template HTML, the background top/left offsets are still `10*classScale`.
- With a mock fabric object, after a BACKGROUND action with an image 810 wide and 1000 tall and classScale=0.9, `setBackgroundImage` receives scaleX=scaleY=0.9 and top=left=9.
- Under the same conditions with an image 1280 wide, the scale is 0.9×810/1280, the same as before.
- The existing tests (`__tests__/liveClassCanvasTemplate.test.ts`, `__tests__/liveClassResetOrder.test.ts`, `__tests__/canvasEraser.test.ts`, `__tests__/classOnAirEntryReplay.test.tsx`, etc.) all still pass.
- The `topic-canvas-template.ts`, `whiteboard-canvas-template.ts`, `canvas-template-base.ts` and `canvasSize.ts` files are unchanged.
