# 주제 실황 수업에서 defaultScript(음수 id) 유닛 전환·동기화 지원

## 배경과 목적
학생 앱 주제 실황 화면 `app/topic-live-class.tsx`는 `topicForStudy`의 `units[].scripts`를 펼쳐 MMKV `live-scripts`에 저장합니다. 캔버스 패널 `src/kit/canvas/note-canvas/topic-live-canvas.tsx`(TopicLiveClassCanvasPanel)는 이 목록에서 `currentScriptId`로 스크립트를 고르고(`refreshMenuscript`), `releaseScriptUrl`을 `scriptMaker`로 불러옵니다.

지금은 스크립트 없는 유닛이 `live-scripts`에 없습니다. 그리고 `onReceiveGuide`와 `refreshMenuscript`는 `scriptId > 0`일 때만 id로 전환합니다. 그래서 선생님이 스크립트 없는 유닛으로 바꿔도(guide scriptId 0) 전환되지 않습니다.

graphql-server가 이런 유닛에 `id: -unitModelId`, `isDefaultScript: true`, 서버 URL을 가진 defaultScript를 넣어 주므로, 앱도 음수 id를 정상 id로 다루고 구버전 guide(scriptId 0 또는 null)는 sourceType/sourceId로 해석해야 합니다.

## 범위
### 하는 것
- `src/api/graphql/queries/topic.ts`의 topicForStudy 쿼리 `units.scripts`에 `isDefaultScript`를 추가합니다.
- `topic-live-canvas.tsx`의 `onReceiveGuide`(CLASS_ON_AIR 분기 포함)와 `refreshMenuscript`에서 scriptId 판정을 '양수'에서 '0이 아닌 수'로 바꿉니다.
- 같은 파일에서 scriptId가 null 또는 0인 guide는 `live-scripts`에서 sourceType/sourceId가 같은 스크립트의 id로 바꿔 처리합니다.
- 이 판정과 정규화를 순수 함수로 분리하고 jest 테스트를 추가합니다.
- `docs/COMPONENTS.md`에 새 파일을 등록합니다.

### 하지 않는 것
- 핫라인 화면(`app/hotline-class.tsx`, `src/kit/canvas/note-canvas/hotline-class-canvas.tsx`)은 바꾸지 않습니다.
- `cacheLiveReleaseScriptUrl`(`legacy.ts`)은 바꾸지 않습니다. defaultScript guide에는 releaseScriptUrl이 없습니다.
- 스크립트 로드(`scriptMaker`)와 재생(`playToPointInternal`) 로직은 바꾸지 않습니다.
- 목록에 없는 양수 scriptId를 defaultScript로 대신하지 않습니다.
- qoolla-package 의존 버전은 바꾸지 않습니다.

## 변경할 동작
1. 새 파일 `src/kit/canvas/note-canvas/live-script-id.ts`에 다음을 export합니다.
   - `hasScriptId(id)`: `Number(id)`가 유한수이고 0이 아니면 true입니다. null, undefined, 0, NaN이면 false입니다.
   - `normalizeGuideScriptId(guide, scripts)`: `hasScriptId(guide?.scriptId)`가 false이고 `guide.sourceType`, `guide.sourceId`가 있을 때만 동작합니다. scripts(`live-scripts` 배열)에서 `src.sourceType == guide.sourceType && String(src.sourceId) == String(guide.sourceId)`이고 `hasScriptId(src.id)`인 항목을 찾습니다. `isDefaultScript === true`를 먼저 고르고, 없으면 첫 항목을 고릅니다. 찾으면 `{ ...guide, scriptId: Number(found.id) }`를, 아니면 guide를 그대로 돌려줍니다.
2. `onReceiveGuide` 시작부에서 imageQuiz와 snapshot 처리 뒤, scriptId 판정 전에 guide를 정규화합니다. 방법은 `guide = normalizeGuideScriptId(guide, JSON.parse(storage.getString('live-scripts') || '[]'))`입니다.
3. CLASS_ON_AIR 분기의 `onAirScriptId > 0` 판정 두 곳을 `hasScriptId(onAirScriptId)`로 바꿉니다.
4. 일반 분기를 다음처럼 바꿉니다.
   - `guide.scriptId == null`인 source 비교 분기는 '`hasScriptId(guide.scriptId)`가 false이고 sourceType이 있음'일 때 지금처럼 동작합니다.
   - `Number(guide.scriptId) > 0`인 분기는 `hasScriptId(guide.scriptId)`일 때 지금처럼 동작합니다(currentScriptId와 다르면 syncPoint 저장, `setCurrentScriptId`).
   - 기존 jest 테스트(`__tests__/liveScriptsCache.test.ts`, `__tests__/classOnAirCanvas.test.ts`, `__tests__/positionGuideCanvas.test.ts`, `__tests__/imageQuizGuide.test.ts`)는 소스 문자열을 검사합니다. 문구가 바뀌면 같은 의도를 검증하도록 테스트를 함께 고칩니다.
5. `refreshMenuscript`의 `Number(targetScriptId) > 0`을 `hasScriptId(targetScriptId)`로 바꿉니다. 음수 id도 `live-scripts`에서 id로 고르게 됩니다.
6. `app/topic-live-class.tsx`의 `live-scripts` 구성(`topicUnits.flatMap(u => u.scripts.map(s => ({...s, sourceType, sourceId})))`)이 defaultScript 항목도 담는지 확인합니다. 마지막 메시지의 `scriptId`(음수)가 `initScript` → `setCurrentScriptId`로 반영되는지도 확인합니다. 막는 조건이 있으면 '0이 아님'으로 고칩니다.

## API 계약
graphql-server spec과 같은 계약입니다.
- `topicForStudy(topicId)` → 스크립트 없는 유닛의 `units[].scripts`: `[{ id: "-{unitModelId}", releaseScriptUrl: "{PUBLIC_BASE_URL}/live-default-script/topic/{topicId}/{unitModelId}", filenames: "", isDefaultScript: true }]`
- `GET {releaseScriptUrl}?ts=...` → raw cut JSON 배열(BACKGROUND 1컷 + 빈 메타 블록). 없으면 404입니다.
- guide: 스크립트 없는 유닛은 `scriptId: -unitModelId` + `sourceType`, `sourceId`입니다. scriptId가 0이 아니면 id로, null이거나 0이면 sourceType/sourceId로 찾습니다.

## 수용 기준
- `hasScriptId(5)`와 `hasScriptId(-12)`, `hasScriptId('-12')`는 true이고, `hasScriptId(0)`, `hasScriptId(null)`, `hasScriptId(undefined)`, `hasScriptId('abc')`는 false입니다.
- `normalizeGuideScriptId({scriptId:0, sourceType:'UNIT', sourceId:1, studyIdx:3}, [{id:'-12', sourceType:'UNIT', sourceId:1, isDefaultScript:true}])`의 결과는 scriptId -12이고 나머지 필드는 같습니다.
- `normalizeGuideScriptId`에 `{scriptId:7}`을 넣으면 그대로 돌려주고, source가 맞는 항목이 없으면 guide를 그대로 돌려줍니다.
- 위를 검증하는 jest 테스트가 있고 `npm test`(jest)가 기존 테스트와 함께 모두 통과합니다.
- TopicLiveCanvas의 `onReceiveGuide`에 currentScriptId와 다른 `scriptId: -12` guide를 넘기면 storage `syncPoint`에 guide가 저장되고 `currentScriptId`가 -12가 됩니다. 소스 검사형 테스트나 코드 확인으로 검증합니다.
- `live-scripts`에 `{id:'-12', ...}`가 있고 currentScriptId가 -12면, `refreshMenuscript`가 그 항목을 currentScript로 고릅니다. 목록 첫 항목으로 떨어지지 않습니다.
- CLASS_ON_AIR guide의 scriptId가 -12면 id 비교로 전환 여부를 정합니다.
- 실기기나 시뮬레이터에서 선생님이 스크립트 없는 유닛으로 전환하면 앱 캔버스 배경이 그 유닛 이미지로 바뀌고, 이후 guide가 처리됩니다. 들어가거나 다시 들어갈 때 마지막 메시지가 그 유닛이면 같은 배경으로 맞춰집니다.
- 스크립트가 있는 유닛의 전환과 동기화, 핫라인 화면 동작은 전과 같습니다.
- `npx tsc --noEmit`에서 새 오류가 생기지 않습니다.

## 가정
- defaultScript 본문은 서버 URL(releaseScriptUrl)로 받으므로 `reloadScript`/`scriptMaker` 로딩 코드는 바꾸지 않습니다.
- scriptId 0 또는 null + sourceType/sourceId 정규화는 배포 전 메시지나 다른 송신자를 위한 호환 처리로 넣습니다.
- 핫라인 화면은 이미 스크립트 없는 문제를 `live-scripts`에 넣고 있어 이번 범위에서 뺍니다.
- 새 순수 함수 파일 위치는 캔버스 패널과 같은 폴더(`src/kit/canvas/note-canvas/`)로 정합니다.
