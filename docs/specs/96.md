# 실황 캔버스: 기본 스크립트 reload 복구와 선생님 캔버스 객체 상태 반영

## 배경과 목적
학생 앱의 **HotlineClassCanvas**(`src/kit/canvas/note-canvas/hotline-class-canvas.tsx`)와 **TopicLiveCanvas**(`src/kit/canvas/note-canvas/topic-live-canvas.tsx`)는 tutor-web guide를 받아 `src/kit/canvas/templates/live-class-canvas-template.ts`의 WebView 캔버스를 제어합니다.

코드에서 확인한 문제는 다음과 같습니다.
1. `reload`의 `downloadScript`는 먼저 `setStudySequences([])`를 호출해 캔버스를 로딩 표시로 바꾼 뒤 `${currentScript.releaseScriptUrl}?ts=...`를 불러옵니다. 스크립트 없는 유닛은 `releaseScriptUrl`이 없어 `undefined?ts=...`를 요청하고, 실패하면 `studySequences`가 빈 채로 남아 로딩 표시가 사라지지 않습니다.
2. 패널의 `magnifyArea`는 `STAND_OUT`에 `obj`만 보내지만, 템플릿은 `magnifyObj(action.objId)`만 호출하므로 영역 돋보기가 앱에서 동작하지 않습니다.
3. `SYNCH`의 `syncCanvasObjects`는 없는 객체만 추가하고 이미 있는 객체의 위치와 크기는 바꾸지 않습니다.
4. `select`, `magnify` guide의 객체 상태를 적용하는 경로가 없습니다.
5. **TopicLiveCanvas**는 **HotlineClassCanvas**와 달리 `handleLiveClassMessage` 호출 전에 `dropEmptyScriptId`를 적용하지 않습니다.

## 범위
### 하는 것
- 두 패널의 reload를 실패해도 로딩에 갇히지 않게 고칩니다.
- 스크립트 없는 유닛의 reload는 임시 기본 스크립트로 처리합니다.
- 템플릿에 영역 돋보기, 객체 상태 적용, 스냅샷 없는 보드 초기화를 추가합니다.
- `snapshot`, `cleanMessy`, `reload`, `canvas-synch`, `select`, `magnify`, `magnifyArea` 수신 동작을 테스트로 확인합니다.

### 하지 않는 것
- `@qoolla/script-parser`, 서버, tutor-web, student-web은 바꾸지 않습니다.
- 학생 필기 도구, 스크립트 재생 순서, 컷 형식, 캔버스 크기와 `classScale` 계산은 바꾸지 않습니다.
- `canvas-synch`로 선생님 캔버스에 없는 객체를 학생 캔버스에서 지우지 않습니다.
- `select` 수신 시 학생 캔버스에 선택 표시를 만들지 않습니다.

## 변경할 동작
1. **reload (두 패널 공통)**
   - `downloadScript`에서 `setStudySequences([])`를 호출하지 않습니다. 새 스크립트가 준비될 때까지 기존 캔버스를 유지합니다.
   - 복귀 지점은 `{ studyIdx: guide.studyIdx ?? lastGuide.studyIdx, step: guide.step ?? lastGuide.step ?? 'main' }`입니다.
   - URL이 있으면 지금처럼 `?ts=`를 붙여 `scriptMaker`로 불러옵니다.
   - **HotlineClassCanvas**에서 URL이 없거나 `'default'`이면 `makeTemporaryScript(currentScript.sourceType, currentScript.sourceId)`를 씁니다.
   - **TopicLiveCanvas**에서 URL이 없으면 다시 불러오지 않고 기존 스크립트와 보드를 유지합니다.
   - 로드 성공 시: 복귀 지점을 `syncPoint`에 저장하고, `RESET_BOARD`를 보내고, `initClassroomStuffs`, `setMenuScript`, `setStudySequences`와 재생 상태 초기화를 수행합니다. 기존 `menuScript` effect가 복귀 지점까지 재생합니다.
   - 로드 실패 또는 `null` 결과 시: 오류를 기록하고 기존 `menuScript`, `studySequences`, 보드를 그대로 유지합니다. `syncPoint`는 쓰지 않으며 처리되지 않은 예외를 남기지 않습니다.
   - reload 경로에서 `synchToCurrent()`를 별도로 호출하지 않습니다.
2. **템플릿 `RESET_BOARD`**
   - `resetEpoch`를 올리고 `backgroundSubs`를 뺀 객체를 지웁니다.
   - `clearCanvas`와 달리 `SAVE` 메시지를 보내지 않습니다.
3. **템플릿 `STAND_OUT`과 영역 돋보기**
   - `action.objId`가 있으면 `magnifyObj(action.objId)`를 호출합니다.
   - 없고 `action.obj`에 `left`, `top`, `width`, `height`가 있으면 새 함수 `magnifyArea(action.obj)`를 호출합니다.
   - `magnifyArea`는 입력 좌표에 `classScale`을 곱한 영역을 캡처합니다. 기본 배율 `scale ?? 1.38`로 표시하되 스크립트 영역(1280×1920에 `classScale`을 곱한 크기)을 넘지 않게 배율과 위치를 제한합니다. tutor-web `PortraitScriptDynamicSizeCanvas.magnifyArea`의 배치 규칙을 따릅니다.
   - 표시 객체 id는 `magnifier:<timestamp>`이고 새 돋보기를 띄우기 전에 기존 돋보기를 지웁니다.
   - `removeFlyingObjs`는 `fly:`와 `magnifier:` 객체를 지웁니다.
   - `REMOVE_OBJ`의 id가 `magnifier:`로 시작하면 표시 중인 돋보기를 지웁니다.
4. **템플릿 `APPLY_OBJ_STATE`와 `SYNCH`**
   - `applyObjectState(target, raw)`는 `left`, `top`, `scaleX`, `scaleY`에 `classScale`을 곱해 적용하고 `angle`, `flipX`, `flipY`를 적용한 뒤 `setCoords()`와 렌더를 수행합니다. `opacity`, `src`, `width`, `height`는 적용하지 않습니다. 값이 숫자가 아니거나 없는 필드는 건너뜁니다.
   - `APPLY_OBJ_STATE`는 `action.obj.id`의 객체에 이를 적용하고, 객체가 없으면 오류 없이 무시합니다.
   - `syncCanvasObjects`는 이미 있는 객체에 `applyObjectState`를 적용하고, 없는 객체는 지금처럼 추가합니다. `magnifier:`, `temporary:` 객체는 갱신 대상에서 뺍니다.
5. **guide 처리 (두 패널 공통)**
   - `select`, `magnify` guide에 `objState`가 있으면 `handleLiveClassMessage` 호출 전에 `sendBoardAction({ actionType: 'APPLY_OBJ_STATE', obj: guide.objState })`를 보냅니다.
   - **TopicLiveCanvas**도 `handleLiveClassMessage` 호출 전에 `guide = dropEmptyScriptId(guide)`를 적용합니다.

## API 계약
기존 실황 guide를 받으며, 다음 선택 필드를 처리합니다.

```json
{
  "action": "select | magnify",
  "objId": "fly:1",
  "objState": {
    "id": "fly:1",
    "left": 100,
    "top": 200,
    "width": 300,
    "height": 150,
    "scaleX": 1,
    "scaleY": 1,
    "angle": 0,
    "flipX": false,
    "flipY": false
  }
}
```

- 좌표와 크기는 스크립트 좌표계(1280×1920) 기준입니다.
- `objState`가 없는 guide도 지금처럼 처리합니다.
- `canvas-synch`의 `objects` 형식은 그대로이며, 이미 있는 객체에 위치, 크기, 회전, 반전을 적용합니다.
- `reload`, `cleanMessy`, `snapshot` guide에는 `actionType: "MAGNIFY"`가 들어가지 않습니다.

## 수용 기준
- `releaseScriptUrl`이 없는 hotline 유닛에서 `reload` guide를 받으면 `scriptMaker`를 호출하지 않고 `makeTemporaryScript`를 호출하며, 처리 뒤 로딩 표시가 없고 WebView가 남아 있습니다.
- 위 reload 처리 중 어느 시점에도 `studySequences`가 비어 로딩 표시로 바뀌지 않습니다.
- URL이 있는 스크립트의 hotline, topic reload에서 `scriptMaker`가 실패하면 로딩 표시가 나타나지 않고 기존 WebView와 재생 상태가 유지되며 처리되지 않은 rejection이 없습니다.
- URL이 있는 스크립트의 reload가 성공하면 `RESET_BOARD`가 전송되고 guide의 `studyIdx`, `step`까지 다시 재생됩니다.
- `RESET_BOARD` 처리 중 `contentMeta: 'SAVE'` 메시지가 발생하지 않습니다.
- `cleanMessy` guide를 받으면 `CLEAN_ADHOCS`가 전송되고, 템플릿의 `removeFlyingObjs` 본문은 `fly:`와 `magnifier:`를 모두 지웁니다.
- `snapshot` guide를 받으면 스크립트 유무와 관계없이 `SAVE`가 한 번 전송됩니다.
- `canvas-synch` guide의 `objects`에 있는 기존 객체의 `left`, `top`, `scaleX`, `scaleY`는 각 값에 `classScale`을 곱한 값으로 바뀌고 객체 수는 늘지 않습니다.
- `canvas-synch` guide의 `objects`에 없던 객체는 추가되고, guide에 없는 기존 객체는 지워지지 않습니다.
- `objState`가 있는 `select` guide는 `APPLY_OBJ_STATE`를 전송합니다.
- `objState`가 있는 `magnify` guide는 `APPLY_OBJ_STATE`를 먼저, `STAND_OUT`을 그다음에 전송합니다.
- `objState`가 없는 `select`, `magnify` guide는 `APPLY_OBJ_STATE`를 전송하지 않습니다.
- 없는 id의 `APPLY_OBJ_STATE`는 오류를 내지 않습니다.
- `magnifyArea` guide를 받으면 `STAND_OUT`이 `obj`와 함께 전송되고, 템플릿은 `objId`가 없고 영역 값이 있는 경우 `magnifyArea`를 호출합니다.
- **TopicLiveCanvas**에서 scriptId 0인 adhoc guide가 공용 처리기의 스크립트 전환으로 걸러지지 않고 `FLY`로 전송됩니다.
- 기존 테스트(`__tests__/hotlineScriptlessAdhoc.test.tsx`, `__tests__/liveClassCanvasTemplate.test.ts` 등)와 새 테스트가 모두 통과하고, `tsc`와 lint에 새 오류가 없습니다.

## 가정
- 요구사항의 임시 default script는 hotline에서 `releaseScriptUrl`이 없어 `makeTemporaryScript`로 만드는 스크립트로 봅니다.
- topic의 defaultScript는 서버가 `releaseScriptUrl`을 제공하므로 일반 URL 경로로 다시 불러옵니다.
- reload는 보드를 현재 진행 지점까지 다시 재생하는 동작으로 보고, reload 전에 받은 Flying Object는 복원하지 않습니다. 선생님이 canvas 동기화를 누르면 복원됩니다.
- `opacity`는 선생님 쪽 애니메이션 중간값이 전달될 수 있어 동기화하지 않습니다.
- flying 객체 id는 현재 앱의 제거 규칙대로 `fly:` 접두사를 쓴다고 봅니다.
