# CLASS_ON_AIR 메시지 수신 (student-app)

## 배경과 목적
tutor-web은 이제 '강의 시작' 때 학생 화면을 송출하지 않습니다. 대신 선생님이 'On Air' 버튼을 누르면 `CLASS_ON_AIR` guide를 한 번 보냅니다. 이 guide는 현재 선생님 페이지의 유닛을 기준으로 합니다.

student-app은 이 메시지를 받으면 다음을 해야 합니다.
- 수업 대기 화면(LiveClassWaiting)을 내립니다.
- guide가 가리키는 스크립트를 불러옵니다.
- cuts[0]을 처음부터 재생합니다.

## 범위
### 하는 것
- **HotlineClassScreen** (`app/hotline-class.tsx`)과 TopicLiveClassScreen (`app/topic-live-class.tsx`)의 구독 처리에서 CLASS_ON_AIR를 진행 메시지로 다룹니다.
- HotlineClassCanvas (`src/kit/canvas/note-canvas/hotline-class-canvas.tsx`)와 TopicLiveCanvas (`src/kit/canvas/note-canvas/topic-live-canvas.tsx`)의 `onReceiveGuide`에서 CLASS_ON_AIR를 명시적으로 처리합니다.

### 하지 않는 것
- quiz/imageQuiz/snapshot/step/refresh 같은 기존 action 처리는 바꾸지 않습니다.
- qoolla-package의 `handleLiveClassMessage` / `playToPoint`는 바꾸지 않습니다.
- student-web은 바꾸지 않습니다.

## 변경할 동작
1. 상수 `CLASS_ON_AIR = 'CLASS_ON_AIR'`를 공용 위치 한 곳에 둡니다. 예: `src/kit/live-class/` 아래 상수 파일.
2. 화면(구독 onData와 마지막 메시지 조회)
   - CLASS_ON_AIR는 quiz/imageQuiz처럼 가로채지 않습니다.
   - 화면이 `waiting`이면 `live`로 바꾸고 `panelRef.current?.onReceiveGuide(guide)`에 넘깁니다. 기존 '그 밖의 guide' 경로와 같습니다.
   - topic 화면은 기존처럼 `setLastPoint(guide)`도 합니다.
   - 마지막 메시지(`lastOnlineClassMessage` / `lastLiveTopicMessage`)가 CLASS_ON_AIR이면, 늦게 들어온 학생에게도 기존 규칙대로 패널 전달 또는 storage `syncPoint` 저장을 합니다.
3. 캔버스 `onReceiveGuide` (두 파일 공통). `guide.action === CLASS_ON_AIR`일 때:
   - **(a) guide의 스크립트가 지금 열린 스크립트와 다를 때.** 판정 기준은 scriptId가 0보다 크면 `currentScriptId`와 비교하고, scriptId가 null/0이면 sourceType/sourceId로 비교합니다.
     - 기존 전환 경로를 그대로 씁니다: `storage.set('syncPoint', JSON.stringify(guide))`, `setLastGuide({studyIdx:0, step:'refresh'})`, `setTargetGuide(guide)`, 스크립트 전환.
     - 스크립트가 로드되면 기존 로드 effect가 backgroundCut을 보내고 `playToPointInternal(syncPoint)`로 cuts[0](studyIdx 0, step 'main')까지 재생합니다.
     - guide에 releaseScriptUrl이 있으면 기존 `cacheLiveReleaseScriptUrl(guide)`로 목록 캐시에 반영합니다. 그래서 수업 중 새로 등록된 release 스크립트도 열립니다.
   - **(b) 같은 스크립트가 이미 열려 있을 때.** 이전 진행 지점과 상관없이 처음부터 다시 시작합니다.
     - `setCurrentIdx(0)` 하고 `setLastGuide({ ...guide, studyIdx: 0, step: 'main' })` 합니다.
     - 그 다음 `playToPointInternal({ studyIdx: 0, step: 'main' }, null)`를 호출합니다. fromPt가 null이므로 backgroundCut을 먼저 보내 캔버스를 초기화한 뒤, cuts[0]의 prologue와 main을 재생합니다.
     - `handleLiveClassMessage`는 부르지 않습니다.
   - 스크립트의 컷(studySequences)이 아직 비어 있어 바로 재생할 수 없으면 `storage.set('syncPoint', ...)`에 guide를 둡니다. 로드가 끝나면 기존 effect가 재생합니다.

## API 계약
수신 경로는 기존 GraphQL subscription과 query입니다.
- hotline: `newOnlineClassMessage(tutorId)` 구독과 `lastOnlineClassMessage(tutorId)` 조회. 보내는 쪽은 `sendOnlineClassMessage`.
- topic: `liveTopicClassMessage(topicId)` 구독과 `lastLiveTopicMessage(topicId)` 조회. 보내는 쪽은 `sendLiveTopicMessage`.

메시지 `content`는 아래 JSON 문자열입니다.
```json
{
  "action": "CLASS_ON_AIR",
  "tutorId": "<hotline 일 때>",
  "topicId": "<topic 일 때>",
  "scriptId": 123,
  "studyIdx": 0,
  "rawCutIdx": 0,
  "step": "main",
  "mode": "main",
  "sourceType": "<유닛 sourceType>",
  "sourceId": 456,
  "releaseScriptUrl": "<있을 때만>"
}
```
- scriptId가 0이면 스크립트가 없는 유닛입니다. 이때는 sourceType/sourceId로 유닛을 찾습니다.

## 수용 기준
- HotlineClassScreen이 waiting 상태일 때 구독으로 action이 'CLASS_ON_AIR'인 guide를 받으면 대기 화면이 사라지고, 그 guide가 패널 `onReceiveGuide`로 한 번 전달됩니다.
- TopicLiveClassScreen이 waiting 상태일 때 CLASS_ON_AIR guide를 받으면 대기 화면이 사라지고, guide가 `setLastPoint`와 패널 `onReceiveGuide`로 전달됩니다.
- CLASS_ON_AIR guide를 받아도 QuizResponseModal은 열리지 않습니다.
- HotlineClassCanvas/TopicLiveCanvas의 `onReceiveGuide`에 현재와 다른 scriptId의 CLASS_ON_AIR guide를 넘기면 storage 'syncPoint'에 그 guide가 저장되고, currentScriptId가 guide.scriptId로 바뀝니다.
- 이 경우 스크립트 로드가 끝나면 `playToPointInternal`이 studyIdx 0, step 'main'으로 호출됩니다.
- 이미 열린 스크립트와 같은 scriptId의 CLASS_ON_AIR guide를 넘기면 다음이 성립합니다.
  - 이전 진행 지점이 studyIdx 5여도 `playToPointInternal`이 `({studyIdx:0, step:'main'}, null)`로 호출됩니다.
  - backgroundCut이 웹뷰로 먼저 전송된 뒤 cuts[0]이 전송됩니다.
  - `handleLiveClassMessage`는 호출되지 않습니다.
- scriptId가 0이고 sourceType/sourceId가 현재와 다른 CLASS_ON_AIR guide를 넘기면, 기존 sourceType/sourceId 전환 경로로 해당 유닛이 열리고 syncPoint가 저장됩니다.
- 마지막 메시지 조회 결과가 CLASS_ON_AIR guide이면 화면이 live 상태가 되고, 그 guide가 패널에 전달되거나 syncPoint에 저장됩니다.
- 기존 테스트(`__tests__/liveClassWaiting.test.tsx`, `__tests__/imageQuizGuide.test.ts` 등)가 모두 통과합니다.
- 위 CLASS_ON_AIR 수신 동작을 검증하는 테스트가 추가되어 통과합니다.

## 가정
- 같은 스크립트가 열린 상태에서 CLASS_ON_AIR를 받으면 처음(cuts[0])부터 다시 그립니다. 학생이 그린 필기도 backgroundCut 전송으로 지워질 수 있습니다.
- 진입하자마자 받는 마지막 메시지가 이전 수업의 메시지일 수 있지만, 이번 범위에서는 따로 처리하지 않습니다.
