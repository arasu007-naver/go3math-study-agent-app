# graphql subscription 재연결 — student-app

## 배경과 목적
**GraphqlClient** `src/api/graphql/client.ts`는 `retryAttempts: 3`, 대기 2·4·6분이라 서버 재시작 때 회복이 매우 늦거나 영구히 끊깁니다. 다시 연결돼도 끊긴 동안의 수업 위치를 맞추지 않습니다. 앱이 백그라운드에서 돌아올 때 죽은 소켓도 바로 감지하지 못합니다. 연결을 자동 복구하고 실황 canvas 화면을 마지막 위치로 따라잡게 합니다.

## 범위
### 하는 것
- **GraphqlClient** `src/api/graphql/client.ts`의 재연결 정책 변경과 상단 주석 갱신
- 새 파일 **WsRecovery** `src/api/graphql/wsRecovery.ts`, **useWsReconnected** `src/api/graphql/useWsReconnected.ts` 추가 및 **docs/COMPONENTS.md** 갱신
- 재연결 따라잡기 적용: **TopicLiveClassScreen** `app/topic-live-class.tsx`, **HotlineClassScreen** `app/hotline-class.tsx`
- `__tests__/wsRecovery.test.ts` 추가

### 하지 않는 것
- 끊긴 동안 놓친 퀴즈의 복구와 중간 메시지 재생은 하지 않습니다.
- 연결 상태 UI와 새 네이티브 의존성(NetInfo 등)은 추가하지 않습니다.
- **TopicLiveCanvas**, **HotlineClassCanvas**, **LiveClassStartTime**은 수정하지 않습니다.

## 변경할 동작
1. `createClient`: `retryAttempts: Infinity`, `shouldRetry: () => true`, `keepAlive: 10000`. `retryWait`는 `retryDelayMs(retries)`에 0 이상 500 미만의 임의 ms를 더해 기다립니다.
2. `wsRecovery.ts`에 `retryDelayMs(n) = min(500 * 2^n, 3000)`과 `attachWsRecovery(client, { pongTimeoutMs = 5000, notifyDelayMs = 300, retryDelay = retryDelayMs } = {})`를 export합니다. 반환값은 `{ client, onReconnected(listener) => unsubscribe, forceReconnect() }`입니다.
   - **pong 감시**: `client.on('ping')`에서 `received === false`이면 타이머를 시작하고, `pong`(`received === true`)과 `closed`에서 해제합니다. 시간이 지나면 `client.terminate()`를 호출합니다.
   - **재연결 알림**: `closed`의 code가 `1000`이 아니면 표시하고, 그 뒤 `connected`에서 표시를 지운 다음 `notifyDelayMs` 뒤 listener들을 한 번 호출합니다. 그 사이 `closed`가 오면 취소합니다.
   - **4500 재구독**: 반환 `client`의 `subscribe`는 `code === 4500` 오류를 sink에 전달하지 않고 `retryDelay(attempt)` 뒤 같은 payload로 재구독합니다. `attempt`는 데이터를 받으면 0으로 돌아갑니다. 다른 오류는 전달하며, 해제 함수는 대기 타이머와 현재 구독을 모두 해제합니다.
   - **forceReconnect**: 연결된 상태일 때만 `client.terminate()`를 호출합니다.
3. `client.ts`는 `new GraphQLWsLink(recovery.client)`를 쓰고 `onWsReconnected(listener)`를 export합니다. React Native `AppState`를 구독해 `background`에 머문 시간이 5초 이상이고 `active`로 돌아오면 `forceReconnect()`를 호출합니다.
4. `useWsReconnected(callback, enabled)`는 최신 callback을 ref에 보관하고 `enabled`가 true일 때만 listener를 등록합니다. 두 화면은 `enabled`에 `isFocused`를 넘깁니다.
5. 두 화면의 재연결 처리(`recoverLivePosition`)는 기존 `callGetLastTopicMessage` / `callGetLastMessage`와 별도 함수로 만들고 다음을 지킵니다.
   - 마지막 메시지를 조회하고 `toPositionGuide`로 변환합니다.
   - 조회 실패 시 로그만 남깁니다. 토픽 화면의 `notReady()`를 호출하지 않아 수업 화면에서 튕기지 않습니다.
   - 메시지가 없으면 현재 상태를 유지합니다.
   - `isPositionGuide`가 false인 guide(`snapshot`, `canvas-synch`, `renewScript`, `reload`)는 적용하지 않습니다.
   - `scriptId`, `studyIdx`, `step`이 마지막으로 적용한 위치와 모두 같으면 적용하지 않습니다. 이를 위해 화면에 `lastAppliedPositionRef`를 두고, 구독으로 받은 위치 guide와 기존 따라잡기 및 복구로 적용한 guide를 기록합니다.
   - 적용 시 `setLiveState('live')` 후 `panelRef.current.onReceiveGuide(guide)`를 호출하고, 패널이 없으면 `storage.set('syncPoint', ...)`에 저장합니다. 토픽 화면은 `setLastPoint(guide)`도 호출합니다.

## API 계약
없음(기존 계약 사용). `lastLiveTopicMessage(topicId: Int!)`, `lastOnlineClassMessage(tutorId: String!)`, 기존 subscription, `connectionParams.authToken`.

## 수용 기준
- `retryDelayMs`의 n=0,1,2,3,10 결과는 500, 1000, 2000, 3000, 3000입니다.
- `src/api/graphql/client.ts`에 `retryAttempts: Infinity`, `keepAlive: 10000`이 있고 `retries * 2 * 60 * 1000`이 없습니다.
- 가짜 client로 `ping(false)` 뒤 5000ms 동안 pong이 없으면 `terminate`가 한 번 호출되고, pong이 오면 호출되지 않습니다.
- `closed(1006)` 뒤 `connected`가 오면 300ms 뒤 listener가 한 번 호출되고, `closed(1000)` 뒤에는 호출되지 않습니다.
- `sink.error({code:4500, reason:'x'})`는 바깥 sink로 전달되지 않고 같은 payload로 재구독하며, `code`가 없는 오류는 바깥 sink로 전달됩니다.
- 재구독 대기 중 해제하면 재구독이 일어나지 않습니다.
- 앱이 5초 이상 background였다가 active가 되면 연결 상태에서 `terminate`가 호출되고, 5초 미만이면 호출되지 않습니다.
- 재연결 알림에서 위치가 달라진 guide를 받으면 `onReceiveGuide`가 그 guide로 한 번 호출됩니다.
- 위치가 같으면 `onReceiveGuide`가 호출되지 않습니다.
- 마지막 메시지가 `snapshot`이면 `onReceiveGuide`가 호출되지 않습니다.
- 마지막 메시지가 `quiz`면 퀴즈 모달을 열지 않고 `action: 'refresh'` 위치 guide로 적용합니다.
- 재연결 조회가 실패해도 토픽 화면이 뒤로 이동하지 않고 토스트 '주제 실황 강의가 준비되지 않았습니다'가 표시되지 않습니다.
- 화면이 포커스를 잃은 상태에서는 재연결 처리가 실행되지 않습니다.
- 실기기나 시뮬레이터에서 graphql-server를 재시작하면 `/topic-live-class`, `/hotline-class`가 조작 없이 서버 복귀 후 5초 안에 구독을 복구하고 이후 메시지를 canvas에 반영합니다.
- `docs/COMPONENTS.md`에 WsRecovery와 useWsReconnected 항목이 있습니다.
- `npm test`와 `npm run typecheck`가 통과합니다.

## 가정
- 앱 복귀 시 재연결 기준은 background 5초 이상으로 합니다.
- 이미 설치된 구버전 앱은 새 버전으로 업데이트해야 이 동작을 얻습니다.
