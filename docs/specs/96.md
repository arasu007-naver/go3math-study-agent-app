# 실황 캔버스: reload 로딩 고착 수정과 선생님 flying object 상태 동기화

## 배경과 목적
tutor-web의 Flying Objects 영역에서 `reload`를 누르면 학생 앱에 로딩 표시가 사라지지 않는 문제를 고칩니다. 또 mentor.qoolla.com(tutor-web)이 보내기, 확대 등의 메시지를 보낼 때 함께 전달하는 flying object의 마지막 상태(위치, 스케일 등)를 학생 캔버스에 반영해 선생님 캔버스와 일치시킵니다.

대상 컴포넌트는 **HotlineClassCanvas**(`src/kit/canvas/note-canvas/hotline-class-canvas.tsx`), **TopicLiveCanvas**(`src/kit/canvas/note-canvas/topic-live-canvas.tsx`), 두 패널이 쓰는 WebView 템플릿 `src/kit/canvas/templates/live-class-canvas-template.ts`입니다.

코드에서 확인한 현재 동작은 다음과 같습니다.
1. `downloadScript`가 먼저 `setStudySequences([])`를 호출해 WebView를 로딩 표시로 바꿉니다. 이후 `${currentScript.releaseScriptUrl}?ts=...`를 불러오므로, URL이 없으면 `undefined?ts=...`를 요청하고 실패 시 로딩이 끝나지 않습니다.
2. 공용 처리기 `handleLiveClassMessage`는 `guide.scriptId != null`이고 `currentScript.id`와 다르면 스크립트 전환으로 보고 반환합니다. 스크립트 없는 유닛의 `scriptId: 0` reload는 이 경로에서 `downloadScript`까지 가지 못할 수 있습니다.
3. 패널의 `magnifyArea`는 `STAND_OUT`에 `obj`만 보내는데 템플릿은 `magnifyObj(action.objId)`만 호출합니다.
4. 템플릿 `syncCanvasObjects`는 없는 객체만 추가하고 기존 객체의 상태는 바꾸지 않습니다.
5. `select`, `magnify` guide의 `objState`를 적용하는 경로가 없습니다.

## 범위
### 하는 것
- 두 패널의 reload가 성공, 실패와 관계없이 로딩에 갇히지 않게 합니다.
- 스크립트 없는 hotline 유닛의 reload는 임시 기본 스크립트로 처리합니다.
- 템플릿에 영역 돋보기, 객체 상태 적용, SAVE 없는 보드 초기화를 추가합니다.
- `snapshot`, `cleanMessy`, `reload`, `canvas-synch`, `select`, `magnify`, `magnifyArea` 수신 동작을 테스트합니다.

### 하지 않는 것
- `dropEmptyScriptId`를 새로 만들거나, TopicLiveCanvas에 적용하거나, 이미 있는 호출을 제거하지 않습니다. 이 함수의 유무에 구현이 의존하면 안 됩니다.
- `@qoolla/script-parser`, 서버, tutor-web, student-web은 바꾸지 않습니다.
- 학생 필기 도구, 스크립트 재생 순서, 컷 형식, 캔버스 크기와 `classScale` 계산은 바꾸지 않습니다.
- `canvas-synch`로 선생님 캔버스에 없는 객체를 학생 캔버스에서 지우지 않습니다.
- `select` 수신 시 학생 캔버스에 선택 표시를 만들지 않습니다.

## 변경할 동작
### 1. reload (두 패널 공통)
- `onReceiveGuide`에서 스크립트 전환 판정과 `quiz`, `follow`, `lastStep`, `canvas-synch`, `synch` 분기를 지난 뒤, `handleLiveClassMessage` 호출 전에 `guide.action`이 `reload` 또는 `renewScript`이면 `await ctx.downloadScript()`를 호출하고 반환합니다. `scriptId: 0` guide가 공용 처리기에서 걸러지지 않게 하기 위함입니다.
- `ctx.downloadScript`는 이 guide를 기준으로 새 reload 함수를 호출합니다. `setStudySequences([])`와 `synchToCurrent()`는 호출하지 않으며, 새 스크립트가 준비될 때까지 기존 WebView와 보드를 유지합니다.
- 복귀 지점은 `{ studyIdx: guide.studyIdx ?? lastGuide.studyIdx, step: guide.step ?? lastGuide.step ?? 'main' }`입니다. `guide.mode`(`'reload'`)는 step으로 쓰지 않습니다.
- 스크립트 출처:
  - **HotlineClassCanvas**: `currentScript?.releaseScriptUrl || releaseScriptUrl` 상태값을 URL로 씁니다. 값이 있고 `'default'`가 아니면 `?ts=<uuid>`를 붙여 `scriptMaker`로 불러옵니다. 없거나 `'default'`이면 `makeTemporaryScript(currentScript.sourceType, currentScript.sourceId)`를 씁니다.
  - **TopicLiveCanvas**: `currentScript?.releaseScriptUrl`이 있으면 `?ts=<uuid>`를 붙여 불러옵니다. 없으면 아무것도 불러오지 않고 기존 스크립트와 보드를 유지합니다.
- 결과 적용 전에 `await playChainRef.current`로 진행 중인 재생이 끝나기를 기다립니다.
- 더 새로운 reload가 시작됐거나 기다리는 동안 현재 스크립트(id, sourceType, sourceId)가 바뀌었으면 결과를 버립니다. ref로 판정하며 `syncPoint`와 보드를 건드리지 않습니다.
- 로드 성공 시 순서: 복귀 지점을 `syncPoint`에 저장 → `RESET_BOARD` 전송 → `initClassroomStuffs(cuts)` → `hasPlayedSinceLoadRef.current = false`, `lastPlayedRef.current = null` → `setMenuScript({ ...cuts })` → `setStudySequences(cuts.contents)`. 기존 `menuScript` effect가 복귀 지점까지 재생합니다. 같은 객체를 돌려받아도 effect가 돌도록 `setMenuScript`에는 항상 새 객체 참조를 넘깁니다.
- 로드 실패, `null` 결과, `contents`가 비어 있는 결과: 오류를 기록하고 기존 `menuScript`, `studySequences`, 보드를 유지합니다. `syncPoint`를 쓰지 않고 처리되지 않은 rejection을 남기지 않습니다.

### 2. 템플릿 `RESET_BOARD`
- `resetEpoch`를 올리고 `backgroundSubs`에 없는 객체를 지운 뒤 렌더합니다.
- `clearCanvas`와 달리 `toDataURL`이나 `SAVE` 메시지를 만들지 않습니다.

### 3. 템플릿 `STAND_OUT`과 영역 돋보기
- `action.objId`가 있으면 `magnifyObj(action.objId)`를 호출합니다.
- 없고 `action.obj`의 `left`, `top`, `width`, `height`가 모두 숫자이면 새 함수 `magnifyArea(action.obj)`를 호출합니다. 그 외에는 무시합니다.
- `magnifyArea`는 입력 좌표에 `classScale`을 곱한 영역을 캡처합니다. 기본 배율은 `scale`이 양수일 때 그 값, 아니면 1.38입니다.
- 배치는 office-manager의 `PortraitScriptDynamicSizeCanvas.magnifyArea`(tutor-web이 쓰는 캔버스) 규칙을 따릅니다. 기준 영역은 `1280*classScale` × `1920*classScale`이고, 가로와 세로를 각각 3등분해 원점을 left/center/right, top/center/bottom으로 정하며, 표시 크기와 위치가 기준 영역을 넘지 않게 제한합니다. 흰 배경, 둥근 모서리, 주황 테두리 그룹을 배율 1에서 목표 배율로 500ms 애니메이션합니다.
- 레티나 환경에서 캡처 이미지의 픽셀 크기가 영역과 달라도 이미지 표시 크기는 캡처 영역 크기와 같아야 합니다.
- 표시 객체 id는 `magnifier:<timestamp>`이며 `selectable`, `evented`는 false입니다. 새 돋보기를 띄우기 전과 이미지 로드 콜백에서 기존 `magnifier:` 객체를 지웁니다.
- 이미지 로드 콜백은 시작 시점의 `resetEpoch`와 다르면 아무것도 추가하지 않습니다. 캡처 실패는 오류 없이 무시합니다.
- `removeFlyingObjs`는 `fly:`와 `magnifier:` 객체를 모두 지웁니다.
- `REMOVE_OBJ`의 id가 `magnifier:`로 시작하면 표시 중인 `magnifier:` 객체를 모두 지웁니다. 학생 쪽 돋보기 id의 timestamp가 선생님 쪽과 다르기 때문입니다.

### 4. 템플릿 `APPLY_OBJ_STATE`와 `SYNCH`
- `applyObjectState(target, raw)`는 `left`, `top`, `scaleX`, `scaleY`에 `classScale`을 곱해 적용하고, `angle`, `flipX`, `flipY`를 적용한 뒤 `setCoords()`와 렌더를 수행합니다.
- `opacity`, `src`, `width`, `height`는 적용하지 않습니다. 없는 필드나 타입이 맞지 않는 필드(숫자 필드의 비숫자, flip의 비불리언)는 건너뜁니다.
- `APPLY_OBJ_STATE`는 `action.obj.id`의 객체에 이를 적용하고, 객체가 없으면 오류 없이 무시합니다.
- `syncCanvasObjects`는 이미 있는 객체에 `applyObjectState`를 적용하고 없는 객체는 지금처럼 추가합니다. id가 `magnifier:`, `temporary:`로 시작하는 기존 객체는 갱신하지 않습니다.

### 5. objState 적용 (두 패널 공통)
- `select`, `magnify` guide에 `objState`가 있으면 스크립트 전환 판정을 통과한 뒤 `handleLiveClassMessage` 호출 전에 `sendBoardAction({ actionType: 'APPLY_OBJ_STATE', obj: guide.objState })`를 보냅니다.
- `dropEmptyScriptId` 관련 변경은 이 작업에 포함하지 않습니다.

## API 계약
서버나 다른 프로젝트의 변경은 없습니다. tutor-web이 이미 보내는 실황 guide를 다음과 같이 해석합니다.

```json
{
  "action": "select | magnify",
  "scriptId": 12,
  "studyIdx": 3,
  "step": "main",
  "objId": "fly:1",
  "objState": {
    "id": "fly:1",
    "left": 100,
    "top": 200,
    "width": 300,
    "height": 150,
    "scaleX": 1,
    "scaleY": 1,
    "angle": 0,
    "flipX": false,
    "flipY": false
  }
}
```

- 좌표와 크기는 스크립트 좌표계(1280×1920) 기준입니다.
- `objState`가 없는 guide는 지금처럼 처리합니다.
- `reload` guide는 `{ action: 'reload', mode: 'reload', step: <현재 step>, studyIdx, scriptId, sourceType, sourceId }` 형태입니다.
- `magnifyArea` guide는 `{ action: 'magnifyArea', actionType: 'MAGNIFY', mode: 'background', objId: 'magnifier:...', obj: { left, top, width, height }, content }` 형태입니다.
- `canvas-synch`의 `objects` 형식은 그대로입니다.

WebView 내부 명령은 다음을 추가합니다.
- `{ actionType: 'RESET_BOARD' }`
- `{ actionType: 'APPLY_OBJ_STATE', obj: <objState> }`
- `{ actionType: 'STAND_OUT', obj: { left, top, width, height, scale? } }`의 영역 돋보기 처리

## 수용 기준
- `releaseScriptUrl`이 없는 hotline 유닛에서 `scriptId: 0`인 `reload` guide를 받으면 `scriptMaker`를 호출하지 않고 `makeTemporaryScript`를 호출하며, 처리 뒤 로딩 표시가 없고 WebView가 남아 있습니다.
- 위 reload 처리 중 어느 시점에도 로딩 표시로 바뀌지 않습니다.
- `currentScript`에 URL이 없어도 패널의 `releaseScriptUrl` 상태에 실제 URL이 있는 hotline 유닛의 reload는 그 URL에 `?ts=`를 붙여 `scriptMaker`를 호출합니다.
- URL이 있는 스크립트의 hotline, topic reload에서 `scriptMaker`가 reject하거나 `null`을 돌려주면 로딩 표시가 나타나지 않고, 기존 WebView와 재생 상태가 유지되며, `RESET_BOARD`가 전송되지 않고, `syncPoint`가 쓰이지 않고, 처리되지 않은 rejection이 없습니다.
- URL이 없는 topic reload는 `scriptMaker`를 호출하지 않고 `RESET_BOARD`를 보내지 않으며 WebView를 유지합니다.
- URL이 있는 스크립트의 hotline, topic reload가 성공하면 `RESET_BOARD`가 전송되고 guide의 `studyIdx`, `step`까지 다시 재생됩니다. `mode: 'reload'`가 step으로 쓰이지 않습니다.
- reload 로딩 중 다른 스크립트로 전환되면 늦게 도착한 결과가 `menuScript`, `studySequences`, `syncPoint`, 보드에 반영되지 않습니다.
- reload를 연속 두 번 받으면 마지막 요청의 결과만 반영됩니다.
- `RESET_BOARD` 처리 중 `contentMeta: 'SAVE'` 메시지가 발생하지 않고, `backgroundSubs`의 객체는 남습니다.
- `cleanMessy` guide를 받으면 `CLEAN_ADHOCS`가 전송되고, 템플릿의 `removeFlyingObjs`는 `fly:`와 `magnifier:` 객체를 모두 지웁니다.
- `snapshot` guide를 받으면 스크립트 유무와 관계없이 `SAVE`가 한 번 전송됩니다.
- `canvas-synch` guide의 `objects`에 있는 기존 객체의 `left`, `top`, `scaleX`, `scaleY`는 각 값에 `classScale`을 곱한 값으로 바뀌고 객체 수는 늘지 않습니다.
- `canvas-synch` guide의 `objects`에 없던 객체는 추가되고, guide에 없는 기존 객체는 지워지지 않으며, 기존 `magnifier:`, `temporary:` 객체는 갱신되지 않습니다.
- `objState`가 있는 `select` guide는 `APPLY_OBJ_STATE`를 전송합니다.
- `objState`가 있는 `magnify` guide는 `APPLY_OBJ_STATE`를 먼저, `STAND_OUT`을 그다음에 전송합니다.
- `objState`가 없는 `select`, `magnify` guide는 `APPLY_OBJ_STATE`를 전송하지 않습니다.
- `applyObjectState`는 `opacity`, `src`, `width`, `height`를 바꾸지 않고, 없는 id의 `APPLY_OBJ_STATE`는 오류를 내지 않습니다.
- `magnifyArea` guide를 받으면 `STAND_OUT`이 `obj`와 함께 전송되고, 템플릿은 `objId`가 없고 영역 값이 있는 경우 `magnifyArea`를 호출합니다.
- 영역 돋보기의 표시 범위는 `1280*classScale` × `1920*classScale`을 넘지 않고, 새 돋보기를 띄우면 `magnifier:` 객체는 하나만 남습니다.
- `REMOVE_OBJ`로 `magnifier:` id를 받으면 학생 쪽 id와 달라도 표시 중인 돋보기가 지워집니다.
- `src/kit/canvas/note-canvas/live-script-id.ts`와 `dropEmptyScriptId` 사용 여부는 이 변경으로 달라지지 않습니다.
- 기존 테스트와 새 테스트가 모두 통과하고, `tsc`와 lint에 새 오류가 없습니다.

## 가정
- 코멘트의 "스펙 5는 무시"는 `dropEmptyScriptId` 적용만 제외하는 뜻으로 보고, 같은 항목의 `objState` 적용은 코멘트의 목적이므로 유지합니다.
- 구현 기준 브랜치에 `dropEmptyScriptId`가 있을 수도 없을 수도 있으므로 어느 쪽에서도 동작하게 reload를 패널에서 직접 처리합니다.
- `scriptId: 0`이고 정규화되지 않는 `magnify`, `magnifyArea`, `cleanMessy`, `adhoc` guide가 공용 처리기에서 걸러지는 기존 한계는 이번 범위에서 고치지 않습니다.
- 임시 기본 스크립트는 hotline에서 `releaseScriptUrl`이 없을 때 `makeTemporaryScript`로 만드는 스크립트로 봅니다.
- topic의 defaultScript는 서버가 `releaseScriptUrl`을 제공하므로 일반 URL 경로로 다시 불러옵니다.
- reload는 보드를 현재 진행 지점까지 다시 재생하는 동작으로 보고, reload 전에 받은 Flying Object와 학생 필기는 복원하지 않습니다. Flying Object는 선생님이 canvas 동기화를 누르면 복원됩니다.
- `opacity`는 선생님 쪽 애니메이션 중간값이 전달될 수 있어 동기화하지 않습니다.
- flying 객체 id는 tutor-web 캔버스가 만드는 `fly:<timestamp>` 형식입니다.
- 진행 중인 `magnifyObj` 애니메이션과 겹쳐 들어온 상태 적용의 경합은 별도로 처리하지 않습니다.
