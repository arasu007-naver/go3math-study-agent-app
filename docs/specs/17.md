## 배경과 목적
프로젝트 안의 컴포넌트 이름을 하나로 정해 두면 단축키처럼 쓸 수 있습니다. 사람이 프롬프트에서 이름만 말해도 task agent가 해당 파일을 바로 찾게 하는 것이 목적입니다. student-app(학생 사용자 앱, Expo Router, /Users/jaesung/QoollaWorkspace/go3math-study-agent-app)의 공용 컴포넌트를 `컴포넌트명: 파일경로` 형식의 용어집으로 정리합니다.

## 범위
### 하는 것
- 저장소 루트에 `docs/COMPONENTS.md`를 새로 만듭니다.
- 다음을 뽑아 정리합니다.
  - 네비게이터(`src/app/**/_layout.tsx`)
  - 화면(`src/app/` 아래 라우트 파일)
  - `src/app/` 밖의 공용 컴포넌트
  - 훅
  - 상태/컨텍스트
  - API 클라이언트
  - 공용 유틸
  - 테마/상수
- 기존 `AGENTS.md` 끝에 `## 컴포넌트 용어집` 절을 추가합니다.

### 하지 않는 것
- 코드 변경은 하지 않습니다.
- 기존 AGENTS.md 규칙 문구는 수정하지 않습니다.
- node_modules, .expo, ios/android 빌드 산출물은 넣지 않습니다.

## 변경할 동작
1. 맨 위에 사용법 단락을 두고, 범주별 절로 나눕니다: 네비게이터 / 화면 / 공용 컴포넌트 / 훅 / 상태 / API / 유틸 / 테마·상수.
2. 항목 형식은 `- **컴포넌트명**: \`상대경로\``입니다. 선택으로 별칭과 한 줄 설명을 붙입니다.
3. 이름 규칙
   - 화면 항목은 라우트 경로(예: `/study/[id]`)를 설명으로 적습니다.
   - 화면 항목의 이름은 export된 컴포넌트명을 씁니다. 이름 없는 default export라면 라우트 기반의 PascalCase 이름을 정해 적습니다.

- `docs/COMPONENTS.md`가 있고, 모든 항목이 `- **이름**: \`경로\`` 형식이다.
- 적힌 경로는 모두 실제로 존재한다.
- 이름과 별칭이 중복되지 않는다.
- `src/app/` 아래의 모든 `_layout.tsx`가 실려 있다.
- `src/app/` 아래의 모든 화면 파일이 라우트 경로와 함께 실려 있다.
- 두 곳 이상에서 import되는 공용 컴포넌트가 모두 실려 있다.
- node_modules, .expo, ios, android 빌드 산출물 경로가 없다.
- `AGENTS.md`에 용어집 참조와 갱신 규칙이 있다.
- 위 두 파일 외의 파일은 바뀌지 않았다.
