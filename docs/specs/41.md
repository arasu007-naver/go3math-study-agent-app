# 마지막 수업 메시지가 quiz/imageQuiz여도 스크립트 컷 위치로 동기화하기

## 배경과 목적
이 변경은 두 화면에 적용합니다.
- **HotlineClassScreen** (`app/hotline-class.tsx`, 패널 **HotlineClassCanvas** `src/kit/canvas/note-canvas/hotline-class-canvas.tsx`)
- **TopicLiveClassScreen** (`app/topic-live-class.tsx`, 패널 **TopicLiveCanvas** `src/kit/canvas/note-canvas/topic-live-canvas.tsx`)

두 화면은 수업 진입 때와 '필기 따라가기'(syncBoard) 때 마지막 메시지 guide를 그대로 패널 `onReceiveGuide`에 넘깁니다. 마지막 메시지는 `lastOnlineClassMessage` / `lastLiveTopicMessage`로 받습니다.

선생님이 마지막으로 보낸 것이 퀴즈이면 guide의 action이 `quiz` / `imageQuiz`입니다. 이때 캔버스는 다음처럼 동작합니다.
- `imageQuiz`: 스크립트가 이미 열려 있으면 퀴즈 모달만 띄우고 return 합니다.
- `quiz`: 같은 스크립트이면 `onQuizReceived` 후 return 합니다.

그래서 guide 안의 scriptId / studyIdx / rawCutIdx / step이 재생에 쓰이지 않습니다. 동기화 때마다 퀴즈 모달만 다시 뜨고 캔버스 컷 재생은 맞춰지지 않습니다.

graphql-server도 퀴즈가 마지막 메시지 키를 덮어쓰지 않게 고쳐집니다. 이 스펙은 이미 Redis에 저장된 데이터와 서버 배포 순서에 상관없이 앱이 진행 위치로 동기화하게 하는 방어 처리입니다.

## 범위
### 하는 것
- 두 화면의 마지막 메시지 처리(`callGetLastMessage` / `callGetLastTopicMessage`)에서, 받은 guide의 action이 `quiz` 또는 `imageQuiz`이면 위치 guide로 바꿔 넘깁니다.
- 변환 함수는 공용 위치 한 곳에 둡니다. 예: `src/kit/live-class/toPositionGuide.ts`. 두 화면이 같이 씁니다.

### 하지 않는 것
- 구독(`newOnlineClassMessage` / `liveTopicClassMessage`)으로 실시간 받은 quiz/imageQuiz 처리는 바꾸지 않습니다. 지금처럼 퀴즈 모달만 띄우고 패널로 넘기지 않습니다.
- 캔버스 `onReceiveGuide`의 기존 분기는 바꾸지 않습니다. imageQuiz, CLASS_ON_AIR, scriptId 전환 분기가 여기에 해당합니다.
- qoolla-package(`handleLiveClassMessage`, `playToPoint`)는 바꾸지 않습니다.
- student-web, tutor-web은 바꾸지 않습니다.

## 변경할 동작
1. `toPositionGuide(guide)`
   - action이 `quiz`/`imageQuiz`가 아니면 guide를 그대로 돌려줍니다.
   - 맞으면 새 객체를 돌려줍니다. 원본에서 `quiz`, `quizId`, `imageUrl`, `conceptId`를 뺍니다. `action`은 `'refresh'`로 바꿉니다.
   - 나머지 필드는 값 그대로 보존합니다: scriptId, studyIdx, rawCutIdx, step, mode, sourceType, sourceId, tutorId / topicId, releaseScriptUrl 등.
2. HotlineClassScreen `callGetLastMessage`는 파싱한 guide에 `toPositionGuide`를 적용한 결과를 쓰고, 그 뒤 기존 규칙을 그대로 따릅니다.
   - `setLiveState('live')`
   - 패널이 있으면 `onReceiveGuide`, 없으면 storage `syncPoint`
3. TopicLiveClassScreen `callGetLastTopicMessage`도 같습니다.
4. 그 결과 캔버스는 위치 guide를 받습니다.
   - 스크립트가 다르면 기존 전환 경로를 탑니다: syncPoint 저장 → 로드 후 `playToPointInternal`.
   - 같으면 `handleLiveClassMessage`의 refresh 경로로 `playToPoint`를 탑니다.
   - 어느 쪽이든 guide의 studyIdx/step까지 재생됩니다.

## API 계약
수신 경로는 기존과 같습니다.
- `lastOnlineClassMessage(tutorId)`, `lastLiveTopicMessage(topicId)`
- `newOnlineClassMessage(tutorId)`, `liveTopicClassMessage(topicId)`

guide JSON은 다음과 같습니다.
```json
{ "tutorId": "<hotline>", "topicId": 0, "scriptId": 123, "studyIdx": 3, "rawCutIdx": 17, "action": "step|refresh|quiz|imageQuiz|...", "step": "prologue|main|epilogue", "mode": "...", "sourceType": "...", "sourceId": 456, "quiz": "<quiz일 때>", "quizId": 9, "imageUrl": "<imageQuiz일 때>", "conceptId": 1 }
```

서버(graphql-server) 변경 후에는 마지막 메시지 content의 action이 quiz/imageQuiz가 아닙니다. 퀴즈는 Redis `online-class:<tutorId>:quiz` / `topic-live:<topicId>:quiz`에 따로 저장되고 구독으로만 전달됩니다.

## 수용 기준
- `toPositionGuide`의 퀴즈 변환
  - 입력: `{action:'imageQuiz', scriptId:12, studyIdx:3, rawCutIdx:17, step:'epilogue', sourceType:'A', sourceId:5, quiz:'Q', quizId:9, imageUrl:'u', conceptId:1}`
  - 결과: `{action:'refresh', scriptId:12, studyIdx:3, rawCutIdx:17, step:'epilogue', sourceType:'A', sourceId:5}`. quiz/quizId/imageUrl/conceptId 키는 없습니다.
- `toPositionGuide`에 `action:'quiz'` guide를 넣어도 같은 규칙으로 변환됩니다.
- `toPositionGuide`에 `action:'step'` guide를 넣으면 같은 내용의 guide가 그대로 나옵니다.
- HotlineClassScreen에서 `LAST_ONLINE_CLASS_MESSAGE`가 `action:'imageQuiz', scriptId:12, studyIdx:3, step:'main'` guide를 돌려주는 경우:
  - 패널 `onReceiveGuide`(또는 storage `syncPoint`)로 action 'refresh', scriptId 12, studyIdx 3, step 'main'인 guide가 전달됩니다.
  - QuizResponseModal은 열리지 않습니다.
- TopicLiveClassScreen에서 `LAST_LIVE_TOPIC_MESSAGE`가 `action:'quiz'` guide를 돌려주면 위와 같은 위치 guide가 패널 또는 syncPoint로 전달되고, 퀴즈 모달은 열리지 않습니다.
- HotlineClassCanvas에서 currentScriptId 12와 studySequences가 준비된 상태로 위 변환 guide를 `onReceiveGuide`에 넘기면, `handleLiveClassMessage`를 거쳐 `playToPoint`가 studyIdx 3, step 'main' 대상으로 호출됩니다. 퀴즈 처리로 return 하지 않습니다.
- TopicLiveCanvas에서도 같은 조건으로 같은 결과가 나옵니다.
- 구독으로 실시간 quiz/imageQuiz를 받을 때의 동작은 기존과 같습니다. 퀴즈 모달이 뜨고 패널 `onReceiveGuide`는 불리지 않습니다.
- 기존 테스트가 모두 통과합니다. 예: `__tests__/imageQuizGuide.test.ts`, `__tests__/classOnAirCanvas.test.ts`, `__tests__/liveClassWaiting.test.tsx`.
- 위 변환과 동기화를 검증하는 테스트가 추가되어 통과합니다.
- `tsc`에 새 오류가 없습니다.

## 가정
- 마지막 메시지가 퀴즈일 때 다시 퀴즈 모달을 띄우지 않고 진행 위치 동기화만 합니다. 늦게 들어온 학생에게 퀴즈를 다시 띄우는 일은 범위 밖으로 봅니다.
- 변환 guide의 action은 qoolla-package `handleLiveClassMessage`의 기본 재생 경로를 타는 `'refresh'`로 둡니다.
- 새 공용 파일을 만들면 docs/COMPONENTS.md에 이름과 경로를 추가합니다.
