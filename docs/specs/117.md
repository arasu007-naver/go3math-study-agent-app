# 실황 수업 학습장에 Quiz·조회 내용 영역 추가 (student-app)

## 배경과 목적
실황 캔버스(**HotlineClassCanvas** `src/kit/canvas/note-canvas/hotline-class-canvas.tsx`, **TopicLiveCanvas** `src/kit/canvas/note-canvas/topic-live-canvas.tsx`)를 나갈 때 `useSolveFinished`가 **StudyNoteActivity**(`src/kit/study-note/activity.ts`)에 조회 개념과 받은 퀴즈 id를 남기고 **StudyNoteForm**(`src/kit/study-note/StudyNoteForm.tsx`)을 엽니다.

지금 양식은 퀴즈를 `수업 퀴즈 N개`로만 보여 주고, 조회 개념은 메모 추천 칩으로만 보여 줍니다. 실황 학습장 양식 아래에 받은 퀴즈의 내용과 조회한 개념 제목을 표시합니다.

모달 문구는 tutor-web이 `guide.quiz`에 새 문구를 넣어 보내며, **QuizResponseModal**(`src/kit/live-class/QuizResponseModal.tsx`)은 이미 `quiz.content`를 그대로 표시하므로 모달 코드는 바꾸지 않습니다.

## 범위
### 하는 것
- `mode === 'live'`인 StudyNoteForm에 읽기 전용 `Quiz`, `조회 내용` 영역 추가
- 퀴즈 본문은 기존 `GET /api/study-notes/{taskId}/activities`의 `QUIZ_SENT`에서 조회
- `src/host/widgets.tsx`의 StudyNoteWidget에서 live일 때 조회 함수 전달

### 하지 않는 것
- `Activities` 저장 형식 변경(`{v, concepts, quizIds}` 유지)
- 학습장 시트를 여는 조건 변경
- 자습(`self`) 모드 양식, 추천 칩, QuizResponseModal 변경
- 서버 API 변경

## 변경할 동작
1. StudyNoteForm props에 선택 항목을 추가합니다.
   `fetchSentQuizzes?: (taskId: number) => Promise<{ quizId: number; content: string }[]>`
2. StudyNoteWidget은 `mode === 'live'`일 때 `createStudyLogFetchers().listActivities(taskId)`(`src/adapters/studyLogFetchers.ts`)로 이 함수를 구현해 넘깁니다. `type === 'QUIZ_SENT'`이고 `quizId`와 `content`가 있는 항목만 남기고, 같은 `quizId`는 처음 하나만 씁니다.
3. 양식은 live이고 `activities.quizIds`가 있을 때 열리면서 한 번 조회합니다. 조회 실패는 저장과 입력을 막지 않습니다.
4. 메모 입력과 `다음 목표` 분기 아래, 오류 문구와 버튼 위에 다음 순서로 표시합니다.
   - `Quiz` (testID `study-note-quiz-section`): `activities.quizIds` 순서로 한 항목씩 표시합니다. 조회 결과에 본문이 있으면 `cleanMathText(content)`, 없으면 `Quiz #{id}`를 표시합니다. 기존 `수업 퀴즈 N개` 문구는 이 영역 안으로 옮깁니다. `quizIds`가 비면 영역을 표시하지 않습니다.
   - `조회 내용` (testID `study-note-concepts-section`): `activities.concepts` 순서로 `cleanMathText(title)`을 표시합니다. 개념이 없으면 영역을 표시하지 않습니다.
5. 두 영역은 누를 수 없는 표시 전용입니다. 저장 payload의 `activities`는 변경 전과 같습니다.
6. 조회한 퀴즈는 `activities.quizIds`에 있는 것만 표시합니다. 같은 수업에서 이 학생이 받지 못한 퀴즈는 나오지 않습니다.

## API 계약
기존 API를 그대로 사용합니다.

`GET /api/study-notes/{taskId}/activities`
```json
{ "activities": [ { "id": 31, "type": "QUIZ_SENT", "createdAt": "2026-11-19T10:02:00", "quizId": 1011, "content": "등차수열의 일반항입니다. 중요한 부분을 표시하시오", "imageUrl": "https://...", "quizType": "IMAGE", "imageSourceType": "MATH_CONCEPT", "imageSourceId": 12 } ] }
```

imageQuiz guide의 `quiz`:
`${개념 제목}입니다. 중요한 부분을 표시하시오`

## 수용 기준
1. `quiz: '등차수열입니다. 중요한 부분을 표시하시오'`인 imageQuiz를 받으면 QuizResponseModal 문구 영역에 그 문장이 표시된다.
2. live 양식에 `quizIds: [1011]`이 있고 조회 결과에 1011의 본문이 있으면 `study-note-quiz-section` 안에 `Quiz` 제목과 그 본문이 보인다.
3. 조회가 실패하거나 해당 본문이 없으면 그 항목은 `Quiz #1011`로 보이고, 저장 버튼은 정상 동작한다.
4. 조회 결과에 `quizIds`에 없는 퀴즈가 있어도 표시되지 않는다.
5. 같은 `quizId`의 `QUIZ_SENT`가 여러 개 있어도 한 번만 표시된다.
6. live 양식에 `concepts: [{id:1,title:'일반항'}]`이 있으면 `study-note-concepts-section` 안에 `조회 내용` 제목과 `일반항`이 보인다.
7. 개념 제목의 HTML 엔티티와 수식 표기는 `cleanMathText`로 정리되어 표시된다.
8. `quizIds`가 비면 Quiz 영역이, `concepts`가 비면 조회 내용 영역이 렌더링되지 않는다.
9. `mode: 'self'`에서는 두 영역이 렌더링되지 않고 `fetchSentQuizzes`가 호출되지 않는다.
10. 저장 시 `activities` JSON은 `{v:1, concepts, quizIds}` 형식으로 변경 전과 같다.
11. 기존 추천 칩은 그대로 보이고 누르면 메모에 추가된다.
12. `npx tsc --noEmit`과 jest가 통과한다. 같은 제목이 칩과 새 영역에 함께 있어 기존 `getByText`가 실패하는 테스트는 `within`으로 범위를 좁히는 수정만 허용한다.

## 가정
- 시트를 여는 조건은 유지하므로, 퀴즈를 받기만 하고 다른 학습 행동이 없으면 학습장이 열리지 않습니다.
- 로컬 기록에는 퀴즈 id만 있으므로 본문은 기존 활동 API에서 가져옵니다.
- `Quiz`와 `조회 내용`은 실황(`live`) 양식에만 표시합니다.
- 퀴즈 본문은 시트 안 WebView를 늘리지 않도록 `cleanMathText`를 거친 텍스트로 표시합니다.
