# Script canvas play scale (cScale): fit the 1280×1920 script inside the canvas

## Background and purpose
A script (the class board recorded in tutor-web) is drawn in a **1280×1920** coordinate system. Today's code works like this:
- In **CanvasSize** (`src/kit/canvas/canvasSize.ts`), `canvasContextSize(screen)` always returns the context as `{ width: 1280, height: round(screen.height × 1280 / screen.width) }` (spec 60).
- **TopicLiveCanvas** (`src/kit/canvas/note-canvas/topic-live-canvas.tsx`) and **HotlineClassCanvas** (`src/kit/canvas/note-canvas/hotline-class-canvas.tsx`) build their HTML with `liveClassCanvasTemplate(contextSize.width, contextSize.height, color, pencilWidth, screenSize.width, screenSize.height)`.
- In `src/kit/canvas/templates/live-class-canvas-template.ts`, `var classScale = ${width}/1280;` fits the scale to width only, so it is always 1.
- Script play (ADD/MODIFY, PROLOGUE/FOLLOW/EPILOGUE, sync/group/prep members, FLY, SYNCH, ON_ANIMATION move, BACKGROUND/INIT_BACKGROUND background placement) multiplies left/top/scaleX/scaleY by `classScale`.

Tablet canvas screens are often wider than 2:3 (for example 788×1170 → context 1280×1900). Their context height is under 1920, so the bottom of the script is cut off. The goal: on any canvas size, the whole 1280×1920 script shows in proportion.

Rule (requirement):
1. cScale = canvas height / 1920 (fit to height).
2. If 1280 × cScale ≤ canvas width, use that cScale.
3. If 1280 × cScale > canvas width, use cScale = canvas width / 1280 (fit to width).
→ This is the same as `cScale = min(canvasHeight/1920, canvasWidth/1280)`. Use this cScale for every play that follows.

## Scope
### In scope
- Add a pure function to CanvasSize (`src/kit/canvas/canvasSize.ts`) that computes the script play scale.
- Set `classScale` in the live template (`src/kit/canvas/templates/live-class-canvas-template.ts`) to this function's result. TopicLiveCanvas and HotlineClassCanvas both use this template, so both pick up the change.
- Keep the size of the snapshot images (SNAPSHOT, CLEAN_BOARD) at the 1280-width basis.
- Update the existing tests (`__tests__/liveClassCanvasTemplate.test.ts` and others) and add new tests.

### Out of scope
- No change to the context and screen size calculation (`canvasContextSize`, `canvasScreenSize`) or the WebView and frame layout.
- No change to `boardScale` (the student's own tools: line, circle, image and so on), the pen and eraser, or the Notebook background (`changeNotebookBackgroundImage`, `notebookBackgroundScale`).
- No change to Notebook (`whiteboard-canvas-template.ts`), TopicNotebook (`topic-canvas-template.ts`, which no route uses) or `canvas-template-base.ts`.
- No change to tutor-web, the server, or the script and cut data format.
- The leftover space (the right margin when width is larger) is not centered. The origin (0,0) stays at the top-left.

## Behavior changes
1. **CanvasSize (`src/kit/canvas/canvasSize.ts`)**
   - Add `export function scriptPlayScale(canvas: Size): number`.
     - `const s = canvas.height / BOARD_HEIGHT;` (BOARD_HEIGHT = 1920)
     - `return BOARD_WIDTH * s <= canvas.width ? s : canvas.width / BOARD_WIDTH;` (BOARD_WIDTH = 1280)
   - Change the BOARD_HEIGHT comment from 'reference only' to 'height of the script coordinate system (used for the play scale)'.
2. **Live template (`src/kit/canvas/templates/live-class-canvas-template.ts`)**
   - Change `var classScale = ${width}/1280;` to `var classScale = ${scriptPlayScale({ width, height })};`. Here width and height are the canvas context size, and the numeric result goes straight into the template. Add a comment: '// script play scale (cScale): fit the 1280×1920 script inside the canvas (height basis, width basis if width overflows)'.
   - Every script play path that already uses classScale (exeObjMovingAnimation, showPrologues, enlivenPaatternedRect, syncCanvasObjects, addObjToCanvas, showSyncMembers, showEpilogues, importObjectFromClipboard, and the 10*classScale and instanceScale = 810/1280*classScale in changeBackgroundImage/changeFeedbackBackgroundImage) uses the new value without further changes. If a play path places script coordinates without classScale, apply classScale there too.
   - Leave `boardScale = ${width}/1280` and the student tool code as they are.
   - Change the `toDataURL` multiplier in `uploadSnapshot` and `resetCanvas` from `1/classScale` to `1280/canvasWidth`. The result image stays 1280 wide and does not grow too large when classScale < 1. Comment: '// 폭 1280 기준으로 맞춘다' (fit to the 1280 width) stays.
3. TopicLiveCanvas and HotlineClassCanvas keep calling the template as they do now (contextSize first, then screenSize). The scale ratio is the same in context and CSS coordinates, so the scale is computed from the context size.

## API contract
None.

## Acceptance criteria
- `scriptPlayScale({ width: 1280, height: 1920 })` returns 1.
- `scriptPlayScale({ width: 1280, height: 1900 })` returns `1900/1920`, which is less than 1.
- `scriptPlayScale({ width: 1280, height: 2560 })` returns 1 (1280×(2560/1920) > 1280, so it switches to the width basis 1280/1280).
- `scriptPlayScale({ width: 788, height: 1170 })` returns `1170/1920`.
- `scriptPlayScale({ width: 600, height: 1200 })` returns `600/1280`.
- For any positive size `{ w, h }`, `scriptPlayScale` returns `Math.min(h/1920, w/1280)`, and `1280 × result ≤ w` and `1920 × result ≤ h` both hold (allowing for floating-point error).
- The HTML from `liveClassCanvasTemplate(1280, 1900, 'orange', 6, 788, 1170)` contains `var classScale = ${1900/1920};` (the number written into the template).
- The HTML from `liveClassCanvasTemplate(1280, 2560, 'orange', 6)` contains `var classScale = 1;`.
- The live template's HTML contains no `var classScale = 1280/1280` or `classScale = <number>/1280` expression, and no `1920/classScale`.
- In the live template HTML, the `uploadSnapshot` and `resetCanvas` bodies contain `multiplier: 1280/canvasWidth` and do not contain `multiplier: 1/classScale`.
- The live template HTML still contains `var boardScale = <width>/1280`, `enableRetinaScaling: false` and a `setDimensions({ width: '788px', height: '1170px' }, { cssOnly: true })` call (when a CSS size is given).
- In the live template HTML, the bodies of `addObjToCanvas`, `showSyncMembers`, `syncCanvasObjects`, `importObjectFromClipboard` and `showEpilogues` all still contain `* classScale`.
- When TopicLiveCanvas and HotlineClassCanvas are rendered with window 800×1280 and insets top 24, bottom 0, the WebView html's `classScale` value equals `scriptPlayScale(canvasContextSize(canvasScreenSize({width:800,height:1280},{top:24,bottom:0})))`.
- The existing tests (`__tests__/liveClassCanvasTemplate.test.ts`, `__tests__/canvasSize.test.ts`, `__tests__/canvasLayout.test.tsx`, `__tests__/classOnAirEntryReplay.test.tsx`, `__tests__/liveClassResetOrder.test.ts` and others) are updated to the new rules and all pass, and `tsc` and lint report no new errors.

## Assumptions
- The 'canvas width/height' in the requirement is taken to be the canvas context size (width 1280, height round(screen height × 1280 / screen width)). It has the same ratio as the CSS screen size, so the fit result is the same.
- 'Script play' is taken to be the TopicLiveCanvas and HotlineClassCanvas screens that use the live template, and the background image placement is included in cScale.
- 'Tablet mode' is not split out as a separate branch. The same rule applies to every live canvas, and on phone-like tall screens the result is the same as now (1).
