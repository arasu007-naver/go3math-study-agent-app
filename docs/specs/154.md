# 학습장 입력 양식: Bottom Sheet → 모달 전환

## 배경과 목적
학습장 입력 양식 **StudyNoteForm**(`src/kit/study-note/StudyNoteForm.tsx`)은 지금 **SheetHost**(`src/host/SheetHost.tsx`)가 `@gorhom/bottom-sheet`의 `BottomSheetModal`(backdrop 없음, `enableDynamicSizing`, 최대 높이 90%, `keyboardBehavior="interactive"`)로 띄웁니다. 양식 안은 `BottomSheetScrollView`와 `BottomSheetTextInput`입니다. 메모를 쓸 때 키보드와 시트 때문에 텍스트 입력창이 가려져서 입력한 내용을 보기 어렵습니다. 그래서 양식을 화면 가운데 뜨는 카드 모달로 바꾸고, 키보드가 떠 있을 때도 입력 중인 칸이 키보드 위에 보이게 합니다.

## 범위
### 하는 것
- **SheetHost**(`src/host/SheetHost.tsx`)가 `BottomSheetModal` 대신 RN `Modal` 기반 공용 **Sheet**(`src/ui/Sheet.tsx`, scrim과 가운데 카드, `KeyboardAvoidingView` 포함)를 써서 학습장 위젯을 띄운다.
- **StudyNoteForm**에서 `@gorhom/bottom-sheet` 의존을 없앤다. `BottomSheetScrollView`는 RN `ScrollView`로, `BottomSheetTextInput`은 RN `TextInput`으로 바꾼다.
- 카드 크기 규칙(폭, 최대 높이)과 키보드 회피를 정한다.
- 바뀐 동작에 맞춰 `__tests__/sheetHost.test.tsx`, `__tests__/studyNoteForm.test.tsx`의 gorhom mock과 Bottom Sheet 전용 단언을 고친다.
- **StudyNoteForm**의 머리 주석(키보드 회피 담당 설명)과 **SheetHost** 주석을 새 구조에 맞게 고친다.

### 하지 않는 것
- 양식의 항목, 문구, 저장 로직, 초안·활동 기록 처리, 조회 흐름은 바꾸지 않는다.
- 에이전트 세션의 sheet 슬롯, `commandRouter`, registry의 `placement: 'sheet'`, 이벤트 이름(`study_note_saved`, `study_note_dismissed`)은 바꾸지 않는다.
- **StudyNoteWidget**(`src/host/widgets.tsx`)의 finish 로직(같은 taskId에서 한 번만 emit, closeSheet 한 번)은 바꾸지 않는다.
- 다른 Bottom Sheet(`app/notebook.tsx`, `app/topic-live-class.tsx`, `app/hotline-class.tsx`, **PhoneStudySheets**, **CanvasStudySheet** 등)와 `BottomSheetModalProvider`(`app/_layout.tsx`), **SheetHandle**(`src/ui/SheetHandle.tsx`)는 건드리지 않는다. `@gorhom/bottom-sheet` 패키지도 제거하지 않는다.
- 공용 **Sheet**/**Dialog**의 기존 동작은 바꾸지 않는다. 필요하면 선택 prop만 더한다.

## 변경할 동작
1. **표시 방식**
   - 세션 `state.sheet`에 `sheetWidgets`에 있는 componentId(현재 `study_note`)가 들어오면, SheetHost가 `Sheet`(RN `Modal`, `transparent`, `animationType="fade"`)를 `visible=true`로 렌더한다. 화면 전체에는 scrim(`colors.scrim`)을 깔고, 가운데 카드 안에 위젯을 그린다.
   - 카드 폭은 `Math.min(창 폭 - layout.gutter*2, 560)`이다. 폰과 태블릿 모두 가운데 정렬한다. 기존 태블릿 카드 최대 폭 `TABLET_CARD_MAX_W = 560`을 그대로 쓴다.
   - 카드 최대 높이는 창 높이의 90%이다. 내용이 짧으면 내용 높이만큼만 차지하고, 넘치면 양식 안의 `ScrollView`가 스크롤한다.
   - 카드 배경은 `colors.card`이고 모서리는 `radius.lg`이다. 카드 위쪽의 드래그 핸들(SheetHandle)은 그리지 않는다.
2. **키보드**
   - 카드는 `Sheet`의 `KeyboardAvoidingView`로 키보드를 피한다. 키보드가 올라오면 카드의 사용 가능 높이가 키보드 위 영역으로 줄어들고, 그 안에서 양식이 스크롤된다. 그래서 포커스된 메모·다음 목표 입력칸이 키보드에 가려지지 않는다.
   - 이 동작을 위해 카드의 최대 높이를 "키보드를 뺀 가용 높이의 90%"로 계산한다. `Keyboard` 이벤트나 `useWindowDimensions`, `KeyboardAvoidingView` 안의 flex 제약 중 어떤 방법으로 맞출지는 구현자가 고른다.
   - 양식 `ScrollView`는 `keyboardShouldPersistTaps="handled"`를 유지한다. 칩이나 저장 버튼을 누를 때 키보드 때문에 첫 탭이 먹히지 않게 하기 위해서다.
   - 입력 중인 `TextInput`이 보이는 영역 밖에 있으면 스크롤해서 보이게 한다. iOS는 `automaticallyAdjustKeyboardInsets`, Android는 `KeyboardAvoidingView`와 스크롤처럼 플랫폼에 맞는 방법을 쓴다.
3. **닫기**
   - 다음 세 경우에는 위젯의 `dismissRef`를 불러 `study_note_dismissed`를 한 번 내보내고 `session.closeSheet()`를 부른다.
     - scrim(접근성 라벨 "닫기")을 누를 때
     - Android 뒤로 가기(`Modal`의 `onRequestClose`)를 할 때
     - "나중에" 버튼을 누를 때(지금처럼 onDone('dismissed'))
   - 기존 `BackHandler` 직접 구독은 `Modal`의 `onRequestClose`로 대신한다. 모달이 떠 있지 않을 때는 뒤로 가기를 가로채지 않는다.
   - 끌어 내려서 닫는 제스처는 없앤다.
   - 저장 성공 시에는 지금처럼 `study_note_saved`를 한 번 내보내고 closeSheet를 부른다. 세션이 sheet를 비우면 모달이 `visible=false`가 되고, 이때는 이벤트를 더 내보내지 않는다.
   - 세션이 sheet를 비워서 닫는 경우(위젯이 끝내지 않음)에는 아무 이벤트도 내보내지 않는다.
4. **다시 열기·taskId 변경**
   - sheet가 null에서 값으로 바뀌어 다시 열릴 때마다 위젯을 새로 마운트한다(기존 `generation` 증가와 같은 의미). 그래서 같은 taskId로 저장한 뒤 다시 열어도 다시 저장하거나 닫을 수 있다.
   - 열린 채로 taskId만 바뀌면 모달은 그대로 두고 양식만 새 taskId로 다시 마운트한다(**StudyNoteWidget**의 `key={taskId}`).
   - 닫히는 페이드 애니메이션 중에 세션이 새 sheet를 열면, 새 sheet 내용으로 모달이 다시 보이고 이전 위젯의 이벤트는 나가지 않는다.
5. **StudyNoteForm**
   - 루트를 RN `ScrollView`로 바꾼다(`contentContainerStyle={styles.root}`, `keyboardShouldPersistTaps="handled"`).
   - 메모와 다음 목표 입력을 RN `TextInput`으로 바꾼다. props(accessibilityLabel, multiline, maxLength, value, onChangeText, textAlignVertical, style)는 그대로 둔다.
   - 파일에서 `@gorhom/bottom-sheet` import를 없앤다.
   - 이 파일과 SheetHost 모두 `@gorhom/bottom-sheet`를 import하지 않는다.

## API 계약
없음.

## 수용 기준
- `src/host/SheetHost.tsx`와 `src/kit/study-note/StudyNoteForm.tsx`에 `@gorhom/bottom-sheet` import가 없다.
- 세션 snapshot의 sheet가 `{ componentId: 'study_note', props: { taskId: 7, mode: 'self', title: '21번' } }`이면 RN `Modal`이 `visible=true`로 렌더되고, 그 안에 "학습장 · 21번" 텍스트가 보인다.
- sheet가 null이면 "학습장" 텍스트가 화면에 없고, 표시된(visible=true) 모달도 없다.
- 학습장 모달이 열려 있을 때 접근성 라벨 "닫기"인 scrim이 있다. 이것을 누르면 `session.emit('study_note_dismissed', { taskId: 7 })`가 정확히 한 번 불리고, `session.closeSheet`도 정확히 한 번 불린다.
- 모달의 `onRequestClose`(Android 뒤로 가기)를 두 번 불러도 `study_note_dismissed`는 한 번만 나가고 closeSheet도 한 번만 불린다.
- "거의" 칩을 누르고 "저장"을 누르면 `study_note_saved`가 `{ taskId: 7 }`로 한 번 나가고 closeSheet가 한 번 불린다. 그 뒤 sheet를 null로 바꿔도 이벤트가 더 나가지 않는다.
- 위젯이 끝내지 않은 상태에서 sheet를 null로 바꾸면 emit과 closeSheet가 한 번도 불리지 않는다.
- 열린 상태에서 taskId를 7에서 8로 바꾸면 fetchNote가 8로 불린다. 이어서 저장하면 `study_note_saved`가 `{ taskId: 8 }`로 한 번 나간다.
- taskId 7로 저장해 닫은 뒤 다시 taskId 7 sheet가 열리고 "나중에"를 누르면, 두 번째 이벤트 `study_note_dismissed`가 `{ taskId: 7 }`로 나간다(emit은 모두 2회).
- sheet가 null이 된 직후 새 sheet `{ taskId: 8, title: 'u' }`가 들어오면 "학습장 · u"가 보이고 이전 위젯의 이벤트는 나가지 않는다.
- 저장이 끝나기 전에 scrim을 누르면 emit은 한 번만 일어나고 값은 `study_note_dismissed`이다.
- 학습장 카드는 `KeyboardAvoidingView`(testID `sheet-keyboard-avoider` 또는 이와 같은 역할의 요소) 안에 렌더된다.
- 카드 폭은 `Math.min(창 폭 - 24, 560)` 이하이고, 카드 최대 높이는 창 높이의 90% 이하이다.
- 메모 입력(접근성 라벨 "공부한 내용" 또는 "한 줄 메모 (선택)")은 RN `TextInput`이다. 글자를 입력하면 값이 바뀌고 초안이 저장된다. 기존 studyNoteForm 테스트의 입력·저장 시나리오가 모두 통과한다.
- 양식의 스크롤 컨테이너는 `keyboardShouldPersistTaps="handled"`를 가진다.
- 학습장 모달 카드 위에 SheetHandle(드래그 핸들)이 렌더되지 않는다.
- `npx tsc --noEmit`과 `npx jest` 전체가 통과한다.
- `app/notebook.tsx` 등 다른 Bottom Sheet 사용처와 `app/_layout.tsx`의 `BottomSheetModalProvider`는 바뀌지 않았다.

## 가정
- "modal"을 공용 **Sheet**(`src/ui/Sheet.tsx`, RN Modal + scrim + 가운데 카드) 형태로 해석했다. 앱의 다른 모달(Dialog, QuizResponseModal)과 같은 형태다.
- scrim 탭과 Android 뒤로 가기는 "나중에"와 같은 닫기(study_note_dismissed)로 처리한다. 입력 내용은 초안으로 남으므로 잃지 않는다.
- 카드 최대 폭은 기존 태블릿 시트 폭 560을, 최대 높이는 기존 시트 상한 90%를 그대로 쓴다.
- 기존 Gate B Q5(backdrop 없는 Bottom Sheet, 아래 화면 터치 통과) 결정은 이 요구사항으로 대체된다. 모달이 떠 있는 동안 아래 화면은 터치할 수 없다.
