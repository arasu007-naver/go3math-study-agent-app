# Canvas screen context 1280 width basis and removal of vertical whitespace

## Background and purpose
The tutor-web live board and the app's live class canvas must use the same coordinate system so that the background image (the problem, UNIT) and the script objects feel like they sit in the same place. The app's canvas screens are portrait-locked. The requirement:
- canvas context width = **1280**, always.
- canvas context height = canvas screen height × (1280 / canvas screen width). It is not fixed at 1920.
- canvas screen height = screen height − top system bar height − bottom tool group area height.

Code review shows the following behavior today:
1. **TopicLiveCanvas** (`src/kit/canvas/note-canvas/topic-live-canvas.tsx`) and **HotlineClassCanvas** (`src/kit/canvas/note-canvas/hotline-class-canvas.tsx`) build the template with `live-class-canvas-template.ts` from the frame's onLayout size (`width`, `height - 12`). The context is in CSS px (about 800 px), not 1280, and `classScale = height/1920` is height-based.
2. **TopicLiveClassScreen** (`app/topic-live-class.tsx`) and **HotlineClassScreen** (`app/hotline-class.tsx`) wrap everything in a `SafeAreaView` that covers every edge. Inside it, **ScreenWrapper** (`src/kit/canvas/note-canvas/screen-wrapper.tsx`, FullScreenWrapper, default edges `['top','left','right']`) applies the top inset a second time. The result is a doubled top margin.
3. ScreenWrapper's `wrapper` style has `justifyContent: 'center', alignItems: 'center'`, so the canvas can end up vertically centered.
4. **CanvasStyles** `frame` (`src/kit/canvas/note-canvas/canvasStyles.ts`) has `padding: 3`. The live and hotline WebView is a fixed `height - 96` and does not match the frame height.
5. In **CanvasSize** (`src/kit/canvas/canvasSize.ts`), `canvasContextSize` fixes the height at 1920 when the screen is at least as wide as the 1280:1920 ratio, so the width can differ from 1280. This affects the **Notebook** (`src/kit/canvas/note-canvas/notebook.tsx`) screen.
6. In the HTML templates, only `html, body { margin: 0 }` is set. The canvas element is inline, which leaves a baseline gap, and nothing resets the padding or margin of fabric's `.canvas-container` wrapper.

The goal: every canvas screen uses as much vertical space as possible, and the canvas origin (0,0) sits right below the top system bar.

## Scope
### In scope
- Change the context calculation in CanvasSize (`src/kit/canvas/canvasSize.ts`) to a fixed 1280 width.
- Make TopicLiveCanvas and HotlineClassCanvas compute screen and context sizes with the same `canvasScreenSize`/`canvasContextSize` that Notebook uses, and fit the canvas to the screen size with CSS scaling only.
- Change the live template (`src/kit/canvas/templates/live-class-canvas-template.ts`) to take a CSS size, and base the coordinate scale on 1280 width.
- Remove vertical padding and margin from the canvas element, the canvas container (fabric `.canvas-container`, plus html/body) and the WebView with its wrapping View.
- Remove the doubled top inset and the vertical centering.
- Apply this to every canvas screen in the app: TopicLiveClassScreen (`app/topic-live-class.tsx`), HotlineClassScreen (`app/hotline-class.tsx`) and NotebookScreen (`app/notebook.tsx`).
- Update existing tests (`__tests__/canvasSize.test.ts` and others) to the new rules.

### Out of scope
- No changes to tutor-web or other projects, or to the script and cut data format.
- No change to the horizontal margin (`layout.canvasMargin` = 6, left and right).
- No change to the look or position of the FloatingToolbar, CanvasChrome or CanvasStudySheet.
- No change to TopicNotebook (`src/kit/canvas/note-canvas/topic-notebook.tsx`), which no route uses.
- No changes to non-canvas WebViews (popup and memo QoollaWebView).

## Behavior changes
1. **Context size (CanvasSize, `src/kit/canvas/canvasSize.ts`)**
   - `canvasContextSize(screen)` always returns `{ width: 1280, height: Math.round(screen.height * 1280 / screen.width) }`. Remove the branch that fixes the height at 1920. `BOARD_WIDTH = 1280` stays; `BOARD_HEIGHT` may stay for reference only.
   - `canvasScreenSize(window, insets)` keeps its current definition: width = window.width − canvasMargin×2, height = window.height − (insets.top + layout.toolbarH + insets.bottom). Update the comments to match.
2. **TopicLiveCanvas and HotlineClassCanvas**
   - Take `useSafeAreaInsets()` and compute `screenSize = canvasScreenSize({width, height}, insets)` and `contextSize = canvasContextSize(screenSize)`, as Notebook does.
   - Remove the onLayout-based `canvasDimensions` state and the `height - 96` / `width - 6` hard-coding. Build the template as `liveClassCanvasTemplate(contextSize.width, contextSize.height, pencilColor, pencilWidth, screenSize.width, screenSize.height)`. Memoize so it rebuilds only when the size changes.
   - The frame View holding the canvas has `{ width: screenSize.width, height: screenSize.height, flex: 0, padding: 0, paddingVertical: 0, marginVertical: 0, marginHorizontal: layout.canvasMargin }`.
   - WebView style: `{ width: screenSize.width, height: screenSize.height, padding: 0, margin: 0, backgroundColor: 'transparent' or white }`. Vertical padding and margin are 0.
   - Use `<FullScreenWrapper edges={[]}>` (or `['left','right']`) so the top inset is not applied again, and set the frame's vertical alignment to the top (`justifyContent: 'flex-start'`). The top edge of the canvas frame must equal the screen's safe-area top inset.
   - The loading View (`canvasStyles.loading`) uses the same size and padding 0.
3. **ScreenWrapper (`src/kit/canvas/note-canvas/screen-wrapper.tsx`)**: change `wrapper` to `justifyContent: 'flex-start'`, keep `alignItems: 'center'`, keep padding/margin at 0, and leave the `edges` prop as is. (The canvas screens' callers pass the edges from step 2.)
4. **CanvasStyles (`src/kit/canvas/note-canvas/canvasStyles.ts`)**: change `frame` and `loading` padding from 3 to 0 and update the comment.
5. **Live template (`src/kit/canvas/templates/live-class-canvas-template.ts`)**
   - New signature: `(width, height, pencilColor, pencilWidth, cssWidth = width, cssHeight = height)`.
   - When `cssWidth/cssHeight` differ from the context, use `new fabric.Canvas('canvas', { enableRetinaScaling: false })` and `canvas.setDimensions({ width: cssWidth+'px', height: cssHeight+'px' }, { cssOnly: true })`, the same way as the whiteboard template (`whiteboard-canvas-template.ts`).
   - Change `classScale` from `${height}/1920` to `${width}/1280` (1280 width basis, 1 when width = 1280). All placement and scale math that uses classScale (background top/left 10*classScale, instanceScale = 810/1280*classScale, ADD/SYNCH/FLY and so on) follows this value.
   - Keep the result size of `uploadSnapshot`/`resetCanvas` at a 1280-wide basis with `multiplier: 1/classScale`, and update the comment from 'height 1920 basis' to '1280 width basis'.
6. **Vertical whitespace removal in every canvas HTML template** (`live-class-canvas-template.ts`, `whiteboard-canvas-template.ts`, `canvas-template-base.ts`)
   - Include the following CSS in the `<style>`:
     `html, body { margin: 0; padding: 0; overflow: hidden; }`
     `canvas { display: block; margin: 0; padding: 0; }`
     `.canvas-container { margin: 0 !important; padding: 0 !important; }`
   - The canvas element has no vertical padding or margin, and the canvas sits at the top-left (0,0) of the document.
7. **Notebook (`src/kit/canvas/note-canvas/notebook.tsx`)**: the structure stays. Because of the context change in step 1 it now always gets a 1280-wide context. Add `padding: 0, margin: 0` explicitly to the WebView style, and make sure the outer Views and the frame have vertical padding and margin of 0.
8. **Screens**: in TopicLiveClassScreen, HotlineClassScreen and NotebookScreen, the root `SafeAreaView` keeps its current edges, so the top and bottom insets are applied once each. Its children (the panel) must add no vertical padding or margin of their own.

## API contract
None.

## Acceptance criteria
- `canvasContextSize({ width: 1018, height: 1270 })` returns `{ width: 1280, height: Math.round(1270 * 1280 / 1018) }`.
- `canvasContextSize({ width: 640, height: 960 })` returns `{ width: 1280, height: 1920 }`.
- `canvasContextSize({ width: 600, height: 1200 })` returns `{ width: 1280, height: 2560 }`.
- For any positive screen size, the `width` returned by `canvasContextSize` is always 1280 and `height` is `Math.round(screen.height * 1280 / screen.width)`.
- `canvasScreenSize({ width: 1024, height: 1366 }, { top: 24, bottom: 20 })` returns `{ width: 1024 - 12, height: 1366 - 24 - layout.toolbarH - 20 }`.
- The HTML from `liveClassCanvasTemplate(1280, 1900, 'orange', 6, 788, 1170)` contains `<canvas id='canvas' width='1280' height='1900'`, `var classScale = 1280/1280`, `enableRetinaScaling: false`, and a `setDimensions` call with `788px` and `1170px` plus `cssOnly: true`.
- The HTML from `liveClassCanvasTemplate(1280, 1900, 'orange', 6)` (no CSS size given) has `enableRetinaScaling: true`, or omits that option, and has no `setDimensions` call.
- The HTML from `liveClassCanvasTemplate`, `classCanvasTemplate` (whiteboard) and `buildCanvasTemplate` all contain the `html, body` margin:0 and padding:0 rules, the `canvas` display:block, margin:0 and padding:0 rules, and the `.canvas-container` margin:0 and padding:0 rules.
- The live template's HTML has no `classScale = <height>/1920` expression.
- When TopicLiveCanvas is rendered with window 800×1280 and insets top 24, bottom 0, the canvas WebView style is width `800 - 12` and height `1280 - 24 - layout.toolbarH`, with vertical padding and margin 0 or unset, and the HTML in the source has a canvas element `width='1280'`.
- Under the same conditions HotlineClassCanvas shows the same WebView size and canvas context width 1280.
- When Notebook is rendered with window 800×1280 and insets top 24, bottom 0, the WebView html has `width='1280'` and `height` equal to `Math.round((1280 - 24 - layout.toolbarH) * 1280 / (800 - 12))`.
- In TopicLiveCanvas, HotlineClassCanvas and Notebook, the View holding the canvas WebView (the frame) and its parent Views have `padding`, `paddingTop`, `paddingBottom`, `paddingVertical`, `margin`, `marginTop`, `marginBottom` and `marginVertical` all at 0 or unset.
- TopicLiveCanvas and HotlineClassCanvas do not apply the top safe-area inset a second time inside the panel: the `edges` passed to FullScreenWrapper contains no `'top'`.
- ScreenWrapper's `wrapper` style has `justifyContent` set to `'flex-start'`.
- `canvasStyles.frame.padding` and `canvasStyles.loading.padding` are 0.
- The existing tests (`__tests__/canvasSize.test.ts`, `__tests__/liveClassCanvasTemplate.test.ts`, `__tests__/classOnAirCanvas*.test.*` and others) are updated to the new rules and all pass, and `tsc`/lint report no new errors.

## Assumptions
- The 'bottom tool group area height' is taken to be the FloatingToolbar height `layout.toolbarH` (52) plus the bottom safe-area inset, matching the existing `canvasScreenSize` definition.
- The 'canvas screen width' is taken to be the window width minus the left and right `layout.canvasMargin` (6 each); the horizontal margin stays.
- The tutor-web live board is assumed to place objects in a 1280-wide coordinate system, so the live template's `classScale` is set to the width basis `canvasWidth/1280` (= 1).
- The 'canvas container' in the requirement is taken to be both the `.canvas-container` div that fabric.js creates and html/body; the WebView vertical padding and margin are applied to the RN WebView style and the frame View around it.
- 'Every canvas screen in the app' is taken to be the three routed screens TopicLiveClassScreen, HotlineClassScreen and NotebookScreen; TopicNotebook, which no route uses, is left out.
