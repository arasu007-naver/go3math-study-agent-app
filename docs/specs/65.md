# 학습장 돌아보기에서 선생님 이미지 퀴즈의 이미지 보이기 (student-app)

## 배경과 목적
학습장 '돌아보기'(**StudyNoteReviewList** `src/kit/study-log/StudyNoteReviewList.tsx`)는 api-v3 `GET /api/study-notes/{taskId}/activities`를 **studyLogFetchers**(`src/adapters/studyLogFetchers.ts`)로 받아 기록을 보입니다. 지금 선생님 퀴즈(QUIZ_SENT)는 본문만 있고 이미지가 없습니다.

이번에 api-v3가 실황 수업 이미지 퀴즈의 QUIZ_SENT 항목에 다음을 실어 줍니다.
- `imageUrl`
- `quizType: "IMAGE"`
- 이미지 출처 유닛(`imageSourceType: "MATH_CONCEPT"`, `imageSourceId: 개념 id`)

학생 앱은 이 값을 받아 선생님 이미지 퀴즈의 이미지를 썸네일로 보이고, 눌러서 크게 보게 합니다.

## 범위
### 하는 것
- **StudyLogModel**(`src/kit/study-log/model.ts`)의 `ReviewActivity` 타입에 선택 필드 `quizType?: string | null`, `imageSourceType?: string | null`, `imageSourceId?: number | null`을 추가합니다.
- studyLogFetchers의 `listActivities`가 이 필드를 지우지 않고 그대로 넘기는지 확인합니다. 지금은 spread로 넘기므로 코드 변경이 없어도 되고, 테스트로 보장합니다.
- StudyNoteReviewList에서 QUIZ_SENT 항목에 `imageUrl`이 있으면 다음처럼 보입니다.
  - 기존 풀이·답안과 같은 썸네일을 보이고, 누르면 기존 ImageViewer로 크게 봅니다.
  - `quizType === 'IMAGE'`이면 종류 라벨을 '선생님 이미지 퀴즈'로 보입니다.

### 하지 않는 것
- 실황 수업 화면(TopicLiveCanvas / HotlineClassCanvas)의 `imageQuiz` guide 처리와 **QuizResponseModal**은 바꾸지 않습니다. guide에 새로 붙는 `imageSourceType`/`imageSourceId`는 무시해도 됩니다.
- 학습장 activities(task_note.activities, `src/kit/study-note/activity.ts`) 저장 형식은 바꾸지 않습니다.
- 개념 출처로 개념 화면을 여는 이동 기능은 만들지 않습니다.

## 변경할 동작
1. `ReviewActivity` 타입에 위 세 선택 필드를 더합니다.
2. StudyNoteReviewList의 UploadList 항목
   - 라벨은 `a.type === 'QUIZ_SENT' && a.quizType === 'IMAGE'`이면 '선생님 이미지 퀴즈'이고, 아니면 기존 `KIND_LABEL[a.type]`입니다.
   - `a.imageUrl`이 있으면 type에 상관없이 썸네일을 보이고, 누르면 ImageViewer가 그 URL로 열립니다(지금 동작 유지). 썸네일의 접근성 라벨은 `${라벨} 크게 보기`입니다.
   - content가 있으면 지금처럼 본문을 3줄까지 보입니다.

## API 계약
`GET /api/study-notes/{taskId}/activities` (api-v3) 응답 `activities[]` 항목에 선택 필드가 더해집니다.
```json
{ "id": 31, "type": "QUIZ_SENT", "createdAt": "2026-11-19T10:02:00", "quizId": 1011, "content": "중요한 부분에 표시하시오", "imageUrl": "https://<storage>/math-files/images/concepts/12/<ts>.jpeg", "quizType": "IMAGE", "imageSourceType": "MATH_CONCEPT", "imageSourceId": 12 }
```
- 이미지가 없는 퀴즈와 다른 type 항목은 기존 키만 옵니다.

## 수용 기준
- `listActivities`가 위 JSON 항목을 받으면 돌려주는 ReviewActivity에 `imageUrl`, `quizType: 'IMAGE'`, `imageSourceType: 'MATH_CONCEPT'`, `imageSourceId: 12`가 그대로 들어 있습니다.
- StudyNoteReviewList에서 그 task를 펼치면 다음이 보입니다.
  - 라벨 '선생님 이미지 퀴즈'
  - 본문 '중요한 부분에 표시하시오'
  - 접근성 라벨이 '선생님 이미지 퀴즈 크게 보기'인 이미지 버튼
- 그 이미지 버튼을 누르면 ImageViewer 모달이 그 imageUrl로 열립니다.
- imageUrl과 quizType이 없는 QUIZ_SENT 항목은 라벨이 '선생님 퀴즈'이고, 이미지 버튼이 없습니다(변경 전과 같음).
- SOLUTION_UPLOAD와 QUIZ_ANSWER 항목의 라벨과 썸네일 표시는 변경 전과 같습니다.
- studyNoteReviewList.test.tsx, studyLogFetchers.test.ts를 포함한 기존 테스트와 새로 더한 테스트가 통과하고, 타입 검사가 새 오류 없이 통과합니다.

## 가정
- 요구사항의 'app에서 학습장 리뷰'는 student-app의 학습장 '돌아보기'(StudyNoteReviewList)로 보았습니다.
- 이미지 퀴즈 라벨 '선생님 이미지 퀴즈'는 기존 라벨 체계에 맞춰 정했습니다.
- 실황 수업 중 imageQuiz 수신은 이미 imageUrl로 동작하므로 이번 범위에서 바꾸지 않았습니다.
