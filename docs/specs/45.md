## 배경과 목적
학생 앱의 실황 수업 화면(TopicLiveClassScreen `app/topic-live-class.tsx`, hotline `app/hotline-class.tsx`)에 들어오면, lastLiveTopicMessage의 guide를 패널에 넘깁니다. 패널은 TopicLiveCanvas(`src/kit/canvas/note-canvas/topic-live-canvas.tsx`)와 HotlineClassCanvas(`src/kit/canvas/note-canvas/hotline-class-canvas.tsx`)입니다.

현재 코드를 확인한 결과입니다.
- 스크립트가 다르면 guide를 storage 'syncPoint'에 저장하고, menuScript 로드 뒤 `playToPointInternal(tPt)`를 fromPt 없이 호출합니다. 이 호출은 `playToPoint(studySequences, tPt, undefined, cb)`이고, lastGuide가 없으므로 인덱스 0부터 last cut idx까지 모든 컷을 순서대로 재생합니다. 이것이 요구사항이 말한 '처음부터 재생' 문제입니다.
- 같은 스크립트가 이미 열려 있을 때 초기 lastGuide `{studyIdx:0, step:'refresh'}`로 ctx.playToPoint가 호출되면 역시 0부터 재생합니다.
- `getPlayerCallbacks()`에 runCurtains가 없어, 리셋 컷 이전에 추가된 배경 유지 객체(연습장 등 backgroundSubs)를 복원할 수 없습니다.
- WebView 템플릿 `src/kit/canvas/templates/live-class-canvas-template.ts`의 `clearCanvas`는 60ms 뒤에 backgroundSubs가 아닌 객체를 지웁니다. 그래서 CLEAN 직후 지연 없이 ADD를 보내면 그 객체도 지워질 수 있습니다. 또 'CLEAR' 컷은 처리하지 않습니다.

## 범위
하는 것
- `@qoolla/script-parser` 의존성을 `github:arasu007-naver/qoolla-package#v1.5.0`으로 올립니다(현재 v1.3.1).
- TopicLiveCanvas와 HotlineClassCanvas의 진입 재생을 last cut idx 직전의 가장 가까운 리셋 컷(CLEAN/CLEAN_SCENE/CLEAR)부터로 바꿉니다(`fastforward` 사용).
- runCurtains 콜백을 추가해 연습장 등 배경 유지 객체를 복원합니다.
- 리셋 컷 직후 객체가 지워지는 경합을 막고, 템플릿이 CLEAR를 처리하게 합니다.

하지 않는 것
- 수업 중 실시간 진행(선생님이 다음 컷으로 넘길 때 lastGuide부터 순차 재생)은 바꾸지 않습니다.
- CLASS_ON_AIR로 같은 스크립트를 다시 시작할 때 0부터 재생하는 동작은 유지합니다.
- 'follow'(synchToCurrent), 'lastStep', 퀴즈, 스냅샷 동작은 바꾸지 않습니다.
- clearCanvas가 SAVE 스냅샷을 올리는 기존 부수효과는 바꾸지 않습니다.

## 변경할 동작
두 캔버스 파일에 똑같이 적용합니다.
1. import에 `fastforward`, `isResetCut`를 추가합니다(`./script-maker`가 패키지를 재export).
2. 진입 여부 플래그 `hasPlayedSinceLoadRef`(useRef)를 둡니다. `initClassBoard`나 `reloadScript`로 studySequences를 새로 세팅할 때 false로 초기화합니다. playToPoint, fastforward, runNext, runAt 중 하나라도 끝나면 true가 됩니다.
3. `playToPointInternal(targetPt, fromPt)`
   - `fromPt == null`이거나 `hasPlayedSinceLoadRef.current === false`이면 진입 재생입니다. backgroundCut을 보낸 뒤 `fastforward(studySequences, targetPt, callbacks)`를 호출합니다.
   - 그 밖에는 지금처럼 `playToPoint(studySequences, targetPt, fromPt, callbacks)`를 호출합니다.
   - syncPoint 재생(useEffect[menuScript], initBackground)과 ctx.playToPoint 모두 이 규칙을 따릅니다.
   - CLASS_ON_AIR 분기의 `playToPointInternal({studyIdx:0, step:'main'}, null)`은 fastforward로 가도 시작점이 0이므로 결과가 같습니다.
4. `getPlayerCallbacks()`에 `runCurtains: async (startIdx)`를 추가합니다. `menuScript.curtains`에서 `seq === startIdx`인 항목의 objs 각각에 대해, `menuScript.canvasBackStuffs[id]`가 있으면 `sendBoardAction({actionType:'ADD', obj})`를 보냅니다.
   - curtains 객체는 backgroundSubs이므로 뒤따르는 CLEAN의 clearCanvas에서 지워지지 않아야 합니다.
   - 지워진다면, 시작 리셋 컷 처리 뒤에 복원되도록 순서를 조정합니다.
5. `runCut`에서 `isResetCut(cut)`이면 sendBoardAction 뒤에 `await sleep(120)`을 합니다. 템플릿의 60ms 지연 정리가 끝난 뒤 다음 ADD가 그려지게 하기 위함입니다.
6. `live-class-canvas-template.ts` dispatchCanvasAction의 `case 'CLEAR_CANVAS': case 'CLEAN':`에 `case 'CLEAR':`와 `case 'CLEAN_SCENE':`를 추가해 clearCanvas()를 호출합니다. topic-canvas-template.ts의 같은 분기에도 'CLEAR'를 추가합니다.
7. 연습장 컷 점검: 연습장 컷은 연습지/유색 종이 이미지 ADD(ruled-paper, *-paper.jpg(e))이고, WHITE_PAPER 보드 액션은 학생 로컬 동작입니다. 진입 재생에서 다음을 보장합니다.
   - 시작 리셋 컷과 last cut idx 사이의 연습장 ADD는 표시되고, 직전 리셋 컷의 지연 정리로 지워지지 않습니다.
   - 시작 리셋 컷 이전의 연습장은 backgroundSubs일 때만 runCurtains로 표시됩니다.

## API 계약
`@qoolla/script-parser` v1.5.0
- `isResetCut(cut): boolean`: actionType(대소문자 무시)이 CLEAN, CLEAN_SCENE, CLEAR 중 하나이면 true입니다.
- `fastforward(cuts, targetGuide, callbacks)`: findNearestCleanBefore(cuts, studyIdx)부터 재생하고, 반복문 전에 `callbacks.runCurtains(startIdx)`를 한 번 호출합니다.
- `parseDocument` 결과의 `curtains[{seq, objs}]`와 `canvasBackStuffs[id]`, `refreshPoints`에 CLEAR가 반영됩니다.

서버 메시지 형식(lastLiveTopicMessage.content의 guide `{scriptId, sourceType, sourceId, studyIdx, step}`)은 바뀌지 않습니다.

## 수용 기준
- package.json의 `@qoolla/script-parser`가 `#v1.5.0`이고, `npx tsc --noEmit`과 기존 jest 테스트가 통과합니다.
- studySequences [BACKGROUND(0), ADD a(1), ADD b(2), CLEAN(3), ADD c(4), ADD d(5)]가 로드된 뒤 syncPoint {studyIdx:5, step:'main'}로 진입 재생하면 webview에 BACKGROUND, CLEAN(3), ADD c, ADD d가 보내지고 ADD a, ADD b는 보내지지 않습니다.
- 같은 조건에서 3번을 CLEAR로 바꿔도 ADD a, ADD b는 보내지지 않습니다. webview 템플릿은 'CLEAR'를 받으면 clearCanvas를 실행합니다.
- 스크립트가 이미 열려 있고 아직 재생 기록이 없을 때(hasPlayedSinceLoadRef=false) ctx.playToPoint로 {studyIdx:5}가 오면 같은 결과(3부터 재생)입니다.
- 진입 재생을 한 번 마친 뒤 선생님이 {studyIdx:6}으로 넘기면 지금처럼 playToPoint로 이전 지점 다음 컷만 재생하고, 처음이나 리셋 컷부터 다시 재생하지 않습니다.
- 리셋 컷이 없는 스크립트에서는 0부터 last cut idx까지 재생합니다.
- runCut이 리셋 컷을 보내면 다음 sendBoardAction까지 120ms 이상 기다립니다.
- 1번이 연습지 이미지이고 id가 backgroundSubs에 있으면, 진입 재생 때 runCurtains(3)가 그 객체를 ADD로 보냅니다. 재생 뒤 캔버스에 남습니다.
- 연습지 ADD가 4번이면 진입 재생 뒤 캔버스에 남습니다(CLEAN 지연 정리로 지워지지 않음).
- 1번이 연습지이고 backgroundSubs가 아니면 진입 재생 때 보내지지 않습니다.
- guide.step이 'refresh'이면 마지막 컷 main을 실행하지 않습니다(fastforward 기존 동작).
- HotlineClassCanvas에서도 위 항목들이 똑같이 성립합니다.

## 가정
- 진입 재생은 '스크립트 로드 뒤 첫 재생'으로 판정합니다.
- qoolla-package를 v1.3.1에서 v1.5.0으로 올려도 앱의 기존 사용처와 호환된다고 가정합니다.
- 연습장 컷은 연습지/유색 종이 이미지 ADD 컷으로 해석합니다.
