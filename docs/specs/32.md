# 실황 수업 진입 시: 진행 중이면 마지막 컷까지 재생, 수업 전이면 로고 애니메이션 + '수업 전입니다.' 대기

## 배경과 목적
실황 수업 dock(**LiveClassListPanel**: `src/kit/live-class/LiveClassListPanel.tsx`)에서 수업을 고르면 Stage에 문제 목록(**ProblemListPanel**: `src/kit/problem-list/ProblemListPanel.tsx`)이 뜹니다. 그 목록의 수강(풀이) 버튼을 누르면 `src/host/widgets.tsx`의 `openTopicLiveClass` / `openHotlineClass`가 캔버스 화면을 엽니다.
- 주제 실황 수업: **TopicLiveClassScreen** `app/topic-live-class.tsx` (패널 **TopicLiveCanvas** `src/kit/canvas/note-canvas/topic-live-canvas.tsx`)
- 선생님 수업: **HotlineClassScreen** `app/hotline-class.tsx` (패널 **HotlineClassCanvas** `src/kit/canvas/note-canvas/hotline-class-canvas.tsx`)

지금 동작:
- 화면이 문제(스크립트)를 받으면 `LAST_LIVE_TOPIC_MESSAGE`(`lastLiveTopicMessage(topicId)`) 또는 `LAST_ONLINE_CLASS_MESSAGE`(`lastOnlineClassMessage(tutorId)`)를 부릅니다.
- content를 guide로 파싱할 수 있으면 `panelRef.current.onReceiveGuide(guide)`를 부르거나 storage `syncPoint`에 넣습니다. 그러면 패널이 그 스크립트를 열고 컷까지 재생합니다(`playToPointInternal`).
- guide가 없으면 그냥 return 합니다. 패널은 `live-scripts`의 첫 스크립트를 열고 배경만 그린 빈 캔버스를 보입니다. 스크립트가 아직 없으면 `ActivityIndicator`만 계속 돕니다. 그래서 학생은 수업이 아직 시작하지 않았다는 것을 알 수 없습니다.

목적: last Live Message가 없으면, 수업 전이라는 것을 로고 애니메이션과 문구로 알립니다. live message 구독은 유지한 채 기다리다가, 진행 메시지가 처음 오면 바로 캔버스로 바꿔 그 컷까지 재생합니다.

## 범위
### 하는 것
- TopicLiveClassScreen과 HotlineClassScreen 두 화면에 '진행 확인 중(checking) / 진행 중(live) / 수업 전 대기(waiting)' 상태를 둡니다.
- waiting일 때 캔버스 영역 위에 대기 화면을 보입니다. 대기 화면에는 로고 애니메이션(**LoadingView**의 `Go3MathLoader`: `src/kit/ui/loading-view/index.tsx`), 그 바로 아래 문구 '수업 전입니다.', 그리고 나가기 버튼이 있습니다.
- waiting에서도 기존 live message 구독(`TOPIC_LIVE_MESSAGE_ADDED` / `ONLINE_TUTOR_CLASS_MESSAGE_ADDED`, **GraphqlSubscriptions** `src/api/graphql/subscriptions.ts`)을 유지합니다. 진행 메시지가 처음 오면 live로 바꾸고, 그 guide를 패널에 넘겨 해당 스크립트의 컷까지 재생합니다.

### 하지 않는 것
- 서버, GraphQL 스키마, 쿼리·구독 문서는 바꾸지 않습니다.
- last message가 있을 때의 재생 로직(`onReceiveGuide`, `playToPointInternal`, `syncPoint`)은 바꾸지 않습니다.
- 퀴즈 모달, 풀이 저장, task 생성, 툴바 버튼 구성(나가기/필기 따라가기/마지막 단계/목록/개념·해답)은 바꾸지 않습니다.
- LiveClassListPanel, ProblemListPanel, widgets.tsx의 화면 열기 흐름은 바꾸지 않습니다.
- 폰 레이아웃의 별도 흐름이나 노트북(`/notebook`) 화면은 다루지 않습니다.

## 변경할 동작
1. **상태 추가**: 두 화면에 `liveState: 'checking' | 'live' | 'waiting'`를 둡니다.
   - 화면이 focus될 때마다 `checking`으로 초기화합니다. 기존에 `syncPoint`를 지우고 문제를 다시 받는 effect 안에서 합니다.
2. **진입 판정** (기존 `callGetLastTopicMessage` / `callGetLastMessage`의 진입 호출 결과로 정함):
   - content를 guide로 파싱할 수 있으면(`safeJsonParse(...) != null`) `live`로 바꾸고, 기존처럼 guide를 패널에 넘기거나 `syncPoint`에 넣어 그 컷까지 재생합니다.
   - 응답이 null이거나 content가 비었거나 파싱할 수 없으면 `waiting`으로 바꿉니다.
   - HotlineClassScreen에서 수업 문제가 0개이면 last message 호출이 일어나지 않습니다. 이때도 `waiting`으로 바꿉니다.
   - HotlineClassScreen에서 last message 쿼리가 실패하면(지금은 경고 로그만 남김) `waiting`으로 둡니다.
   - TopicLiveClassScreen에서 쿼리가 실패하면 기존대로 `notReady()`(토스트 후 뒤로가기)를 유지합니다.
3. **'필기 따라가기'(sync) 버튼**: 같은 함수를 다시 부르는 경우입니다. 이미 `live`이면 결과가 비어도 `waiting`으로 되돌리지 않습니다. `waiting`일 때 결과가 있으면 `live`로 바꿉니다.
4. **대기 화면 렌더**: `liveState === 'waiting'`이면 SafeAreaView 안에서 패널 위를 덮는 전체 영역 View를 그립니다(absolute, 흰 바탕, 패널보다 위의 zIndex). 내용은 다음과 같습니다.
   - `testID="live-class-waiting"`
   - 가운데: `<Go3MathLoader />`. 반복 scale 애니메이션이고, 컨테이너가 flex:1을 차지하지 않게 style로 크기를 조정합니다.
   - 로고 바로 아래: `<Text>수업 전입니다.</Text>`
   - 나가기 버튼: 기존 `goBack`을 부르고 `accessibilityLabel="나가기"`를 붙입니다. 대기 화면이 하단 툴바를 가리므로 필요합니다.
   - 패널(TopicLiveClassCanvasPanel / HotlineClassCanvasPanel)은 언마운트하지 않고 대기 화면 아래에 그대로 둡니다. 그래야 live로 바뀔 때 바로 `onReceiveGuide`를 받을 수 있습니다.
   - `checking` 동안은 대기 화면을 보이지 않습니다. 기존 로딩 표시를 그대로 둡니다.
5. **구독 유지와 전환**: 구독의 `skip` 조건(`!isFocused || !topicId` / `!tutorId`)은 그대로 두므로 waiting에서도 구독합니다. `onData`에서 guide가 오면:
   - `action`이 `quiz` / `imageQuiz`: 기존대로 퀴즈 모달을 띄우고, 상태는 바꾸지 않습니다.
   - Hotline의 `action === 'units'`: 기존대로 `loadAgenda()`를 부르고, 상태는 바꾸지 않습니다. 다시 받은 문제로 last message를 다시 확인한 결과에 따라 2번 규칙대로 정해집니다.
   - `action === 'snapshot'`: 상태를 바꾸지 않습니다.
   - 그 밖의 guide: `waiting`이면 `live`로 바꾸고, 기존처럼 `panelRef.current?.onReceiveGuide(guide)`로 넘깁니다. 패널이 해당 스크립트의 컷까지 재생합니다. 이미 `live`이면 기존 동작과 같습니다.
6. 화면을 떠나거나 focus를 잃으면 기존처럼 패널을 내리고 구독을 멈춥니다. 다시 들어오면 1번부터 다시 판정합니다.
7. 두 화면에서 같은 대기 화면을 쓰도록 작은 공용 컴포넌트를 만들어도 됩니다(예: `src/kit/live-class/LiveClassWaiting.tsx`, props `{ onExit(): void }`). 새로 만들면 **docs/COMPONENTS.md**의 '공용 컴포넌트'에 `- **LiveClassWaiting**: \`src/kit/live-class/LiveClassWaiting.tsx\``를 추가합니다.

## API 계약
없음. 기존 GraphQL을 그대로 씁니다.
- 쿼리 `lastLiveTopicMessage(topicId: Int!) { id content createdAt sub topicId }`, `lastOnlineClassMessage(tutorId: String!) { id content sub tutorId }`
- 구독 `liveTopicClassMessage(topicId: Int!)`, `newOnlineClassMessage(tutorId: String!)`
- 'last Live Message 없음'은 응답 객체가 null이거나, content가 비었거나, content가 JSON으로 파싱되지 않는 경우로 판단합니다.

## 수용 기준
1. TopicLiveClassScreen에서 `STUDY_TOPIC`이 스크립트가 있는 unit을 돌려주고 `LAST_LIVE_TOPIC_MESSAGE`가 `{ lastLiveTopicMessage: null }`을 돌려주면, `testID="live-class-waiting"` 요소가 보이고 그 안에 '수업 전입니다.' 텍스트와 `accessibilityLabel="불러오는 중"`인 Go3MathLoader가 있다.
2. 1과 같은 조건에서 `lastLiveTopicMessage.content`가 빈 문자열이거나 JSON이 아닌 문자열이어도 대기 화면이 보인다.
3. TopicLiveClassScreen에서 `LAST_LIVE_TOPIC_MESSAGE`가 파싱 가능한 guide(예: `{"scriptId":12,"studyIdx":3,"step":"main"}`)를 돌려주면, 대기 화면이 보이지 않고 그 guide가 패널 `onReceiveGuide`에 전달되거나 storage `syncPoint`에 저장된다.
4. 대기 화면이 보이는 동안 `TOPIC_LIVE_MESSAGE_ADDED` 구독이 해당 topicId로 활성 상태이다(skip되지 않음).
5. 대기 화면에서 구독으로 `action`이 quiz/imageQuiz/snapshot이 아닌 guide(예: `{"scriptId":12,"studyIdx":0,"step":"main"}`)가 오면, 대기 화면이 사라지고 그 guide가 패널 `onReceiveGuide`로 전달된다.
6. 대기 화면에서 구독으로 `action: 'quiz'` guide가 오면 퀴즈 모달(QuizResponseModal)이 뜨고, 대기 화면은 그대로 남는다.
7. 대기 화면의 '나가기' 버튼을 누르면 `router.back()`이 불린다. 뒤로 갈 수 없으면 `router.replace('/')`가 불린다.
8. HotlineClassScreen에서 `ONLINE_CLASS_OF_TUTOR`가 unit을 돌려주고 `LAST_ONLINE_CLASS_MESSAGE`가 `{ lastOnlineClassMessage: null }`을 돌려주면, 대기 화면('수업 전입니다.' + Go3MathLoader)이 보이고 `ONLINE_TUTOR_CLASS_MESSAGE_ADDED` 구독은 활성 상태이다.
9. HotlineClassScreen에서 `ONLINE_CLASS_OF_TUTOR`의 units가 빈 배열이면 대기 화면이 보인다.
10. HotlineClassScreen에서 `LAST_ONLINE_CLASS_MESSAGE`가 파싱 가능한 guide를 돌려주면 대기 화면이 보이지 않고, 그 guide가 패널에 전달되거나 `syncPoint`에 저장된다.
11. HotlineClassScreen 대기 중에 구독으로 `action: 'units'`가 오면 `loadAgenda`(ONLINE_CLASS_OF_TUTOR 재조회)가 불리고, 그 메시지만으로 대기 화면이 사라지지는 않는다.
12. HotlineClassScreen 대기 중에 구독으로 progress guide가 오면 대기 화면이 사라지고, 그 guide가 패널 `onReceiveGuide`로 전달된다.
13. 이미 live인 상태에서 '필기 따라가기'를 눌러 last message 응답이 null이어도 대기 화면이 나타나지 않는다.
14. last message 응답이 오기 전(checking)에는 대기 화면이 보이지 않는다.
15. TopicLiveClassScreen에서 `LAST_LIVE_TOPIC_MESSAGE` 쿼리가 실패하면 기존처럼 '주제 실황 강의가 준비되지 않았습니다' 토스트가 뜬다.
16. 기존 테스트(`__tests__/liveClass.test.tsx`, `__tests__/hotlineRefreshMenuscript.test.ts`, `__tests__/liveScriptsCache.test.ts`, `__tests__/solveFinishedLive.test.tsx` 등)가 모두 통과하고, `tsc` 타입 검사에 새 오류가 없다.
17. 새 공용 컴포넌트 파일을 만들었다면 docs/COMPONENTS.md에 그 이름과 경로가 있다.

## 가정
- '실황 수업 Dock'의 수강 버튼은 주제 실황 수업과 선생님 수업 두 종류의 캔버스 진입을 모두 뜻한다고 보고, 두 화면에 함께 적용합니다.
- 'Logo Animation'은 앱에 이미 있는 Go3MathLoader(주황 Go3 Math 로고 scale 반복)를 씁니다.
- 'last Live Message가 없음'은 응답이 null이거나, content가 비었거나, 파싱되지 않는 경우로 봅니다.
- 대기 화면이 캔버스 툴바를 가리므로, 나가기 버튼을 대기 화면에 따로 둡니다.
- 대기에서 진행으로 바뀌는 신호는 quiz/imageQuiz/snapshot/units를 뺀 첫 구독 guide입니다.
- TopicLiveClassScreen의 last message 쿼리 실패 처리(notReady)는 그대로 두고, HotlineClassScreen의 실패는 대기 화면으로 처리합니다.
- 대기 중에도 패널은 아래에 마운트된 채로 둡니다.
