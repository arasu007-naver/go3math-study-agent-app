# 실황 수업 진입 재생을 리셋 컷부터로 바꾸기 (TopicLiveCanvas / HotlineClassCanvas)

## 배경과 목적
학생이 실황 수업 화면에 들어오면 `lastLiveTopicMessage`나 `lastOnlineClassMessage`의 guide가 패널로 넘어갑니다. 화면과 패널은 다음과 같습니다(docs/COMPONENTS.md 기준).
- 화면: **TopicLiveClassScreen** `app/topic-live-class.tsx`, **HotlineClassScreen** `app/hotline-class.tsx`
- 패널: **TopicLiveCanvas** `src/kit/canvas/note-canvas/topic-live-canvas.tsx`, **HotlineClassCanvas** `src/kit/canvas/note-canvas/hotline-class-canvas.tsx`

현재 코드에서 확인한 내용입니다.
- 스크립트가 다르면 guide를 storage `'syncPoint'`에 저장합니다. 그 뒤 `useEffect([menuScript])`나 `initBackground`가 `playToPointInternal(tPt)`를 fromPt 없이 호출합니다. 이 호출은 `playToPoint(studySequences, tPt, undefined, cb)`가 되는데, lastGuide가 없으므로 `lastPointIdx=0`입니다. 그래서 0번부터 목표 컷까지 모든 컷을 재생합니다.
- 같은 스크립트가 이미 열려 있으면 초기 `lastGuide`가 `{studyIdx:0, step:'refresh'}`입니다. 이 상태에서 `ctx.playToPoint`가 `playToPointInternal(tgt, lastGuide)`를 부르면 역시 0번부터 재생합니다.
- `getPlayerCallbacks()`에 `runCurtains`가 없습니다. 그래서 리셋 컷 이전에 추가된 배경 유지 객체(backgroundSubs, 예: 연습장)를 복원하지 못합니다.
- `src/kit/canvas/templates/live-class-canvas-template.ts`의 `clearCanvas`는 60ms 뒤에 backgroundSubs가 아닌 객체를 지웁니다. 그래서 CLEAN 직후 바로 보낸 ADD 객체도 지워질 수 있습니다. `dispatchCanvasAction`은 `'CLEAR'`와 `'CLEAN_SCENE'`를 처리하지 않습니다.
- 참고: 현재 설치된 `@qoolla/script-parser` v1.3.1에도 `fastforward`, `findNearestCleanBefore`, `ScriptPlayerCallbacks.runCurtains`가 있습니다. 하지만 `isResetCut`가 없고, `CLEAR`를 리셋 컷으로 보지 않습니다.

목적: 진입할 때 목표 컷 직전의 리셋 컷부터 재생해, 지워졌어야 할 이전 객체가 다시 그려지거나 처음부터 오래 재생되는 문제를 없앱니다.

## 범위
### 하는 것
- `package.json`의 `@qoolla/script-parser`를 `github:arasu007-naver/qoolla-package#v1.5.0`으로 올리고 `package-lock.json`을 갱신합니다.
- TopicLiveCanvas와 HotlineClassCanvas의 진입 재생을 `fastforward`로 바꿉니다. 재생은 목표 컷 직전의 가장 가까운 리셋 컷(CLEAN/CLEAN_SCENE/CLEAR, 패키지 규칙상 BACKGROUND 포함)부터 시작합니다.
- 두 캔버스에 `runCurtains` 콜백을 추가해 배경 유지 객체를 복원합니다.
- `runCut`이 리셋 컷을 보낸 뒤 120ms 기다립니다.
- `live-class-canvas-template.ts`가 `CLEAR`와 `CLEAN_SCENE`를, `topic-canvas-template.ts`가 `CLEAR`를 `clearCanvas()`로 처리합니다.

### 하지 않는 것
- 수업 중 실시간 진행(재생 기록이 있는 상태에서 선생님이 다음 컷으로 넘길 때 lastGuide부터 순차 재생)은 바꾸지 않습니다.
- CLASS_ON_AIR로 같은 스크립트를 다시 시작할 때 0부터 재생하는 동작을 유지합니다. `playToPointInternal({ studyIdx: 0, step: 'main' }, null)` 호출 문자열도 그대로 둡니다(기존 소스 검사 테스트가 있습니다).
- `'follow'`(synchToCurrent), `'lastStep'`(playLastStep), 퀴즈(`quiz`/`imageQuiz`), 스냅샷 동작은 바꾸지 않습니다.
- `clearCanvas`가 SAVE 스냅샷을 올리는 부수효과와 60ms 지연은 바꾸지 않습니다.
- 서버 메시지 형식, 화면(app/*.tsx)의 guide 전달 로직, `useScriptPlayer.ts`는 바꾸지 않습니다.

## 변경할 동작
두 캔버스 파일에 똑같이 적용합니다.

1. **import**: `./script-maker`(패키지를 `export *`로 재export합니다)에서 `fastforward`와 `isResetCut`를 추가로 가져옵니다.
2. **진입 여부 플래그**: `const hasPlayedSinceLoadRef = useRef(false)`를 둡니다.
   - `initClassBoard`와 `reloadScript`에서 `setStudySequences(...)`를 호출할 때 `false`로 되돌립니다.
   - `playToPoint`, `fastforward`, `runAt`(playLastStep), `runNext`(사용처가 있다면) 중 하나의 await가 끝나면 `true`로 설정합니다.
3. **playToPointInternal(targetPt, fromPt)**:
   - 기존처럼 `hideModal()`을 부르고, studySequences가 비었으면 return합니다.
   - `fromPt == null` 또는 `hasPlayedSinceLoadRef.current === false`이면 **진입 재생**입니다. `menuScript?.backgroundCut`이 있으면 보내고, `await fastforward(studySequences, targetPt, callbacks)`를 호출합니다.
   - 그 밖에는 지금처럼 `await playToPoint(studySequences, targetPt, fromPt, callbacks)`를 호출합니다.
   - 끝나면 `hasPlayedSinceLoadRef.current = true`로 두고, 기존의 `targetPt.objects` SYNCH 전송을 유지합니다.
   - syncPoint 재생(`useEffect([menuScript])`, `initBackground`)과 `ctx.playToPoint`가 모두 이 규칙을 따릅니다.
   - CLASS_ON_AIR 분기의 `playToPointInternal({studyIdx:0, step:'main'}, null)`도 fastforward로 갑니다. 시작점이 0이므로 결과는 같습니다.
   - **예외**: `synchToCurrent`(follow)는 동작을 바꾸지 않습니다. 그래서 진입 판정 없이 지금처럼 `playToPoint(lastGuide, startPoint)` 경로를 탑니다. 예를 들어 `playToPointInternal`에 세 번째 옵션 인자 `{ sequential: true }`를 넘겨 우회합니다.
4. **runCurtains**: `getPlayerCallbacks()`에 `runCurtains: async (startIdx) => { ... }`를 추가합니다.
   - `menuScript?.curtains`에서 `seq === startIdx`인 항목을 고릅니다. 각 항목의 `objs`(id 배열)를 돌면서 `menuScript.canvasBackStuffs?.[id]`가 있으면 `sendBoardAction({ actionType: 'ADD', obj: menuScript.canvasBackStuffs[id] })`를 보냅니다.
   - curtains나 canvasBackStuffs가 없으면 아무것도 보내지 않습니다.
   - curtain 객체는 backgroundSubs에 속하므로, 뒤이어 오는 시작 리셋 컷의 `clearCanvas`가 지우지 않아야 합니다. 템플릿에서 실제로 지워진다면(id가 backgroundSubs에 없는 경우 등) 순서를 바꿉니다. 이때는 시작 리셋 컷 처리와 120ms 대기 뒤에 curtain 객체를 ADD합니다.
5. **runCut**: `isResetCut(cut)`이 true이면 `sendBoardAction(cut)` 뒤에 `await sleep(120)`을 합니다. 템플릿의 60ms 지연 정리가 끝난 뒤에 다음 ADD가 그려지게 하려는 것입니다. 기존 POPUP/MEMO 처리와 FOLLOW(synchs) 처리는 그대로 둡니다.
6. **템플릿**:
   - `live-class-canvas-template.ts`의 `dispatchCanvasAction`에서 `case 'CLEAR_CANVAS':case 'CLEAN':`에 `case 'CLEAR':`와 `case 'CLEAN_SCENE':`를 추가합니다. 모두 `clearCanvas()`를 호출합니다.
   - `topic-canvas-template.ts`의 같은 분기에는 `case 'CLEAR':`를 추가합니다.
7. **연습장 컷**: 연습장 컷은 연습지나 유색 종이 이미지를 ADD하는 컷입니다(ruled-paper, `*-paper.jpg`/`*-paper.jpeg`). `WHITE_PAPER` 보드 액션은 학생 로컬 동작이므로 대상이 아닙니다. 진입 재생에서 다음을 보장합니다.
   - 시작 리셋 컷과 목표 컷 사이의 연습장 ADD는 표시되고, 앞선 리셋 컷의 지연 정리로 지워지지 않습니다(5번의 120ms 대기).
   - 시작 리셋 컷 이전의 연습장은 curtains/canvasBackStuffs(backgroundSubs)에 있을 때만 runCurtains로 표시됩니다.

## API 계약
다른 프로젝트와 주고받는 API는 없습니다. 사용하는 외부 패키지 계약(`@qoolla/script-parser` v1.5.0)은 다음과 같습니다.
- `isResetCut(cut): boolean`: actionType(대소문자 무시)이 CLEAN, CLEAN_SCENE, CLEAR 중 하나이면 true입니다.
- `fastforward(cuts, targetGuide, callbacks)`: `findNearestCleanBefore(cuts, studyIdx)`부터 재생합니다. 반복문 전에 `callbacks.runCurtains(startIdx)`를 한 번 호출합니다. `step==='refresh'`이면 마지막 컷 main을 실행하지 않습니다.
- `parseDocument` 결과의 `curtains: {seq, objs}[]`, `canvasBackStuffs: Record<id, obj>`, `refreshPoints`에 CLEAR가 반영됩니다.
- 서버 메시지 형식(`lastLiveTopicMessage.content`의 guide `{scriptId, sourceType, sourceId, studyIdx, step}`)은 바뀌지 않습니다.

## 수용 기준
1. `package.json`의 `@qoolla/script-parser`가 `github:arasu007-naver/qoolla-package#v1.5.0`입니다. `npx tsc --noEmit`과 기존 jest 테스트(`__tests__/classOnAirCanvas.test.ts`, `classOnAirCanvasBehavior.test.tsx`, `imageQuizGuide.test.ts`, `liveClassWaiting.test.tsx`, `positionGuideCanvas.test.ts` 포함)가 통과합니다.
2. TopicLiveCanvas에 studySequences `[BACKGROUND(0), ADD a(1), ADD b(2), CLEAN(3), ADD c(4), ADD d(5)]`를 로드한 뒤 syncPoint `{studyIdx:5, step:'main'}`로 진입 재생하면, webview에 BACKGROUND(backgroundCut), CLEAN(3), ADD c, ADD d가 이 순서로 보내집니다. ADD a와 ADD b는 보내지지 않습니다.
3. 2번 조건에서 3번 컷을 CLEAR로 바꿔도 ADD a와 ADD b는 보내지지 않습니다.
4. `live-class-canvas-template.ts`와 `topic-canvas-template.ts`의 `dispatchCanvasAction`이 `'CLEAR'`를 받으면 `clearCanvas()`를 실행합니다. `live-class-canvas-template.ts`는 `'CLEAN_SCENE'`를 받아도 `clearCanvas()`를 실행합니다.
5. 스크립트가 이미 열려 있고 로드 뒤 재생 기록이 없을 때(`hasPlayedSinceLoadRef.current === false`) `ctx.playToPoint`로 `{studyIdx:5, step:'main'}`가 오면 2번과 같은 결과(3번 컷부터 재생)가 나옵니다.
6. 진입 재생을 한 번 마친 뒤 `{studyIdx:6}`이 `ctx.playToPoint`로 오면 `playToPoint(studySequences, {studyIdx:6...}, lastGuide, cb)`가 호출됩니다. 이전 지점 이후의 컷만 재생하고, 0번이나 리셋 컷부터 다시 재생하지 않습니다.
7. 리셋 컷이 없는 스크립트(예: `[ADD(0), ADD(1), ADD(2)]`, 목표 2)에서는 0번부터 목표 컷까지 모두 재생합니다.
8. `runCut`이 CLEAN, CLEAN_SCENE 또는 CLEAR 컷을 보내면, 다음 `sendBoardAction`까지 120ms 이상 기다립니다(`sleep(120)` 호출 확인).
9. 1번 컷이 연습지 이미지이고 그 id가 curtains(seq=3)와 canvasBackStuffs에 있으면, 진입 재생 때 `runCurtains(3)`가 `{actionType:'ADD', obj: canvasBackStuffs[id]}`를 보냅니다. 재생이 끝난 뒤에도 그 객체가 캔버스에 남습니다.
10. 연습지 ADD가 4번 컷이면 진입 재생 뒤에도 캔버스에 남습니다. CLEAN(3)의 60ms 지연 정리로 지워지지 않습니다.
11. 1번 컷이 연습지이지만 curtains/backgroundSubs에 없으면 진입 재생 때 보내지지 않습니다.
12. 진입 guide의 step이 `'refresh'`이면 목표 컷의 main이 실행(전송)되지 않습니다.
13. CLASS_ON_AIR로 같은 스크립트가 다시 시작되면 backgroundCut 뒤에 cuts[0] main이 재생됩니다. 소스에 `playToPointInternal({ studyIdx: 0, step: 'main' }, null)`가 그대로 남아 있습니다.
14. `'follow'`, `'lastStep'`, `'quiz'`, `'imageQuiz'`, `'snapshot'` guide의 처리 결과(호출되는 함수와 보내는 보드 액션)는 변경 전과 같습니다.
15. HotlineClassCanvas에서도 2번부터 14번까지가 똑같이 성립합니다.

## 가정
- 진입 재생은 '스크립트 로드(initClassBoard/reloadScript) 뒤 첫 재생' 또는 fromPt가 없는 재생으로 판정합니다.
- `@qoolla/script-parser` v1.5.0 태그가 있고, 카드에 적힌 API(isResetCut, fastforward, curtains/canvasBackStuffs)를 제공하며, v1.3.1 사용처와 호환된다고 가정합니다.
- follow(synchToCurrent)는 바꾸지 않는 범위이므로 진입 판정에서 제외하고 기존 playToPoint 경로를 유지합니다.
- runCurtains는 `useScriptPlayer.ts`의 DEFAULT 액션 대신 카드에 적힌 ADD 액션으로 객체를 보냅니다.
