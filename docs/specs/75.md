## 배경과 목적
실황 수업 퀴즈 답안 모달은 QuizResponseModal(`src/kit/live-class/QuizResponseModal.tsx`)입니다. 이 모달은 TopicLiveClassScreen(`app/topic-live-class.tsx`)과 HotlineClassScreen(`app/hotline-class.tsx`)에서 뜹니다. 지금은 캔버스 화면의 펜 설정을 MMKV에서 그대로 읽습니다. 색은 `canvasStrokeColor`(기본 'orange'), 굵기는 `canvasStrokeWidth`(기본 6)입니다(199행).

캔버스 화면에서는 흰 펜이 지우개입니다. TopicLiveCanvas(`src/kit/canvas/note-canvas/topic-live-canvas.tsx`), HotlineClassCanvas(`src/kit/canvas/note-canvas/hotline-class-canvas.tsx`), Notebook(`src/kit/canvas/note-canvas/notebook.tsx`), TopicNotebook(`src/kit/canvas/note-canvas/topic-notebook.tsx`)에서 지우개 버튼을 누르면 다음이 일어납니다.
- `setCanvasStrokeWidth(eraserWidth(storage, canvasStrokeColor, canvasStrokeWidth))`가 실행되고, 색은 'white'가 됩니다.
- useEffect가 MMKV에 `canvasStrokeColor='white'`, `canvasStrokeWidth=72`를 저장합니다.
- CanvasUtils(`src/kit/canvas/note-canvas/canvas-utils.ts`)의 `eraserWidth`는 지우개 전 굵기만 `canvasStrokeWidthBeforeEraser`에 저장합니다. 지우개 전 색은 어디에도 저장하지 않습니다.

그래서 학생이 지우개를 고른 상태로 퀴즈가 오면, 모달은 흰 배경 위에 흰색 72px로 그립니다. 답안이 보이지 않고, 보이지 않는 답이 제출됩니다.

목적: 캔버스 화면의 펜이 지우개(흰색)일 때, 퀴즈 답안은 지우개를 풀면 돌아갈 펜의 색과 굵기로 그립니다.

## 범위
하는 것
- CanvasUtils의 `eraserWidth`가 지우개 전 굵기와 함께 지우개 전 색도 MMKV 키 `canvasStrokeColorBeforeEraser`에 저장합니다.
- CanvasUtils에 퀴즈 펜을 정하는 순수 함수 `quizPen(store)`를 추가합니다.
- QuizResponseModal이 `quizPen(storage)`의 결과로 캔버스 HTML의 펜 색과 굵기를 정합니다.
- 관련 jest 테스트를 추가하고 고칩니다.

하지 않는 것
- 퀴즈 모달 안에 지우개 기능이나 펜 선택 UI를 추가하지 않습니다.
- 캔버스 화면의 지우개 동작은 바꾸지 않습니다: 72px, 흰색, 지우개 커서, 색 버튼을 누르면 `inkWidth`로 굵기 복원.
- 캔버스 화면에서 지우개를 풀 때 색을 자동으로 되돌리지 않습니다. 사용자가 고른 색 버튼이 그대로 적용됩니다.
- 위 네 캔버스 파일의 지우개/색 버튼 코드 문자열은 바꾸지 않습니다. `__tests__/canvasEraser.test.ts`가 이 문자열을 검사합니다.
- 서버 API, 업로드, 제출 경로는 바꾸지 않습니다.

## 변경할 동작
### 1. CanvasUtils (`src/kit/canvas/note-canvas/canvas-utils.ts`)
1. 상수 `COLOR_BEFORE_ERASER = 'canvasStrokeColorBeforeEraser'`를 추가합니다.
2. 스토어 타입을 넓힙니다. 기존 `WidthStore`를 확장하거나 새 타입을 둡니다.
   - `set(k: string, v: number | string)`
   - `getNumber(k)`
   - `getString?(k)`
   - 기존 테스트의 memStore(숫자만 저장)도 타입 오류 없이 넘길 수 있어야 합니다. 필요하면 테스트의 memStore를 고칩니다.
3. `eraserWidth(store, color, width)`:
   - `color !== 'white'`이면 지금처럼 `WIDTH_BEFORE_ERASER`에 width를 저장합니다.
   - 같은 조건에서 color가 비어 있지 않은 문자열이면 `COLOR_BEFORE_ERASER`에도 color를 저장합니다.
   - 이미 지우개('white')면 두 값 모두 덮어쓰지 않습니다.
   - 반환값은 지금처럼 `ERASER_WIDTH`(72)입니다.
4. `export function quizPen(store: { getString(k): string|undefined; getNumber(k): number|undefined }): { color: string; width: number }`를 추가합니다.
   - `canvasStrokeColor`를 읽습니다. 없으면 'orange'입니다.
   - 색이 'white'가 아니면 `{ color, width: getNumber('canvasStrokeWidth') || 6 }`를 반환합니다. 기존 동작과 같습니다.
   - 색이 'white'이면 다음을 반환합니다.
     - color: `getString('canvasStrokeColorBeforeEraser')`. 이 값이 없거나 'white'이면 'orange'.
     - width: `getNumber('canvasStrokeWidthBeforeEraser') || 6`. 지우개 굵기 72는 쓰지 않습니다.

### 2. QuizResponseModal (`src/kit/live-class/QuizResponseModal.tsx`)
- `useMemo`의 html 생성을 바꿉니다. 지금의 `drawingCanvasHtml(storage.getString('canvasStrokeColor') || 'orange', storage.getNumber('canvasStrokeWidth') || 6)` 대신, `const pen = quizPen(storage)`를 구해 `drawingCanvasHtml(pen.color, pen.width)`를 씁니다. `quiz?.quizId`가 바뀔 때마다 다시 읽는 점은 그대로입니다.
- 41행 주석을 고칩니다: 지우개(흰색)면 지우개 전 색과 굵기를 쓴다는 내용을 넣습니다.
- 16행에서 `uploadQuizAnswerToStorage` import 뒤에 `Button` import가 같은 줄에 붙어 있습니다. 줄을 나눠 정리하면서 `quizPen`을 함께 import합니다.

### 3. 테스트
- `__tests__/canvasEraser.test.ts`에 `eraserWidth`의 색 저장과 `quizPen` 단위 테스트를 추가합니다.
- `__tests__/quizResponseModal.test.tsx`는 지금 canvas-utils를 `{ uploadQuizAnswerToStorage }`만 있는 객체로 mock합니다.
  - `quizPen`이 실제 구현으로 동작하도록 mock을 고칩니다. 예: `react-native-blob-util`과 `../src/api/rest`를 mock하고 `jest.requireActual`을 spread.
  - legacy storage mock이 `canvasStrokeColorBeforeEraser`와 `canvasStrokeWidthBeforeEraser`도 돌려줄 수 있게 합니다.

## 수용 기준
- `eraserWidth(store, 'blue', 9)`를 호출하면 72를 반환합니다. store에는 `canvasStrokeWidthBeforeEraser=9`와 `canvasStrokeColorBeforeEraser='blue'`가 저장됩니다.
- `eraserWidth(store, 'red', 4)` 뒤에 `eraserWidth(store, 'white', 72)`를 호출해도 store의 `canvasStrokeColorBeforeEraser`는 'red', `canvasStrokeWidthBeforeEraser`는 4로 남습니다.
- `eraserWidth(store, undefined, 6)`처럼 색이 없으면 `canvasStrokeColorBeforeEraser`를 저장하지 않고, 예외도 없습니다.
- `quizPen`에 `canvasStrokeColor='blue'`, `canvasStrokeWidth=10`인 store를 넣으면 `{color:'blue', width:10}`을 반환합니다.
- `quizPen`에 빈 store를 넣으면 `{color:'orange', width:6}`을 반환합니다.
- `quizPen`에 `canvasStrokeColor='white'`, `canvasStrokeWidth=72`, `canvasStrokeColorBeforeEraser='green'`, `canvasStrokeWidthBeforeEraser=15`인 store를 넣으면 `{color:'green', width:15}`를 반환합니다.
- `quizPen`에 `canvasStrokeColor='white'`, `canvasStrokeWidth=72`이고 지우개 전 값이 없는 store를 넣으면 `{color:'orange', width:6}`을 반환합니다. 결과의 color는 'white'가 아니고 width는 72가 아닙니다.
- QuizResponseModal 테스트: storage가 `canvasStrokeColor='white'`, `canvasStrokeWidth=72`, `canvasStrokeColorBeforeEraser='blue'`, `canvasStrokeWidthBeforeEraser=9`일 때 렌더하면 WebView html에 `ctx.strokeStyle = "blue";`와 `ctx.lineWidth = 9;`가 있고, `ctx.strokeStyle = "white";`와 `ctx.lineWidth = 72;`는 없습니다.
- QuizResponseModal 테스트: storage가 `canvasStrokeColor='white'`이고 지우개 전 값이 없으면 html에 `ctx.strokeStyle = "orange";`와 `ctx.lineWidth = 6;`이 있습니다.
- 기존 QuizResponseModal 테스트가 그대로 통과합니다: 'blue'·10이면 그 값으로 그리고, 저장값이 없으면 'orange'·6.
- `__tests__/canvasEraser.test.ts`의 기존 테스트가 그대로 통과합니다: 네 캔버스 파일의 `eraserWidth`/`inkWidth` 호출 문자열 검사와 지우개 굵기 복원.
- `__tests__/quizResponseModal.test.tsx`의 기존 제출, 지우기, 배경 테스트가 모두 통과합니다. jest 전체가 통과하고, `npx tsc --noEmit`에 새 오류가 없습니다.

## 가정
- '지우개 해제 후 복원될 펜슬'은 지우개를 고르기 직전의 펜으로 봅니다. 색은 새로 저장하는 `canvasStrokeColorBeforeEraser`, 굵기는 기존 `canvasStrokeWidthBeforeEraser`(`inkWidth`가 쓰는 값)입니다.
- 지우개 전 색이 저장되지 않은 경우(업데이트 전부터 지우개 상태였던 경우 등)에는 기본 펜 'orange'로, 굵기는 `inkWidth`와 같은 기본 6으로 봅니다.
- 캔버스 화면에서 지우개를 풀 때 색은 사용자가 고른 버튼 색이 되는 것이 기존 동작입니다. 퀴즈 모달은 그 전에 열리므로 직전 펜 색을 쓰는 것이 의도에 맞다고 봅니다.
