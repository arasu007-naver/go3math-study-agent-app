# 실황 수업: '이미지 퀴즈' 받기 — 설명 이미지 위에 표시하는 퀴즈 모달 (student-app)

## 배경과 목적
실황 수업 중 선생님(tutor-web)이 개념 설명 이미지 URL을 퀴즈로 보냅니다(`action: "imageQuiz"`). 학생 앱은 퀴즈 모달 **QuizResponseModal**(`src/kit/live-class/QuizResponseModal.tsx`)에 퀴즈 문구('중요한 부분에 표시하시오')를 보이고, 답안을 그리는 캔버스의 **배경으로 설명 이미지**를 그립니다. 학생은 이미지 위에 중요한 부분을 표시하고 '답 보내기'로 제출합니다. 이것이 개념 설명에 대한 학생의 리액션입니다.

지금은 다음과 같이 동작합니다.
- **TopicLiveClassScreen**(`app/topic-live-class.tsx`)과 hotline 화면(`app/hotline-class.tsx`)의 구독 `onData`는 `guide.action === 'quiz'`일 때 `receiveQuiz({ quizId, content: guide.quiz })`로 QuizResponseModal을 엽니다.
- **TopicLiveCanvas**(`src/kit/canvas/note-canvas/topic-live-canvas.tsx`)와 **HotlineClassCanvas**(`src/kit/canvas/note-canvas/hotline-class-canvas.tsx`)의 `onReceiveGuide`도 'quiz'를 받으면 `onQuizReceived`를 부릅니다. 마지막 메시지를 다시 받을 때가 이 경로입니다.
- QuizResponseModal의 답안 캔버스(`DRAWING_CANVAS_HTML`)는 흰 배경입니다.

## 범위
### 하는 것
- `LiveQuiz` 타입에 선택 필드 `imageUrl?: string`를 추가합니다.
- 두 화면의 구독 `onData`에서 `imageQuiz`를 `quiz`처럼 처리합니다.
- 두 캔버스 패널의 `onReceiveGuide`에서 `imageQuiz`를 `quiz`처럼 처리합니다.
- QuizResponseModal에서 `imageUrl`이 있으면 답안 캔버스 배경에 이미지를 그리고, 제출 PNG에 배경과 필기를 함께 담습니다.

### 하지 않는 것
- 메인 실황 캔버스(live-class-canvas-template)의 배경과 Flying Objects 처리는 바꾸지 않습니다.
- 답안 업로드(`uploadQuizAnswerToStorage`)와 답안 제출 API(api-v3 `POST /api/live-class-quizzes/{quizId}/responses`, GraphQL `addLiveClassQuizResponse`)는 바꾸지 않습니다.
- 기존 `action: 'quiz'`(이미지 없는 퀴즈)의 화면과 동작은 바꾸지 않습니다.
- student-web은 이번 범위가 아닙니다.

## 변경할 동작
1. **QuizResponseModal**의 `LiveQuiz`를 `{ quizId: number | string; content: string; imageUrl?: string }`로 바꿉니다.
2. **TopicLiveClassScreen**(`app/topic-live-class.tsx`)과 hotline 화면(`app/hotline-class.tsx`)의 구독 `onData`를 바꿉니다.
   - `guide.action === 'imageQuiz'`이면 `receiveQuiz({ quizId: guide.quizId, content: guide.quiz, imageUrl: guide.imageUrl })`를 부르고 return합니다.
   - 이때 `setLastPoint`를 하지 않고 `panelRef.current?.onReceiveGuide`도 부르지 않습니다. 기존 `quiz`와 같습니다.
   - `canvasActivityStore`의 quiz 기록은 기존 `receiveQuiz`가 그대로 남깁니다.
3. **TopicLiveCanvas**와 **HotlineClassCanvas**의 `onReceiveGuide`를 바꿉니다.
   - 스크립트 전환 검사보다 먼저 `guide.action === 'imageQuiz'`를 확인합니다. 맞으면 `onQuizReceived?.({ quizId: guide.quizId, content: guide.quiz, imageUrl: guide.imageUrl })`를 부르고 return합니다.
   - 이때 `handleLiveClassMessage`나 `playToPoint`를 부르지 않고, 스크립트 전환이나 `syncPoint` 저장도 하지 않습니다.
4. **QuizResponseModal**의 답안 캔버스를 바꿉니다.
   - `quiz.imageUrl`이 있으면 WebView가 로드된 뒤 `{ type: 'SET_BACKGROUND', url }` 메시지로 HTML에 전달합니다. HTML 템플릿에 url을 주입하는 방식도 됩니다.
   - HTML은 `Image`를 `crossOrigin = 'anonymous'`로 불러 캔버스 크기에 비율을 유지한 채(contain) 가운데에 그립니다. 그 위에 필기합니다.
   - 배경을 그려도 `hasDrawn`은 false로 남습니다. 학생 필기가 없으면 기존처럼 '답안을 작성해 주세요.'가 뜹니다.
   - '지우기'(CLEAR)는 흰색으로 채운 뒤 배경 이미지를 다시 그립니다. 학생 필기만 지워지고 이미지는 남습니다.
   - resize 때도 흰색으로 채운 뒤 배경을 다시 그립니다.
   - GET_IMAGE의 `toDataURL('image/png')` 결과에는 배경 이미지와 필기가 함께 들어갑니다.
   - 이미지 로드에 실패하면 흰 배경 캔버스로 두고 필기와 제출은 그대로 됩니다. 배경이 그려졌다가 캔버스가 tainted가 되어 toDataURL이 예외를 내면, 배경을 지우고 필기만 담아 보내도록 바꾸지 않고 `onError('이미지를 불러오지 못했습니다.')`를 알립니다.
   - 퀴즈 문구 영역(MathJaxWrapper)은 그대로 `quiz.content`('중요한 부분에 표시하시오')를 보입니다.
   - 이미지가 있을 때는 답안 캔버스가 더 많은 높이를 쓰도록 퀴즈 문구 영역 최대 높이를 줄여도 됩니다(선택).
5. `imageUrl`이 없는 퀴즈의 모달 HTML 동작은 변경 전과 같습니다.

## API 계약
### 받는 라이브 guide (구독 `liveTopicClassMessage.content` / `newOnlineClassMessage.content`, 마지막 메시지 조회 `lastLiveTopicMessage` / `lastOnlineClassMessage`도 같은 모양)
```json
{
  "topicId": 123,
  "scriptId": 456,
  "studyIdx": 0,
  "rawCutIdx": 0,
  "step": "main",
  "sourceType": "MATH_PROBLEM",
  "sourceId": 789,
  "action": "imageQuiz",
  "quizId": 1011,
  "quiz": "중요한 부분에 표시하시오",
  "imageUrl": "https://<storage>/math-files/images/concepts/<conceptId>/<ts>.jpeg",
  "conceptId": 12
}
```
- 필수: `action`(="imageQuiz"), `quizId`(number), `quiz`(string), `imageUrl`(string)
- 선택: `conceptId`(number). 앱은 쓰지 않아도 됩니다.

### 답안 제출 (기존, 변경 없음)
- api-v3 `POST /api/live-class-quizzes/{quizId}/responses`, body `{ answerUrl, taskId? }`. 실패하면 GraphQL `addLiveClassQuizResponse(quizId: Int!, answerUrl: String!)`로 보냅니다.
- `answerUrl`은 설명 이미지와 학생 필기가 합쳐진 PNG의 업로드 URL입니다.

## 수용 기준
- topic 실황 화면의 구독으로 `action: 'imageQuiz'` guide를 받으면 QuizResponseModal이 열린다. 제목은 `Quiz #{quizId}`이고 문구 영역에 '중요한 부분에 표시하시오'가 보인다.
- 이 guide를 받아도 `setLastPoint`와 패널의 `onReceiveGuide`가 불리지 않는다.
- hotline 화면의 구독으로 같은 guide를 받아도 QuizResponseModal이 같은 내용으로 열리고, 패널의 `onReceiveGuide`가 불리지 않는다.
- TopicLiveCanvas나 HotlineClassCanvas의 `onReceiveGuide`에 `imageQuiz` guide를 넘기면 `onQuizReceived`가 `{ quizId, content: guide.quiz, imageUrl: guide.imageUrl }`로 한 번 불린다.
- 이때 `handleLiveClassMessage`는 불리지 않고, guide의 scriptId가 현재 스크립트와 달라도 스크립트 전환이나 `syncPoint` 저장이 일어나지 않는다.
- `imageUrl`이 있는 퀴즈 모달의 답안 캔버스에는 그 이미지가 비율을 유지한 채 가운데에 배경으로 그려진다.
- 배경만 있고 필기가 없을 때 '답 보내기'를 누르면 '답안을 작성해 주세요.'가 뜨고 업로드가 일어나지 않는다.
- '지우기'를 누르면 학생 필기는 지워지고 배경 이미지는 남는다.
- 필기 후 '답 보내기'를 누르면 업로드되는 PNG에 배경 이미지와 필기가 함께 들어 있고, 기존 답안 제출 경로로 `quizId`에 제출된다.
- 제출에 성공하면 모달이 닫히고 '답안을 보냈습니다.' 토스트가 보인다.
- `imageUrl` 이미지 로드가 실패하면 모달이 흰 배경 캔버스로 열리고, 필기 후 제출할 수 있다.
- `action: 'quiz'`(imageUrl 없음) guide를 받으면 변경 전과 같이 흰 배경 답안 캔버스의 모달이 열린다.
- 기존 테스트(`__tests__/quizResponseModal.test.tsx` 등)가 통과하고, imageQuiz 처리와 배경 유지 동작을 검증하는 테스트가 추가되어 통과한다.

## 가정
- 카드의 '캔버스배경'은 메인 실황 캔버스가 아니라 QuizResponseModal 안 답안 캔버스의 배경을 뜻한다고 해석했습니다.
- 액션 이름은 tutor-web 스펙과 같이 'imageQuiz'로 정했습니다. 카드가 제안한 'content'는 기존 guide의 content 필드와 겹칩니다.
- 설명 이미지 저장소는 CORS를 허용한다고 가정했습니다. 그래서 crossOrigin='anonymous'로 그린 캔버스를 toDataURL로 내보낼 수 있습니다.
- 제출 답안은 배경 이미지와 필기를 합친 한 장의 PNG로 정했습니다. 선생님이 어느 부분을 표시했는지 이미지 맥락과 함께 볼 수 있습니다.
- 마지막 메시지를 다시 받을 때 imageQuiz가 오면 기존 quiz처럼 모달을 다시 여는 것을 허용했습니다.
