# Stage 문제 목록 새로고침

## 배경과 목적

문제(unit) 이미지와 해답이 자주 수정되지만, 앱은 같은 URL의 캐시를 계속 보여 주어 수정 내용이 학생에게 전달되지 않는다. 학생이 Stage에 떠 있는 문제 목록을 직접 새로 받을 수 있게 한다.

코드 확인 결과:

- 요구사항의 StagePanel은 용어집의 **Stage**(`src/host/Stage.tsx`)이다. 책갈피/문서 아이콘 버튼은 `stage-header` 안에 있다.
- **ProblemListPanel**과 그 래퍼 BookmarksPanel은 `src/kit/problem-list/ProblemListPanel.tsx`에 있고, **HostWidgets**(`src/host/widgets.tsx`)의 `ProblemListWidget`·`BookmarksWidget`이 렌더링한다.
- 목록 조회(**problemListFetchers**, `src/adapters/problemListFetchers.ts`)의 GraphQL은 이미 `network-only`이다. 오래된 내용의 원인은 목록 데이터가 아니라 **고정 URL의 이미지와 해답 페이지 캐시**이다.
- 문제 이미지는 RN `Image`와 `Image.getSize`(**ImageDynamicDims**, `src/kit/ui/image-dynamic-dims.tsx`), 풀이 화면의 캔버스 WebView, **ImageAdjustCard**가 읽는다. 해답은 WebView가 `UNITANSWER` URL로 읽는다. 이 경로들에 공통으로 쓸 수 있는 URL별 캐시 삭제 API는 없다.
- `ImageDynamicDims`의 크기 계산 effect는 의존성이 `[]`라서 URL만 바뀌면 다시 측정하지 않는다.

따라서 새로고침한 문제의 **표시용 URL에 버전 쿼리를 붙여** 기존 캐시 항목을 더 이상 쓰지 않고 새로 받게 한다.

## 범위

### 하는 것

- Stage 헤더에 새로고침 아이콘 버튼 추가
- 현재 ProblemListPanel/BookmarksPanel 목록 다시 조회
- 조회된 문제들의 이미지·해답 캐시 무효화(문제별 버전 저장)
- 새 버전을 문제 목록, 풀이 화면(`app/notebook.tsx`), 해답 표시에 적용
- 실패 시 기존 목록 유지와 안내

### 하지 않는 것

- 서버, m-cache, Azure Blob 쪽 변경이나 퍼지
- 앱 전체 캐시 삭제, 자동·주기적 새로고침, 당겨서 새로고침
- `problem_preview`(TopicUnitList), 검색·주제 dock 등 다른 화면에 버튼 추가
- 실황 수업 캔버스(`app/hotline-class.tsx`, `app/topic-live-class.tsx`), DiaryPanel, MessageBoxPanel, 공개 문제 화면의 URL 변경
- 해답 HTML 안에 포함된 하위 리소스의 개별 무효화
- 이전 캐시 파일의 물리적 삭제(각 캐시의 자체 정리에 맡긴다)
- `Problem.image`, solveStore, task, 풀이 기록, 스크립트에 저장되는 URL 변경

## 변경할 동작

### 1. 문제별 콘텐츠 버전

새 모듈 `src/kit/problem-list/contentVersion.ts`를 만들고 **컴포넌트 용어집(`docs/COMPONENTS.md`)의 유틸 절에 추가**한다.

- 저장소: **Storage**(`src/storage`)의 키 `agent:unitContentVersions`, 값은 JSON 객체 `{ "<sourceType>-<sourceId>": <epoch ms> }`. 값이 없거나 깨졌으면 빈 객체로 다룬다.
- `bumpContentVersions(problems, version = Date.now())`: 주어진 문제들의 버전을 같은 값으로 기록한다. 다른 문제의 버전은 유지한다.
- `contentVersionOf(sourceType, sourceId)`: 저장된 버전 또는 `undefined`. `sourceId`는 문자열·숫자 모두 같은 키로 본다.
- `versionedUrl(url, sourceType, sourceId)`: 버전이 없거나 url이 비었으면 url을 그대로 돌려준다. 버전이 있으면 `v=<버전>`을 붙인다. url에 쿼리가 없으면 `?v=`, 있으면 `&v=`로 붙이고, 이미 `v`가 있으면 값을 교체한다. fragment가 있으면 그 앞에 넣는다.

### 2. Stage 새로고침 버튼

- `stage.componentId`가 `problem_list`, `bookmarks`, `bookmarks_panel`일 때만 보인다.
- 위치는 기존 책갈피/문제 목록 전환 버튼의 바로 왼쪽이다.
- Ionicons `refresh-outline`, 크기 20, 기존 `styles.iconButton`과 같은 모양을 쓴다.
- `accessibilityRole="button"`, `accessibilityLabel="새로고침"`, `testID="stage-refresh"`.
- 진행 중에는 비활성(`accessibilityState.disabled = true`)이고 아이콘 대신 ActivityIndicator를 보인다.
- 실패하면 Stage의 기존 `styles.fallback` 모양으로 `새로고침하지 못했어요. 잠시 후 다시 시도해 주세요.`를 보인다. 다음 새로고침 시작 또는 Stage 화면 변경 시 사라진다.
- 진행 중 Stage 화면이 바뀌면 진행 상태를 해제한다.

### 3. 패널 새로고침

Stage → Widget → Panel로 다음 형태의 선택 prop을 전달한다.

```ts
refresh?: { token: number; onDone(ok: boolean): void }
```

`token`은 버튼을 누를 때마다 증가한다. 패널은 **마지막으로 처리한 token보다 커졌을 때만** 새로고침한다. 첫 마운트나 `source` 변경만으로는 새로고침하지 않는다.

새로고침 순서:

1. 해답 말풍선을 닫는다.
2. 기존 목록을 비우지 않은 채 현재 `source`로 `fetchProblems`를 호출한다.
3. 성공하면 받은 문제 전부의 버전을 올리고 목록을 교체한다. 선택 문제는 인덱스가 범위 안이면 유지하고, 아니면 0, 목록이 비면 `null`로 한다. `onDone(true)`를 부른다.
4. 실패하면 목록·선택·버전을 바꾸지 않고 `onDone(false)`를 부른다.
5. 응답 전에 `source`가 바뀌거나 패널이 사라지면 그 응답은 목록과 버전에 반영하지 않는다.

### 4. 버전 적용 지점

- ProblemListPanel 카드 이미지: `versionedUrl(problem.image, ...)`. `DynamicDimensionsImage`에 표시 URL을 `key`로 주어 URL이 바뀌면 크기를 다시 측정하게 한다.
- ProblemListPanel 해답 말풍선 URL: `versionedUrl(UNITANSWER(...), ...)`.
- `app/notebook.tsx`: `changeNotebookBackgroundImage` 두 호출과 `ImageAdjustCard`의 `imgPath`에 표시용 URL을 쓴다. `ImageAdjustCard`도 URL이 바뀌면 다시 측정되도록 표시 URL을 `key`로 준다. `session.problems`와 `currentSheet` 객체는 바꾸지 않는다.
- **CanvasAnswer**(`src/kit/canvas/CanvasAnswer.tsx`)와 **PhoneStudySheets**의 `useAnswerSheet`(`src/phone/PhoneStudySheets.tsx`) 해답 URL에 `versionedUrl`을 적용한다.
- `UNITIMAGE`, `UNITANSWER` 자체는 바꾸지 않는다(`script-maker.ts`가 결과에 `?ts=`를 이어 붙이기 때문이다).

## API 계약

없음. 기존 조회를 그대로 쓰며 다른 프로젝트와 주고받는 내용이 바뀌지 않는다.

## 수용 기준

1. Stage가 `problem_list`, `bookmarks`, `bookmarks_panel`을 표시하면 `stage-refresh` 버튼이 책갈피/문제 목록 전환 버튼 바로 왼쪽에 렌더링된다.
2. Stage가 비어 있거나 `problem_preview` 등 다른 위젯이면 `stage-refresh` 버튼이 없다.
3. 버튼을 누르면 현재 `source`로 `fetchProblems`가 정확히 한 번 더 호출된다. 일반 문제 목록과 내 책갈피 각각에서 성립한다.
4. 새로고침 중에도 기존 문제 카드가 화면에 남아 있고, 버튼은 비활성이며 다시 눌러도 추가 조회가 일어나지 않는다.
5. 새로고침에 성공하면 받은 모든 문제의 카드 이미지 URL에 같은 `v=<버전>`이 붙고, 다시 새로고침하면 그 값이 바뀐다.
6. 서버 응답에서 문제가 추가·삭제되면 새로고침 후 목록에 반영된다.
7. 선택 인덱스가 새 목록 범위 안이면 유지되고, 범위를 벗어나면 0, 빈 목록이면 선택이 없다.
8. 새로고침을 시작하면 열려 있던 해답 말풍선이 닫힌다.
9. 새로고침한 문제의 해답 URL(ProblemListPanel, CanvasAnswer, `useAnswerSheet`)에 같은 버전이 붙는다.
10. 새로고침한 문제를 `/notebook`에서 열면 배경 이미지와 문제 교체 목록 이미지 URL에 같은 버전이 붙는다.
11. 버전은 Storage에 저장되어, 모듈을 다시 불러온 뒤에도 같은 문제의 표시 URL에 유지된다.
12. 한 번도 새로고침하지 않은 문제의 이미지·해답 URL은 기존과 글자까지 같다.
13. `versionedUrl`은 쿼리 없는 URL, 쿼리 있는 URL, 이미 `v`가 있는 URL, fragment가 있는 URL, 빈 문자열을 각각 올바르게 처리한다.
14. 조회가 실패하면 기존 목록·선택·버전이 유지되고 안내 문구가 보이며 버튼이 다시 활성화된다.
15. 응답 전에 `source`가 바뀌면 늦게 온 응답이 새 목록이나 버전을 덮어쓰지 않고 진행 표시가 해제된다.
16. 새로고침 후 `Problem.image`, solveStore의 문제, `notebookArgs`가 만드는 TaskSpec에 `v=`가 들어가지 않는다.
17. `docs/COMPONENTS.md`에 `contentVersion` 항목이 추가된다.
18. 기존 테스트와 타입 검사가 통과하고, 위 동작을 검증하는 테스트가 `__tests__`에 추가된다.

## 가정

- 요구사항의 StagePanel은 `src/host/Stage.tsx`의 Stage이다.
- 캐시 삭제는 물리적 파일 삭제 대신 URL 버전 변경으로 기존 캐시를 쓰지 않게 하는 방식으로 충족한다.
- 새로고침 대상에는 문제 이미지와 해답 페이지를 포함한다.
- Azure Blob과 m-cache는 알 수 없는 `v` 쿼리를 받아도 같은 콘텐츠를 응답한다.
- m-cache 서버 자체가 오래된 해답을 캐시하는 경우는 이 작업으로 해결하지 않는다.
- 이미지가 다시 측정되는 동안 카드 높이가 잠시 변해 스크롤 위치가 움직일 수 있는 것은 허용한다.
- 폰 화면에는 Stage 헤더가 없으므로 버튼을 추가하지 않는다.
