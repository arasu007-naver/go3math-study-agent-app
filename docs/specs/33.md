# 실황 수업 진입 점검 및 개선: Dock 주제 카드 제목에 topic id 표시, 대기 문구 '수업 준비 중입니다', 주제 문제 0개일 때 대기 화면

## 배경과 목적
- 실황 수업 Dock은 **LiveClassListPanel**(`src/kit/live-class/LiveClassListPanel.tsx`)입니다. '🎯 주제 실황 수업' 구획의 카드 제목은 지금 `📝 ${t.title}`만 보여 줍니다. 그래서 같은 제목의 주제를 서로 구분할 수 없습니다. 제목 끝에 topic id를 붙여 구분하게 합니다.
- #32(`docs/specs/32.md`)에서 실황 수업 canvas 화면 두 곳에 '진행 확인 중(checking) / 진행 중(live) / 대기(waiting)' 상태와 대기 화면을 넣었습니다.
  - 주제 실황 수업: **TopicLiveClassScreen** `app/topic-live-class.tsx`
  - 선생님 수업: **HotlineClassScreen** `app/hotline-class.tsx`
  - 대기 화면: **LiveClassWaiting** `src/kit/live-class/LiveClassWaiting.tsx`
- #32의 지금 동작은 다음과 같습니다.
  - last message(`LAST_LIVE_TOPIC_MESSAGE` / `LAST_ONLINE_CLASS_MESSAGE`)의 content를 guide로 파싱할 수 있으면 live로 바꿉니다. 그리고 `panelRef.current.onReceiveGuide(guide)`를 부르거나 storage `syncPoint`에 넣어, 패널이 최신 cut까지 재생(`playToPointInternal`)하게 합니다.
  - 파싱할 수 없으면 waiting으로 바꾸고 LiveClassWaiting(Go3MathLoader + '수업 전입니다.' + 나가기)을 보입니다.
- 점검하면서 찾은 것:
  - (1) 요구 문구는 '수업 준비 중입니다'인데 지금 문구는 '수업 전입니다.'입니다.
  - (2) HotlineClassScreen은 units가 0개일 때 waiting으로 바꿉니다. TopicLiveClassScreen은 `topicForStudy.units`가 빈 배열이면 last message 호출 effect(`topicUnits.length === 0`이면 return)가 돌지 않습니다. 그래서 liveState가 `checking`에 영원히 머물고, 대기 화면도 캔버스도 아닌 로딩 상태로 남습니다.
- 목적: Dock에서 주제를 구분할 수 있게 합니다. 두 화면에 들어가면 항상 '최신 cut 따라가기' 또는 '로고 애니메이션 + 수업 준비 중입니다' 중 하나로 끝나게 합니다.

## 범위
### 하는 것
- LiveClassListPanel 주제 실황 수업 카드의 제목 Text 끝에 ` (# {topic id})`를 붙입니다.
- LiveClassWaiting의 안내 문구를 '수업 전입니다.'에서 '수업 준비 중입니다'로 바꿉니다. 두 화면이 이 컴포넌트를 함께 쓰므로 둘 다 바뀝니다.
- TopicLiveClassScreen에서 `topicForStudy`가 정상으로 왔지만 units가 빈 배열이면 liveState를 `waiting`으로 바꿉니다.
- 위 변경에 맞춰 관련 테스트의 기대 문구를 고치고, 새 동작을 검증하는 테스트를 더합니다.

### 하지 않는 것
- 선생님 수업(hotline) 카드의 제목·라벨은 바꾸지 않습니다.
- 주제 카드의 accessibilityLabel, onOpen으로 넘기는 ProblemSource의 title(`📝 ${t.title}`), ProblemListPanel 헤더는 바꾸지 않습니다.
- 서버, GraphQL 쿼리·구독 문서, REST fetcher(`liveClassFetchers`)는 바꾸지 않습니다.
- 다음 #32 로직은 바꾸지 않습니다.
  - last message가 있을 때의 재생 로직(`onReceiveGuide`, `playToPointInternal`, `syncPoint`)
  - 구독에 따른 waiting→live 전환 규칙
  - '필기 따라가기' 규칙
  - TopicLiveClassScreen의 쿼리 실패 시 `notReady()`
- 캔버스 패널(`topic-live-canvas.tsx`, `hotline-class-canvas.tsx`) 내부는 바꾸지 않습니다.
- 로고 애니메이션 자체(Go3MathLoader)와 대기 화면 레이아웃·나가기 버튼은 바꾸지 않습니다.

## 변경할 동작
1. **Dock 주제 카드 제목** (`src/kit/live-class/LiveClassListPanel.tsx`)
   - `topics.map` 안 제목 Text를 `` `📝 ${t.title} (# ${t.id})` ``로 바꿉니다. 예: title '이차함수', id 12이면 `📝 이차함수 (# 12)`.
   - id가 문자열이어도 그대로 문자열로 넣습니다.
2. **대기 문구** (`src/kit/live-class/LiveClassWaiting.tsx`)
   - `<Text style={styles.text}>수업 전입니다.</Text>`를 `<Text style={styles.text}>수업 준비 중입니다</Text>`로 바꿉니다. 끝에 마침표를 붙이지 않습니다.
   - 다음은 그대로 둡니다: `testID="live-class-waiting"`, 화면 가운데의 Go3MathLoader(로고 scale 반복 애니메이션), 문구가 로고 바로 아래에 오는 배치, 나가기 버튼.
   - 파일 상단 주석의 '문구' 설명이 있으면 맞춰 고칩니다.
3. **TopicLiveClassScreen 문제 0개 처리** (`app/topic-live-class.tsx`)
   - 진입 effect의 `getTopic(...).then` 안에서 `setTopicUnits(units)`를 할 때 units 길이가 0이면 `setLiveState((cur) => (cur === 'live' ? cur : 'waiting'))`를 함께 부릅니다. HotlineClassScreen의 `loadAgenda`와 같은 규칙입니다.
   - `topicForStudy`가 null이거나 쿼리가 실패하면 기존처럼 `notReady()`를 부릅니다.
   - 대기 중에도 `TOPIC_LIVE_MESSAGE_ADDED` 구독은 기존 skip 조건(`!isFocused || !topicId`)대로 유지합니다. 진행 guide가 오면 기존 규칙대로 live로 바꿉니다.
4. **진입 흐름 재확인** (코드 변경 없이 테스트로 보장)
   - last message가 파싱 가능한 guide이면 대기 화면 없이 그 guide가 패널 `onReceiveGuide`에 전달되거나 `syncPoint`에 저장됩니다. 그러면 패널이 최신 cut으로 따라갑니다.
   - last message가 null, 빈 문자열, 파싱 불가이면 대기 화면이 보입니다.

## API 계약
없음. 다음 기존 계약을 그대로 씁니다.
- REST: `today-live-classes`의 `{ id, title, description, classTime }`
- GraphQL: `topicForStudy(topicId)`, `lastLiveTopicMessage(topicId)`, `lastOnlineClassMessage(tutorId)`, 구독 `liveTopicClassMessage` / `newOnlineClassMessage`

## 수용 기준
1. LiveClassListPanel에 `fetchTopicLiveClasses`가 `[{ id: 12, title: '이차함수' }]`를 돌려주면 `📝 이차함수 (# 12)` 텍스트가 보인다.
2. 1과 같은 조건에서 주제 카드의 accessibilityLabel은 그대로 `주제 실황 수업 이차함수`이다. 카드를 누르면 `onOpen`이 `{ kind: 'topic_live', topicId: 12, title: '📝 이차함수' }`로 불린다.
3. 선생님 수업 카드의 제목은 그대로 `${name} (${units.length} 문제)` 형식이다.
4. LiveClassWaiting을 렌더하면 `testID="live-class-waiting"` 요소 안에 '수업 준비 중입니다' 텍스트와 `accessibilityLabel="불러오는 중"`인 Go3MathLoader가 있다. '수업 전입니다.' 텍스트는 없다.
5. TopicLiveClassScreen에서 `STUDY_TOPIC`이 스크립트가 있는 unit을 돌려주고 `LAST_LIVE_TOPIC_MESSAGE`가 `{ lastLiveTopicMessage: null }`을 돌려주면, 대기 화면이 보이고 그 안에 '수업 준비 중입니다'가 있다.
6. HotlineClassScreen에서 `ONLINE_CLASS_OF_TUTOR`가 unit을 돌려주고 `LAST_ONLINE_CLASS_MESSAGE`가 `{ lastOnlineClassMessage: null }`을 돌려주면, 대기 화면이 보이고 그 안에 '수업 준비 중입니다'가 있다.
7. TopicLiveClassScreen에서 `STUDY_TOPIC`이 `{ topicForStudy: { units: [] } }`를 돌려주면 대기 화면('수업 준비 중입니다')이 보인다. 이때 '주제 실황 강의가 준비되지 않았습니다' 토스트는 뜨지 않고, `TOPIC_LIVE_MESSAGE_ADDED` 구독은 skip되지 않는다.
8. 7의 대기 상태에서 구독으로 progress guide(예: `{"scriptId":12,"studyIdx":0,"step":"main"}`)가 오면 대기 화면이 사라지고, 그 guide가 패널 `onReceiveGuide`로 전달된다.
9. TopicLiveClassScreen / HotlineClassScreen에서 last message가 파싱 가능한 guide(예: `{"scriptId":12,"studyIdx":3,"step":"main"}`)를 돌려주면, 대기 화면이 보이지 않고 그 guide가 패널 `onReceiveGuide`에 전달되거나 storage `syncPoint`에 저장된다.
10. TopicLiveClassScreen에서 `STUDY_TOPIC`이 `{ topicForStudy: null }`을 돌려주거나 실패하면 기존처럼 '주제 실황 강의가 준비되지 않았습니다' 토스트가 뜬다.
11. 저장소의 기존 테스트(`__tests__/liveClass.test.tsx` 등 live class 관련 포함)가 모두 통과한다. '수업 전입니다.'를 기대하던 테스트는 '수업 준비 중입니다'로 고쳐져 통과한다.
12. `tsc` 타입 검사에서 새 오류가 없다.

## 가정
- 제목 접미사는 요구사항 표기 '(# {topic id})'를 그대로 따릅니다. 제목 뒤 공백 한 칸 뒤에 `(# 12)`처럼 '#' 다음에 공백을 둡니다.
- 접미사는 Dock 카드에 보이는 제목 Text에만 붙입니다. 접근성 라벨과 Stage 문제 목록 제목은 그대로 둡니다.
- 대기 문구는 마침표 없이 '수업 준비 중입니다'로 씁니다.
- 로고 애니메이션은 #32에서 쓴 Go3MathLoader를 그대로 씁니다.
- 주제 문제가 0개인 것은 오류가 아니라 '수업 준비 중'으로 봅니다. 그래서 notReady 대신 대기 화면을 보입니다.
